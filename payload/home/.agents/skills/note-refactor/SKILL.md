# Note Refactor（技术笔记重写规范与精炼指南）

用于将杂乱无章、机械翻译截图、充满流水账或劣质图表的粗糙笔记，重构为**技术严谨、极其凝炼、层次分明、大厂面试与生产避坑兼备**的高级工程师级知识资产。

---

## 一、四大硬性禁止红线（Negative Constraints）

1. **绝对禁止任何元注释与自我纠错杂质**：
   - 严禁在正文中出现：“原图逐字还原”、“作者自评有些不一定对”、“原笔记误称/修正”、“原图底部被裁切”、“本篇还原自截图”、“这里作者画错了”等破坏阅读沉浸感的字样；
   - 发现旧笔记存在技术错误或概念混淆时，**直接以工业界正确标准重写**，绝不把“纠错过程”当正文呈现。
2. **坚决杜绝低质、庞大、连线打架的 Mermaid 流程图**：
   - 严禁手写动辄 100~200 行连线交叉、节点凌乱的巨型 Mermaid 图；
   - 能用清晰编号列表和 Markdown 结构块讲透的，直接用文字呈现；架构全景必须优先利用 `assets/` 真实高清图。
3. **严格贯彻 Minimal Bolding（克制加粗）原则**：
   - 杜绝大面积满屏黑体（会导致视觉严重疲劳）；
   - **只对最核心的专业术语、状态枚举、关键参数名或核心对比词进行克制加粗**，确保一眼抓住重心。
4. **拒绝机械照抄与流水账大表**：
   - 严禁把图里的每个像素、每个格子（如 0 1 2 3 4 5...、图例色块声明）机械敲成毫无营养的 Markdown 大表。

## 二、图像资产深度利用与特写裁剪规范（Image Asset Strategy）

原笔记自带的高分辨率图表是宝贵资产，但常因尺寸过大或排版不当沉底失效。必须按以下规范重塑：

1. **全景置顶建立心智模型**：
   - 篇首直接嵌入全局宏观架构图（如集群拓扑、全链路全景），第一眼建立端到端俯瞰视角。
2. **利用图像工具精准裁剪局部高清特写**：
   - 当原图信息量密集（如 1500px 以上大图），展开具体模块时，**必须使用 ImageMagick（`magick`）裁出局部特写大图**（去除白边、无关杂色和多余模块）；
   - 嵌入到对应小节中，图文紧密呼应，使关键模块放大 2~3 倍清晰可见。
3. **缝合被切断的长图**：
   - 若流程图/路线图被截图工具切为上下两截，使用 `magick img1.png img2.png -append output.png` 垂直无缝拼接为完整长图。
4. **修饰去瑕**：
   - 若原图中带有鼠标悬停残影、标签浮层或窗口边缘，使用背景色修补，保持纯净。
5. **统一 Obsidian 库内引用语法**：
   - 规范采用 `![[库内相对路径/assets/xxx.png]]`，杜绝死链接。

## 三、知识重构黄金三步法（Workflow）

### 第一步：确立知识展开主线（脉络化）
- **单点机制深潜**：以**实体生命周期（Life of an Entity）**顺流而下（如消息产生 $\to$ 序列化 $\to$ 路由 $\to$ 内存攒批 $\to$ 网络发送 $\to$ 落盘存储 $\to$ 消费拉取 $\to$ 位移确认）；
- **系统/架构宏观篇**：按**分层模型**自顶向下展开（客户端 SDK $\to$ 网络反应堆 $\to$ 请求解耦队列 $\to$ 控制平面 $\to$ 本地存储引擎）。

### 第二步：凝练技术内核（拒绝空洞套话）
- **底层机理剖析**：不仅讲“是什么”，更要讲透“为什么这样设计”（如为什么用顺序追加写？为什么需要内存池循环复用？为什么需要静态成员？）；
- **配置与参数联动公式**：将离散的配置参数整理成有逻辑约束的公式链（如 $\text{单批耗时} = \text{max.poll.records} \times \text{单条耗时} \ll \text{max.poll.interval.ms}$）；
- **典范代码范式**：代码只保留最核心切入点、异常防护与资源释放闭环，去除无关业务样板。

### 第三步：双重视角双保险（基础使用 + 面试压轴避坑）
每篇重构必须经受两项检验：
1. **基础认识与正确使用**：概念清晰、API 时机明确、开箱可用；
2. **大厂面试与生产避坑**：主动挖掘深水区考点（如业务假死与 Rebalance 震荡、位移乱序提交导致丢数据、内存打满导致上游线程池雪崩、幂等性在途请求滑动窗口等）。

## 四、目录结构与体系化阶段划分（Category Strategy）

当梳理系列技术笔记（如 Kafka、Redis、MySQL）时，严格按照**学习进阶阶段**组织文件夹：
1. **阶段 1：架构全景与设计模型**（宏观全局、消息传递全链路）；
2. **阶段 2：生产端客户端深潜**（微观组件流水线 + 宏观发送与高可用避坑）；
3. **阶段 3：消费端客户端深潜**（组模型、Rebalance 演进、健康检测与消息堆积治理）；
4. **阶段 4：存储引擎与底层可靠性**（物理落盘、零拷贝、ACK、幂等与事务）；
5. **阶段 5~7：预留骨架目录**（高可用运维、监控调优、生态集成流计算，即便暂无文件也预留目录）。

## 五、交付门槛与验收清单（Quality Gate）

- [ ] **篇幅控制**：单篇文档行数建议控制在 **80~180 行**，密度高、废话少；
- [ ] **全局搜查零杂质**：全文检索 `原图`、`逐字`、`修正`、`自评`、`码点`，必须 **0 命中**；
- [ ] **图文匹配核验**：所有 `assets/` 图片路径有效，特写图边缘规整无截断；
- [ ] **术语严谨**：英文缩写与专业词汇准确（驼峰/大小写无误，如 `max.poll.interval.ms`, `RecordAccumulator`）；
- [ ] **排版自洽**：加粗自然，标题层级严谨（`#` $\to$ `##` $\to$ `###`）。
