# 激活与渐进披露

新用户第一次打开产品时看到什么，决定他会不会有第二次。激活的目标**不是教会产品**，而是尽快把人送到那个"这东西值得我花时间"的时刻。

**触发时机**：新建产品、设计首次运行体验、空状态、引导流程、功能发现时读本篇。空状态的组件实现见 `components.md`，本篇讲**策略与流程**。

## 先定三件事

1. **Aha moment 是什么**：用户做完哪个动作会觉得这东西有用（创建第一个项目、发出第一条消息、看到自己的第一份数据）。整个激活围绕它设计。
2. **用户是谁**：新手/老手/混合。老手要给跳过；新手要给模板与示例。
3. **成功怎么衡量**：首次价值时间（TTV）、完成率、跳过率、流失点。没有指标就没法判断做得对不对。

**核心约束**：教 20% 拿到 80% 价值，其余留到用户真的用到时再教。

## 原则

- **示范胜过描述**：给可运行的真实功能，不要单独的"教程模式"。教程和产品分离，用户学完还是不会用。
- **可跳过**：老用户能直接进产品。"跳过"不能藏起来。
- **按需而教**：用户遇到功能的那一刻再解释（空状态、点用提示、渐进披露），不要开场把全部功能讲一遍。
- **不居高临下**：默认用户懂通用模式。不要解释"点击保存会保存"。
- **不在返回用户身上重复**：记住已完成的引导与已关闭的提示，尊重"不再显示"。

## 首次运行流程

| 阶段 | 要求 |
|---|---|
| 欢迎 | 一句话说清是什么、用户能得到什么、需要多久；老手可跳过 |
| 账户 | 只收当下必需的字段，其余后置；说明为什么需要；给合理默认值 |
| 核心概念 | 只讲 1–3 个，用交互而不是阅读；有进度指示（第 1/3 步） |
| 首次成功 | 用预填示例或模板引导完成一件真实的事；完成后给明确下一步 |

## 功能发现

- **空状态**是激活的主要时机（四类空状态见 `resilience.md`）。
- **点用提示**：在用户第一次遇到该功能时出现，指向具体元素，一句收益说明，可关闭且记住选择。
- **渐进披露**：先只给常用项，复杂的按需展开；不要一次展示所有选项。
- **功能公告**：新功能上线时说明"是什么 + 为什么有用"，并允许立刻尝试。
- **引导游览**：仅用于复杂界面或重大改版；每轮 3–7 步，可跳过、可重播，优先让用户点击真实按钮而非被动观看。

## 反面清单

- 强制走完长引导才能用产品。
- 把"跳过"藏起来或做得很难找。
- 同一个提示反复出现，或忽略关闭选择。
- 游览期间锁死全部界面，不让探索。
- 开场灌所有功能（违背渐进披露）。
- 教程里的操作在真实产品里没效果（示例数据缺失）。
- 老用户被当成新用户，每次都重新引导。

## 自检

- 用户能在多短时间内到达 aha moment？还有哪一步可以砍掉或后置？
- 每个空状态是否都给了下一步动作，而不只是空白？
- 引导是否可跳过、可重播、不重复出现？
- 关掉 JS 或首次加载慢时，首次体验是否仍然成立？
- 完成引导的用户知道下一步该做什么吗？
