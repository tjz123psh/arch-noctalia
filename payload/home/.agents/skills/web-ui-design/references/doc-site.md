# 文档站与单文件参考站点

把一组多页文档整理成可搜索、可导航的 wiki / dashboard / 参考手册站点。目标是让用户**快速定位可靠内容**，不是把原文塞进固定模板。绝不编造缺失内容。需要单文件交互交付物时叠加 `artifacts.md` 的打包流程。

## 1. 内容清单

- 列出源 URL / 文件、标题、主题、更新时间与抓取状态；这是后续校验的对照表
- 公开网页用 `web_fetch`；需要发现子页面时用 `web_search`
- 登录页、目录页、错误页、只有几百字的摘要都**不算**真实内容；内容不足时回到一手来源，不要用模型记忆补齐事实
- 命令、配置、警告保留上下文与出处；翻译时保持代码与技术术语原样

## 2. 信息架构

按内容量选择结构：

- 主题少：tab 或目录 + 单条阅读流
- 主题多 / 多层级：可折叠侧栏 + 面包屑 + 全文本搜索
- 高频查阅：紧凑表格、筛选器、可复制的代码块

视图 id、标题、导航与内容维护在**同一个数据结构**里，导航与页面从它派生；不要手写分别维护的侧栏、内容与标题映射，它们必然漂移。

## 3. 内容标准

- 每页有清晰标题、范围界定、实质说明与来源
- 示例必须来自来源或本地验证过；占位内容显式标注，不伪装成可执行的值
- Note / Warning 写清具体触发条件、后果与规避方式，不写"请注意"这类空话
- 保留原文术语；译文自然；搜索同时匹配译名与常见英文术语

## 4. 交互与视觉

- 风格跟随主题与既有设计系统，不强行套暗色、侧栏或卡片
- 导航清楚显示当前位置；返回与深链接行为一致；代码块可复制且不撑破页面横向宽度
- 提供空搜索结果、加载/抓取失败、来源不可用状态
- 小屏导航可达；正文宽度可读；表格与代码块溢出受控

## 5. 校验

1. 源清单里的每个主题都能从 UI 到达，无孤儿视图、无重复 id
2. 真实操作验证：搜索、导航、主题切换、复制
3. 用 playwright MCP 检查桌面/移动、键盘焦点、控制台与长内容溢出
4. 抽查原始来源，确认命令、数字、警告与翻译准确
5. 单文件交付时重新打开产物，验证资源与路由仍工作

第 1 与第 4 条是本类站点的核心验收：可达性证明没有丢内容，回源抽查证明没有走形。视觉与浏览器维度的完整矩阵按 SKILL.md 第 3 段取用。
