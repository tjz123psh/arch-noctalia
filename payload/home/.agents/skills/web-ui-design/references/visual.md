# 视觉立场与品牌表达

用于品牌站、活动页、作品集、编辑型页面——视觉表达本身是产品的一部分，简报要的是一个**不能被误认成别人**的视觉身份。产品工具/后台的克制取向不适用这里的标准，但可用性底线不变。

## 先钉住主题，再谈风格

简报没钉住主题时自己钉：写明一个具体主体、它的受众、页面的唯一任务，并说明这个选择。**主体的世界——它的材料、器械、器物、行话——才是独特性的来源**，不要从上一份设计或流行风格出发。全程用简报的真实内容与题材构建。

## 立意：Hero 是论点

首屏就是论点。用主体世界里最有特征的东西开场，形式随它而定：标题、图像、动效、可运行的演示、一个交互时刻。大数字配小标签、堆支持性数据、加渐变强调——那是模板答案，只有确认它确实最优时才用。

## 排版承担个性

展示字与正文字要**有意配对**，不用在别的项目上也会顺手拿的那两组，并给出明确的字阶、字重、字宽与字距。展示字要按**可见字母特征**定义——骨架、笔画对比、比例、曲线、节奏——而不只是 `serif`/`sans` 标签：优雅流动的场景配上刻板、均匀、方正的字母是气质错配，哪怕字号阶梯完全正确。中西文配对与真实渲染验证方法见下文排版段。字处理本身要成为设计里值得记住的部分，而不是内容的中性运输工具。

## 结构即信息

结构装置——编号、眉标、分隔线、标签——必须编码内容里真实存在的东西，而不是装饰它。`01 / 02 / 03` 这类编号标记只有在内容**确实是有序序列**（真实流程、顺序携带信息的带类型时间线）时才成立；采用任何这类装置前先问它是否真的成立。

## 动效要有理由

想清楚动效在哪里、是否服务于主题：加载序列、滚动触发的揭示、hover 微交互、环境氛围。一个**被编排的时刻**通常比零散效果更有力；有时少即是多，多余动画恰恰是"AI 生成感"的来源。具体参数见本文件动效段。

## 复杂度匹配立意

极繁方向需要繁复的执行，极简方向需要间距、字型与细节上的精确。优雅 = 把选定的立意执行好。

## 极简不等于怯懦

简报限制调色板（单色、黑白灰、冷色调）或要求大量留白时，它限制的是**色彩与密度**，不是让你变得安全。只做到"对齐正确 + 系统字体 + 几乎看不见的强调色 + 一块死平的背景"，能通过"干净"检查却什么都没主张。调色板与密度被锁死时，胆子要**换位置**，不是消失。三个可花的地方，都不违反单色或留白前提：

- **活的质地，不是平涂**。单色背景也能呼吸：缓慢漂移的字模/点阵、极慢的扫描带、生成场、跟随光标的颗粒。灰而活胜于灰而死。背景是一个静态填充时，先问简报是否真的禁止动效，还是你默认了不动。这不只是极简规则——**背景在每种立意下都是设计面**：极繁、主题浓烈的页面同样可能交付一块死平背景；主题自己的材料（印刷感的墨点半调、纸纹、套准标记；主体世界由什么构成就用什么）应该延伸进背景。收尾时专门看内容后面的空白区域：它在承担立意，还是仅仅在托着内容。
- **有立场的字**。极简正是排版挑大梁的地方：纪念碑式的尺度、极端的字重/字宽对比、真正有个性的展示字（或等宽）、把某个字形做成图形签名。页面中部安放一个中庸尺寸的系统字体，是怯懦的默认值，不是极简。
- **确实在场的强调色**。一个克制的冷色/单色强调也应该**被看见**——用在签名元素、每节一个词、交互状态上。调到读起来像灰的强调色（个位数不透明度、接近背景的明度），与没有强调色是同样的欠交付：whisper 不是 invisible。

克制 = 一个强主张加上有纪律的周围，不是没有任何主张。以"干净/简单"为名丢掉所有风险，本身就是一个失败模式：检查极简页面里是否仍有一件值得记住的东西。

## 避开默认簇

AI 生成设计当前聚在三副面孔上：① 暖奶油底（接近 `#F4F1EA`）+ 高对比衬线展示字 + 陶土色强调；② 近黑底 + 单一亮酸绿或朱红强调；③ 大报式版式——发丝线、零圆角、密集报纸栏。三者在某些简报下都合法，但它们是默认而非选择，且与主题无关地反复出现。简报钉死视觉方向时**完全照办**，包括它要求的就是这三者之一；简报留空某个轴时，不要把这份自由花在默认值上。

也要对照自己近期的产出：如果最近几件作品共享同一种色彩温度、同一类字体或同一种情绪（例如总是深色 + 冷调 + 等宽 + 技术感），那是一个**个人默认簇**，再次伸手与伸手去拿通用默认值是同一种失败。人类设计师记得自己刚交付过什么并刻意变化。

## 两步走：先方案，后代码

**第一步，从简报出发做一份紧凑设计方案**：

- **色彩**：4–6 个具名 hex 值描述调色板
- **字体**：先写可见字母特征，再为 2 个以上角色命名字体（克制使用的个性展示字 + 互补的正文 + 需要时用于图注/数据的工具字体）；核实所需中西文字形真实存在，不要相信 CSS 字族列表
- **布局**：一句话散文描述 + ASCII 线框来发散和比较
- **签名**：这一页将被人记住的唯一元素，以恰当方式承载简报

**第二步，写代码前按简报复核这份方案**：任何一处读起来像"换成同类页面也会得到的结果"（用相似的提示走一遍，看是否落回同一处），就改掉它，并说明改了什么、为什么。确认相对独特性之后再开始写代码，严格按修订后的方案执行，每个颜色与字体决定都从方案推导。

写 CSS 时注意选择器特异性：很容易写出互相抵消的类（尤其是 `.section` 这类基于类型的类与 `.cta` 这类基于元素的类），在区块之间的 padding/margin 上最常见。规划与迭代尽量在思考里完成，只在有较高把握会让对方满意时才把想法展示出来。

## 克制与自我评审

把大胆花在**一个地方**：让签名元素成为唯一值得记住的东西，周围保持安静有纪律，砍掉所有不服务简报的装饰。不冒险本身也是一种风险。质量地板不宣告也要达到：响应式下到移动端、可见键盘焦点、尊重 reduced motion。

边做边评审自己的作品，环境允许就截图——一张图胜过一千 token。想想 Chanel 的建议：出门前照镜子，摘掉一件配饰。若手边有地方快速记下试过什么，记下来，下一轮会用上。

## 界面文案

文字出现在设计里只有一个理由：让人更容易理解，因而更容易使用。它和间距、颜色一样是设计材料，不是装饰。

- **从屏幕使用者那一侧写**。按人控制和识别的对象命名，不按系统怎么实现命名：用户管理的是通知，不是 webhook 配置。平实说明它做什么，不要推销。具体永远优于机灵。
- **默认主动语态**。控件说清用了会怎样："保存修改"而不是"提交"。动作在整个流程里保持同名——按钮写"发布"，toast 就应该说"已发布"。界面词汇是导航用的路标，一贯性是人学会怎么用产品的方式。
- **失败与空白是给方向感的时刻，不是抒情**。说明出了什么、怎么修，用界面的口吻而不是某个人的口吻。错误不道歉，也从不含糊。空屏是一次行动的邀请。
- **语域对话化且调准**：平实动词、句首大写、无填充词，语气匹配品牌与受众。每个元素只做一件事：标签负责标注，示例负责示范，没有谁偷偷兼职。

### 文案诊断：把模糊的话改具体

改文案前先定四件事：**要传达的唯一信息**、**要用户做的动作**、**该有的语气**（出错时克制、成功时简短）、**约束**（字数上限、是否能本地化）。好的界面文案是"看不见"的——用户读完就懂，不会注意到措辞本身。

常见病灶与改法：

| 病灶 | 表现 | 改法 |
|---|---|---|
| 术语 | 用实现名词（webhook 配置、实体关系） | 换成用户自己的说法（通知设置） |
| 歧义 | 一句话多种理解 | 明确主语与结果 |
| 被动语态 | "文件已被上传" | "我们已上传你的文件" / "上传完成" |
| 冗长或过简 | 堆修饰，或缺关键信息 | 保留动作与结果，删掉填充 |
| 假设用户已知 | 不提前提就要求操作 | 补一句为什么、在哪做 |
| 缺上下文 | 只说失败不说怎么办 | 说明原因 + 下一步 |
| 语气错位 | 报错时活泼、成功时啰嗦 | 语气匹配用户当下状态 |

几类高频文案：

- **错误消息**：说清发生什么 → 怎么修 → 不要归咎用户。`"Error 403"` → `"你没有查看此页面的权限，请联系管理员开通"`。`"输入无效"` → `"邮箱需要包含 @，例如 name@example.com"`。
- **字段标签**：用完整词，格式信息放示例或提示，不要塞进标签（`"出生日期"` + 占位示例 `MM/DD/YYYY`，而不是标签写 `"DOB (MM/DD/YYYY)"`）。
- **按钮与动作**：写具体动词与对象（`"创建账户"`、`"保存修改"`），全程同名；同一动作在按钮、提示、结果里保持同一叫法。
- **空状态**：给下一步动作，不给抒情。
- **破坏性操作确认**：说明影响范围与是否可撤销，用具体对象名（`"删除项目「报表」"`），不用"确定吗？"。

改完自查：用户能否一次读懂？是否说清了下一步？去掉形容词后信息是否还完整？本地化后是否会撑破布局（见 `i18n-rtl.md`）？

# 质感与完成度

"高级"不是一种视觉风格，而是**任务适配、层次清楚、语言一致、细节精确**四者同时在场。用户提出"更专业 / 高级 / 精致 / 有质感 / 可上线"时读本节；它负责把已选定的方向做到完整，不负责早期架构。

## 完成度的六个面

- **适配（Appropriate）**：结构、密度与语气来自产品语境，不来自品类模板
- **清楚（Clear）**：一眼知道自己在哪、能做什么、什么最重要
- **一致（Coherent）**：同一语义用同一套词汇、组件、间距与动效规则
- **精确（Precise）**：对齐、基线、行长、图标视觉尺寸、状态与边缘经得起放大检查
- **完整（Complete）**：响应式、长内容、空/错误/加载/禁用、键盘与无障碍不是事后补的
- **可识别（Identifiable）**：有一个与主题相关的记忆点，但不是靠堆效果堆出来的"设计感"

## 表面层次

表面层次 ≠ "每一层一个圆角矩形"。按最小充分集选用：留白、对齐与宽度变化；排版角色与基线；分隔线或背景带；重叠、裁切或固定区域；明度、色相或纹理变化；阴影、模糊与透明**只在真正悬浮时**用。默认避免嵌套卡片，只有内外两层表达不同对象、所有权、交互范围或层级，且确实改善扫描时才保留。把统一的卡片网格换成 Bento 不等于问题解决了——先改信息结构，只有内容权重确实不同才改模块尺寸。

## 排版是免费的表达力

排版是最强的免费表现力来源，比加图形或动效便宜得多。工具型界面对排版保守是正确的；**展示型、品牌型、编辑型界面用系统字体栈 + 中等字号对比，是在浪费最大的表达杠杆**。这类界面应主动考虑：

- **展示字要有观点**：极端字重对比（900 压 300）、可变字体的字重/字宽轴、真斜体衬线（Playfair 一类）、宽字距无衬线、甚至竞技感的等宽字。展示级字号跨度可以很极端（`clamp` 到 5–12vw），不受正文阶梯约束
- **字传气质**：衬线 = 编辑/古典/权威，几何无衬线 = 现代/理性，人文无衬线 = 温暖，等宽 = 技术/精确。选字体时先问"这个产品是什么气质"，不是"哪个安全"
- **中文展示字同样能表达**：思源宋体/黑体的重字重、宽字距标题都能立住存在感，不是只有拉丁字体能玩表现力
- **把表现力集中在展示与标题层**，正文与数据层保持克制可读——一处胆大、其余安静，对比才成立

## 造型、图标与材质

建立造型语法：哪些是可操作控件、哪些是内容边界、哪些是浮层。圆角匹配平台、尺寸与品牌，不用"元素越大圆角越大"的机械公式。图标用一个家族，校准描边、视觉重量与视觉中心；emoji 只在产品语言允许时用。玻璃、渐变、颗粒、辉光、3D、插画、自定义光标都是**材质，不是质量指标**，只在强化主题或空间关系时采用。

## 背景是最大的画布

背景不是负空间，它是**最大的画布**。密集工具界面用平实底色是合理的；展示、品牌、落地页用一大块死平色常常是欠交付——那是"没做完"，不是"克制"。背景要有纵深与氛围，按预算选一到两种手段（不要全部堆上）：

- **大气光**：超大半径径向渐变做光晕/光锥；暗背景从近黑（`#0a0a0a`）起步，给提亮与压暗留余量；`mix-blend-mode: soft-light` 色层给光以体积
- **物理质感**：SVG `feTurbulence` 噪点颗粒消除数字平涂感；细网格、等高线、扫描线等呼应主题的结构纹理
- **空间纵深**：分层背景元素（星点、几何、线框网络）配滚动或指针驱动的微视差，配合持续动效让背景"活着"
- **判据**：氛围服务主题与在场感，绝不与前景内容争对比；正文在最亮背景点上仍须达标。氛围是背景的私语，不是前景的喊话

**强度自检（防"调了但看不见"）**：氛围层做完后看输出截图——缩略图尺寸下肉眼分不出明暗过渡、光晕或纹理，就等同没做、等于平涂底色，必须加强重做。常见失败是把渐变/颗粒/辉光不透明度压到 5% 以下求心安；氛围的"私语"不等于不可见，私语也要被听见。可感知的起点值通常是：径向光晕把底色明度抬升 8%–20%、颗粒 8%–14% 不透明度，而非个位数。数值随底色与屏幕调整，**唯一通过标准是截图里真的看得见**。

## 结构与表面的实现顺序

先用无样式线框验证阅读路径，再上视觉。卡片只在对象边界需要独立选择、移动、复用或隔离时使用；连续内容用排版与分节，同类记录用列表，比较用表格，浏览—详情用主从，创建用画布 + 检查器，时间性内容用时间线或轨道。

## 润色顺序

按此顺序做，避免在错误结构上打磨：

1. 任务路径与信息架构
2. 页面构图与响应式重组
3. 排版层次与真实内容
4. 色彩、形状与组件状态
5. 动效、材质与品牌记忆点
6. 像素级对齐、图标、边缘与文案

环境允许时截图核对窄/中/宽三档，并带上长标题、大数据量、空状态与错误状态。放大看对齐，眯眼看层次，去色（灰度）看颜色是否掩盖了结构问题。

## 反模板自检

- 遮住 logo 与文案后，还能认出这个产品的气质吗？
- 去掉圆角、阴影与渐变后，结构还立得住吗？
- 是否把"高级"自动翻译成了深色 + 暖白 + 单一强调色？
- 是否把"编辑感"自动翻译成了衬线大标题 + 小号全大写眉标？
- 是否把"专业工具"自动翻译成了深色侧栏 + 卡片仪表盘？
- 是否把"不同"翻译成了随机形状、过度版式或牺牲平台惯例？
- 有没有无语义的装饰、容器或动效？删掉一个再比较

最终方案应当能说明：每个显著选择服务于哪个任务、内容关系或品牌证据。

# 色彩系统

## 先选策略，再选值

策略先定，取值在后：克制的单一强调色、品牌主色承担大面、功能性多色、数据色板，或沉浸式单色。明/暗、暖/冷由环境与品牌决定，不是默认项。从既有品牌 token 出发；新项目从主题材料或内容里提取种子色。构建 primitive → semantic → component 三层（层级、命名与多平台输出见 `design-system.md`），组件不直接消费任意颜色值。控制强调色的注意力预算——**满屏都在强调等于没有强调**。状态色保持语义，不要只靠颜色传达成功/警告/错误。

## 语义 token，不用裸值

组件里不写裸 hex/RGB，把颜色映射到语义角色：

| Token 类别 | 示例 | 用途 |
|---------------|----------|---------|
| `background` | `bg-primary`, `bg-secondary`, `bg-surface` | 表面与容器 |
| `foreground` | `fg-primary`, `fg-secondary`, `fg-muted` | 文字与图标 |
| `border` | `border-default`, `border-subtle` | 元素间边界 |
| `accent` | `accent-primary`, `accent-success`, `accent-danger` | 交互与语义强调 |
| `state` | `state-hover`, `state-active`, `state-disabled` | 交互反馈 |

### 三层模型

```
Layer 1: Primitives（裸值）       blue-500: #3b82f6
Layer 2: Semantic tokens（角色）  accent-primary: blue-500
Layer 3: Component tokens（局部） button-bg: accent-primary
```

改一次 `accent-primary` 全部组件更新；换主题只需重映射 Layer 2。

### 完整系统的四层结构

1. **品牌层**：primary / secondary / accent，各带完整色阶（50–950）
2. **中性层**：灰阶，覆盖文字 / 背景 / 边框 / 表面
3. **语义层**：success / warning / error / info，每个再拆 background / foreground / border / icon 四个变体（只有一个色值不够用）
4. **扩展层**：数据可视化色阶、插画色、渐变定义

深色模式映射从一开始就设计，不要事后补。

## 对比度阈值（WCAG）

| 内容 | 最低比值 | 标准 |
|---------|-----------|----------|
| 正文（<18px） | 4.5:1 | WCAG AA |
| 大字（≥18px bold 或 ≥24px regular） | 3:1 | WCAG AA |
| UI 元件与图形 | 3:1 | WCAG AA |
| 增强（所有文字） | 7:1 | WCAG AAA |

| 背景 | 安全文字色 |
|-----------|-----------------|
| 白 `#fff` | `#000`–`#595959` |
| 浅灰 `#f5f5f5` | `#000`–`#525252` |
| 深 `#1a1a1a` | `#a3a3a3`–`#fff` |
| 黑 `#000` | `#757575`–`#fff` |

用浏览器 DevTools 对比度检查器或 WebAIM 实测，不要凭感觉。

## 语义色与使用比例

| 意图 | 色系 | 用在哪 |
|--------|-------------|--------|
| 主操作 | 品牌色 | CTA、主按钮、链接 |
| 成功 | 绿 | 确认、完成 |
| 警告 | 琥珀/黄 | 注意、待处理 |
| 危险/错误 | 红 | 错误、破坏性操作、告警 |
| 信息 | 蓝 | 信息横幅、提示 |
| 中性 | 灰 | 边框、禁用、弱化文字 |

- 颜色不能是唯一信息载体：状态色必须配合图标、标签或图案（色盲不可辨红绿）
- 语义色全应用一致，一个色只承担一个语义
- 危险/错误应视觉上最紧急

### 60-30-10

| 比例 | 角色 | 应用 |
|------------|------|-------------|
| 60% | 背景/中性 | 页面底、卡片面、大面积 |
| 30% | 次要 | 区块背景、边框、次要文字 |
| 10% | 强调 | 按钮、链接、激活态、徽标 |

### 数据可视化色阶（与品牌色分开）

- **Sequential**：单色由浅到深，用于有序量级
- **Diverging**：双色阶，用于围绕中点的正负偏离
- **Categorical**：互异色相，用于无序类别

## 色彩评审切面

评估一个界面的色彩决策时按四组看：

- **对比度**：正文 4.5:1 / 大字 3:1 / 交互元件与相邻面 ≥3:1；每一对失败组合都标出实测比值与最低要求；占位符与禁用态不得因对比不足妨碍使用
- **调色板一致性**：是否限定在 token 内、有无 token 外的一次性 hex；中性/主/强调色是否按角色使用；叠加元素是否产生视觉噪声或振动
- **语义使用**：状态色是否成为唯一指示；全屏是否一致；交互色与非交互色是否清晰区分；有无装饰色被误认为可操作
- **可访问性**：deuteranopia / protanopia 下是否仍可辨；Windows 高对比或强制配色模式下是否成立；装饰色是否干扰可读性

命名失败模式：移除下划线后链接色在白底不足 4.5:1；错误态只有红色；占位符 40% 不透明在浅色面上对比不足；贡献者引入 token 外的 hex；交互与非交互共用同一种颜色处理。

# 排版

## 字号阶梯

用模度比例尺，常用 1.25（Major Third）或 1.333（Perfect Fourth）：

| 档位 | 比例 | 尺寸（16px 基准） | 用途 |
|-------|-------|-------------------|------|
| `xs` | 0.75 | 12px | 图注、细则 |
| `sm` | 0.875 | 14px | 次要文字、元数据 |
| `base` | 1.0 | 16px | 正文 |
| `lg` | 1.125 | 18px | 导语 |
| `xl` | 1.25 | 20px | H4、卡片标题 |
| `2xl` | 1.5 | 24px | H3、区块标题 |
| `3xl` | 1.875 | 30px | H2、主要标题 |
| `4xl` | 2.25 | 36px | H1、页面标题 |
| `5xl` | 3.0 | 48px | 展示字、hero |

**规则：** 每页不超过 4–5 个尺寸；层级间对比建议 ≥1.25×；只用阶梯内的档位，不出现阶梯外中间值。

## 字族选择与配对

| 规则 | 示例 |
|------|---------|
| 每项目最多 2–3 个字族 | 1 标题 + 1 正文（+ 1 等宽） |
| 风格要有对比 | 无衬线标题 + 衬线正文 |
| x-height 匹配 | 正文字号下视觉对齐 |
| 系统字体就够好 | `-apple-system, system-ui, sans-serif` |
| 优先可变字体 | 一个文件覆盖多字重 |

```css
/* 无衬线（UI 文本） */
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto,
  "Helvetica Neue", Arial, sans-serif;

/* 等宽（代码） */
font-family: ui-monospace, "SF Mono", "Cascadia Code", "Fira Code",
  Menlo, monospace;
```

品牌主导的页面里排版承担个性：配对要有意为之，展示字按**可见字形特征**（骨架、笔画对比、比例、曲线、节奏）定义，而不只是 `serif`/`sans` 标签；优雅流动的画面配方正均匀的默认字是气质错配。中文与西文的黑度、字面大小、时代感要协调。真实渲染前不要用 CSS 字族声明当作已生效证据。

### 字形气质与中西文配对

字体类别只是起点：`serif` 不自动等于优雅，`sans-serif` 也不自动等于现代；真正进入画面的是字形骨架、笔画对比、重心、曲线和节奏。

**先写气质，再选字体**。为展示字写 2–3 个可观察形容词（例如"纤长、舒展、有书写流动感"），不要只写"高级"。检查四个维度：

| 维度 | 刚直一侧 | 流动一侧 |
|---|---|---|
| 骨架 | 方正、几何、垂直 | 人文、书写性、曲线舒展 |
| 笔画 | 均匀、低对比 | 粗细对比、收笔有方向 |
| 比例 | 紧凑、宽度规整 | 高挑或宽松、节奏有呼吸 |
| 姿态 | 正体、稳定重心 | 真斜体、连笔感、上扬动势 |

优雅/梦幻/诗性方向通常需要流动侧的**两三**项同时成立，而不是给板正字体加 `font-style: italic` 或扩大字距。飘逸不等于潦草：正文、按钮和数据仍用清晰稳定的字体。

**中西文不能各选各的**：按共同气质配对，不按"都是衬线"配对——比较笔画对比、黑度、字面大小、重心和曲线张力。中文可从宋、仿宋、楷或有书写性的展示字中选；英文可从高对比 display serif、真正 italic 或人文体中选；它们不必同族，但放在同一标题里不能像两个时代。先用同字号并排渲染 `魔女之旅 / The Journey of Elaina / 2026`，再分别校准字号、基线、字重和字距，不要假设 CSS 数值相同就视觉等重。中文大字距不是万能的"东方高级感"，只在短标题中按字形测试，正文保持自然节奏。

**角色与剂量**：表现型字体只用于短展示标题、引句、章节名或一枚签名字，长段正文、导航、表单和数字保持可读；真正的斜体字形优先，禁止用 `skew()` 伪造书写感，脚本/连笔字体不用于全大写、长中文或关键操作；优雅不等于一味细——过细笔画在亮背景、小字号和移动屏会断裂，必要时提高字重或缩短使用范围；没有合适的可用字体时宁可调整艺术方向，或引入经过许可、已审计体积与字符覆盖的字体资产，不要在 CSS 里写一个不存在的理想字体名自我欺骗。

**必须验证真实渲染**：

1. 实施前盘点项目资产与系统字体；Linux 可用 `fc-match '<family>:lang=zh-cn'`，Web 字体先确认许可、格式、子集和加载预算
2. 浏览器中用 `document.fonts.check('48px "Family"', '魔女之旅')` 分别检查中文和英文；它只能证明可用性，最终仍要看截图中的实际字形与 fallback
3. 截取目标字号下的中英混排标题，检查气质、基线、黑度、字面大小和移动端细笔画，不要只检查 CSS 声明
4. 关闭网络或模拟字体失败，确认 fallback 不会让标题溢出、变成另一种气质或产生明显布局跳动；关键品牌展示字可预加载，正文避免为风格牺牲首屏性能

验收问题：隐藏图像和颜色后，只看标题轮廓，它仍然表达这个画面的气质吗？若"优雅画面"配的是中性、方正、均匀笔画的默认字，层级再正确也属于气质错配。

## 行高与行长

| 内容 | 行高 | 原因 |
|------|-------------|--------|
| 正文 | 1.5–1.75（移动端不低于 1.4） | 阅读舒适 |
| 标题 | 1.1–1.3 | 大字收紧 |
| UI 标签 | 1.25–1.5 | 紧凑但可读 |
| 代码 | 1.5–1.7 | 便于扫视 |

| 行长 | 理想 | 可接受 |
|------|-------|------------|
| 每行字符数 | 55–65 | 45–75 |
| 正文 `max-width` | `65ch` | `45ch`–`75ch` |

**规则：** 字号越大，行高比例越小。行太长伤眼，太短则断行频繁。

字号阈值：桌面正文 ≥16px/1rem，移动端最低 14px。

## 字重与字距

| 字重 | 名称 | 用途 |
|--------|------|------|
| 400 | Regular | 正文、默认 |
| 500 | Medium | 轻强调、标签 |
| 600 | Semibold | 小标题、导航项 |
| 700 | Bold | 标题、强强调 |

- 用字重制造层次，不只靠字号；每页最多 2–3 个字重档位
- 长段落不用粗体（降低可读性）

| 场景 | 字距 | 原因 |
|------|----------|--------|
| 全大写文本 | +0.05em ~ +0.1em | 改善辨识 |
| 大号展示字 | -0.02em ~ -0.01em | 收紧松散感 |
| 正文 | 0（默认） | 字体自带间距最优 |
| 小字（<12px） | +0.02em | 补偿清晰度 |

## 层次工具

组合使用，不要只靠字号：

| 工具 | 效果 |
|------|------|
| Size | 大者先被看到，清晰区分至少 1.5× |
| Weight | 粗体/实心图标比细线重 |
| Contrast | 高对比吸引注意，战略性用于 CTA/状态 |
| Spacing | 周围留白越多，感知重要性越高 |
| Position | LTR 下左上先见，F/Z 型扫视路径 |
| Density | 孤立元素突出，成组元素被当作一个单元扫视 |
| Case | 大写 = 标签/类别，少用 |

四个层级：Primary（页标题/主 CTA）→ Secondary（区块标题）→ Tertiary（辅助文字/元数据）→ Quaternary（细则/时间戳）。每个视图只留一个主操作。

自检用 **squint test**：眯眼后层次是否仍清晰。

## 常见排版错误

| 错误 | 修复 |
|---------|-----|
| 尺寸过多 | 只用阶梯内 4–5 档 |
| 正文居中 | 左对齐；只有短标题可居中 |
| 对比不足 | 正文 ≥4.5:1 |
| 全大写正文 | 大写只留给短标签 |
| 用下划线强调 | 下划线意味着链接；改用粗体/斜体 |
| 孤行寡行 | 调整宽度或内容 |
| 阶梯漂移 | 微调 1–2px 而不移到下一档 |
| 行高错配 | display 字号配正文行高（或反之） |
| 气质错配 | 流动柔美的画面配低对比、方正均匀的默认字 |
| 幽灵字体 | CSS 写了理想字族但目标文字缺 glyph 或字体未加载，实际全由 fallback 渲染 |
| 硬编码 font-size | 引 token，不用裸值 |

# 视觉层次、美感与数据可视化

## 美感—可用性效应

**原理**：用户认为好看的界面更易用，甚至在交互前就形成判断。核心不是装饰，而是**一致性作为质量信号**——统一间距/对齐/字号让产品显得经过深思；视觉噪声让用户怀疑系统可靠性；精致表面带来容忍度。

**适用**：首次印象（onboarding/落地页/空状态）、错误状态（精致错误页显得可信，粗糙的显得坏了）、信任关键场景（支付/健康/法律）、设计系统。

**边界**：该效应会**掩盖**可用性问题，容忍度有限。它降低首次印象门槛，不能替代扎实的信息架构与交互设计；精致投入必须配合可用性测试。

落地：强制统一间距与字号（不规则 = 粗心）；对齐网格；相似操作权重一致；错误/空/加载态与主流程同等用心；上线前审计视觉不一致——一个粗糙屏会拉低周围所有屏的感知质量。

## 图表选型

先明确要传达的关系，再选能表达该洞察的最简图表：

| 目的 | 首选 | 备选 |
|------|------|------|
| 比较 | 条形图（类别） | 分组条形（多系列）、bullet（目标 vs 实际） |
| 时间趋势 | 折线图 | 面积图（体量）、sparkline（行内） |
| 占比 | 饼/环（少类别） | 堆叠条（多类别）、treemap（层级） |
| 分布 | 直方图 | 箱线图、散点 |
| 关系 | 散点 | 气泡、热力图 |

原则：最大化 data-ink ratio；条形图 y 轴从 0 起；能直接标注就不用图例；用注释高亮关键洞察。响应式：小屏减少数据点、放大标签，移动端可用表格替代图表，tooltip 要触摸友好。可访问性：图表提供文本替代，交互图表可键盘导航。

# 动效：动机、参数与预算

动机判断（何时该动、何时是装饰）见 SKILL.md 第 1 段。这里只给落地参数。

## 时长与缓动语义

时长按"移动距离与元素尺寸"选：

| 类型 | 时长 | 缓动 |
|---|---|---|
| 即时反馈（点击高亮、涟漪、开关） | ≤100ms | linear / ease-out |
| 小元素状态变化（颜色、图标、tooltip） | 150–200ms | ease-out |
| 局部转场（sheet、drawer、展开折叠） | 200–300ms | ease-in-out / standard |
| 全屏转场（页面、模态、导航栈） | 300–400ms | 平台标准曲线 |
| 大幅编排时刻（品牌入场、构造演示） | 按内容定，但必须可跳过 | 定制曲线 |

**进场用 ease-out**（快起慢停，元素"落位"），**退场用 ease-in**（慢起快走），位移用 ease-in-out。物理感强的界面优先弹簧而非固定时长 tween——弹簧能被打断并从当前速度重定向。

## 编排

- 一个界面同时最多一个主编排时刻，其余克制
- 列表 stagger 合法，前提是每项延迟很小（20–50ms）且总时长可控，不要当成每个列表的默认反射
- 关联元素共享一条时间线（源—目标 morph、共享元素转场），不各自独立动画
- 动效只增强一个**已经可见的默认态**：不要把内容可见性绑在 class 触发的 transition 上——隐藏标签页与无头渲染里 transition 不触发，内容会整块空白发布

## 持续动效（静中有动）

展示/品牌/沉浸型界面在稳定态保留低振幅、慢节奏的持续动效，让画面"活着"而非"播完就死"：

- **环境微动**：背景粒子缓慢漂移、光晕呼吸、渐变极慢位移、噪声纹理流动。振幅小、周期长（4–12s）、无限循环、不抢内容注意力
- **状态在场**：实时/在线指示器脉动、加载骨架流光、数据更新时的数字滚动与高亮
- **响应鼠标/滚动的微视差**：光标附近元素轻微位移、滚动时分层差速，用 lerp 惯性平滑

判据：能长时间停留而不烦人——放在旁边工作 10 分钟不分心才算合格；周期越长、振幅越小、越接近有机节奏越耐看，机械匀速循环最容易露怯。持续动效同样走性能预算，且 reduced-motion 下停止或降为静态氛围。

## 性能预算与降级

- 只动 `transform` 与 `opacity`（合成器层）；宽高、`top/left`、`margin` 的动画会掉帧
- 高级材质（blur、`backdrop-filter`、`clip-path`、mask、shadow/glow）可以用，但代价高，先在低端设备验证
- 目标 60fps，移动端与低端设备是基准；掉帧的动效不如没有
- Core Web Vitals 不达标时动效根本不会被看见——先保性能
- `prefers-reduced-motion: reduce` 不是可选项：位移/缩放/旋转类退化为交叉淡入或即时切换；视差、自动播放、循环、大幅编排关闭或降为静态；降级后内容必须完全可见可用；关闭动效不等于把界面做成完全无反馈

# 叙事与高级视觉模式

用于品牌站、作品集、产品演示、交互空间。**选型前先问：这个模式是在增强内容，还是分散注意？** 实现代码见本节；决策矩阵与组合原则在 SKILL.md 第 1 段的动效判断之后使用。

## 模式组合原则

一个页面只有一个主模式（叙事引擎 / 启动门），其余为从属：

`滚动叙事 + SVG → 产品演示` `水平画廊 + 3D → 作品集` `启动门 + 光标 → 沉浸空间` `暖暗色 + 打字机 → 赛博风` `玻璃卡片 + 动态可读性 → 多阶段叙事`

| 冲突 | 规则 | 原因 |
|---|---|---|
| 动效 vs 性能 | 性能优先，保持 ≤60fps，移动端降级为交叉淡入 | 掉帧毁掉体验 |
| 3D vs 简洁 | 简洁优先，每页 ≤6 张 3D 卡片 | 多了变成噪声 |
| 暖色 vs 品牌色 | 品牌色向琥珀偏移 0.01–0.02 chroma | 保持品牌可辨 |
| 滚动叙事 + 顶部导航 | p>0.1 时导航自动隐藏，触发后恢复 | 不破坏沉浸 |
| 文字色 vs 背景变化 | 用 phase 变量系统动态适配 | 固定值在多阶段背景上必然失效 |

## 滚动叙事引擎

把滚动转化为多阶段叙事：用一个归一化进度 `p ∈ [0,1]` 同时驱动多种状态，而不是简单视差。

```
p = clamp01(-section.top / (section.height - viewport.height))
// 用 lerp 做惯性平滑: procS = lerp(procS, p, 0.13)
```

可同时驱动：SVG 图层绘制顺序、CSS 类切换（`.on`）、文字/数字步进、全局背景色缓变（`body[data-phase="N"]` + transition）、图形旋转/位移、元素透明度/缩放。

实践：滚动即操作隐喻（滚轮成为"动力源"）；`rAF` 循环驱动保证 60fps；`lerp` 惯性平滑避免帧抖动；所有动画状态从归一化进度派生以保证回滚一致；配 `position: sticky; top: 0; height: 100vh` 锁定舞台。

```javascript
const lerp = (a, b, t) => a + (b - a) * t;
procS = lerp(procS, rawP, 0.13);
if (Math.abs(procS - rawP) < 0.0004) procS = rawP; // 收敛后锁定
```

## 全屏启动门

仪式感入口，用于游戏、交互作品、品牌空间。

```css
#splash { position: fixed; inset: 0; z-index: 20;
  display: flex; flex-direction: column; justify-content: center;
  align-items: center; transition: opacity 0.8s; }
#splash.hidden { opacity: 0; pointer-events: none; }
```

```javascript
document.addEventListener('keydown', e => {
  if (e.key === 'Enter' || e.key === ' ') {
    e.preventDefault(); splash.classList.add('hidden');
  }
});
```

键盘（Enter/Space）与点击均可触发。不要用于需要快速获取信息的场景。

## 水平滚动画廊

用于项目列表、卡片画廊。

```css
.h-scroll-track { width: max-content; display: flex; gap: 1.5rem; padding: 0 clamp(1.5rem, 5vw, 6rem); }
```

两端用 `linear-gradient` 渐变遮罩指示还有内容；卡片等宽 `width: clamp(340px, 38vw, 480px)`；可把鼠标滚轮绑定为水平滚动。不适用于逐项比较或窄屏。

## 跑马灯 / Ticker

```css
.marquee-in { display: inline-flex; animation: mq 26s linear infinite; }
@keyframes mq { to { transform: translateX(-50%); } }
```

内容复制两份用 `-50%` 偏移实现无缝循环，速度由 duration 控制，`prefers-reduced-motion` 下停止。只用于技术栈、品牌信息、公告，不承载用户需要停留阅读的重要内容。

## SVG 分层绘图

适合机械、工程、建筑、产品的"构造过程"展示。

| 图层 | 用途 | 样式 |
|------|------|------|
| 蓝图虚线层 | 全部零件轮廓参考 | `stroke-dasharray: 5 6; opacity: 0.7` |
| 实线加工层 | 当前阶段加工的零件 | `stroke-width: 1.4; fill: none` → 逐步填充 |
| 剖面线层 | 显示切削/截面 | `clip-path` 限定区域 + 45° 平行线 |
| 尺寸标注层 | 公差/尺寸标注 | 等宽字体 + 引出线 |
| 质检章 | 完成状态标记 | 旋转 + 缩放动画入场 |

```javascript
// 逐件加工动画（stroke-dashoffset 从全长 → 0）
const L = element.getTotalLength();
element.style.strokeDasharray = L;
element.style.strokeDashoffset = L * (1 - clamp01((p - start) / duration));
```

用 `<defs>` + `<use>` 复用路径；`transform-box: fill-box` 保证 transform-origin 正确；实线/虚线切换用 opacity 过渡。不用于纯 UI 界面或照片展示。

## 高级光标与 HUD

- **何时用**：沉浸式体验、品牌展示、设计作品集；不用于普通内容型网站
- **实现**：`cursor: none`（只在 `@media (pointer: fine)` 启用），主准星/图标 + 外围环双元素结构，hover 时放大/旋转/变色

```css
#cursor { position: fixed; top: 0; left: 0; pointer-events: none; z-index: 1000; }
.cursor-in { width: 34px; height: 34px; margin: -17px;
  transition: transform 0.35s cubic-bezier(0.2, 0.8, 0.2, 1); }
#cursor.on .cursor-in { transform: scale(1.7) rotate(45deg); }
```

HUD 坐标系统可实时显示鼠标位置与模拟遥测数据，适合"驾驶舱/操作台"风格。触摸设备必须有不依赖光标的等价路径。

## 文字动画

**逐字拆分入场**：

```javascript
element.innerHTML = [...text].map(c => `<span class="ch-w"><span class="ch">${c}</span></span>`).join('');
// CSS: .ch { display: inline-block; transform: translateY(115%); }
// 动画: translateY 115% → 0，stagger 45ms
```

**乱码解码特效**（技术感/赛博风）：

```javascript
function scramble(el, text) {
  const chars = '01/—+|×·';
  let i = 0;
  const iv = setInterval(() => {
    el.textContent = [...text].map((c, j) =>
      j < i / 2 ? c : chars[Math.random() * chars.length | 0]
    ).join('');
    if (i++ / 2 >= text.length) { clearInterval(iv); el.textContent = text; }
  }, 32);
}
```

只用于标题/关键词，不给整段正文用；reduced-motion 下直接显示终态文字。

## 3D 透视卡片

```css
.card-inner { perspective: 800px; transform-style: preserve-3d; will-change: transform; }
```

光晕用 `mix-blend-mode: soft-light` + 径向渐变；鼠标移动时按相对卡片中心的位置计算旋转角；hover 时卡片内元素有独立 Z 轴位移。每页 ≤6 张，不用于列表/表格内容。

## 暗色美学增强

暖暗色系（ACG/作品集风格），完整暗色主题规则见 `dark-mode.md`：

```css
--bg: #0a0a0a;           /* 近黑背景，非纯黑 */
--bg-elevated: #111;     /* 卡片/表面，略亮于背景 */
--text: #f0ede6;         /* 暖白文本，非纯白 */
--text-dim: #888880;     /* 辅助文本，带暖灰调 */
--accent: #d4a574;       /* 琥珀主色，暖色锚点 */
```

- 所有中性色向主色色调偏移（+0.005–0.015 chroma）
- 浅色背景也用暖白 `#faf7f1` 而非纯白
- 渐变用同色系深浅过渡，避免突兀色相跳跃
- 表面边缘用边框而非投影（暗色下阴影不可见）
- 背景可叠 SVG `feTurbulence` 颗粒纹理（2.5%–3.5% 不透明度）增加物理质感

## 动态可读性系统

解决玻璃质感 + 多阶段背景下的文字颜色自适应。文字的颜色、阴影与叠加层不应是固定值，而应随所在阶段变化。适用：滚动叙事背景变化、玻璃质感、多色相渐变背景。

架构：每个阶段定义自己的 `--phase-*` 变量——`--phase-text`（主色）、`--phase-text-soft`（辅助色及透明度）、`--phase-text-shadow`、`--phase-card-bg`、`--phase-overlay`、`--phase-label-opacity`。

```css
:root {
  --phase-text: #fff;
  --phase-text-soft: rgba(255,255,255,0.65);
  --phase-text-shadow: 0 1px 4px rgba(0,0,0,0.08);
  --phase-card-bg: rgba(255,255,255,0.06);
  --phase-overlay: rgba(0,0,0,0.06);
}
/* 亮背景阶段 → 提高叠加层 */
.phase-light {
  --phase-text-soft: rgba(255,255,255,0.82);
  --phase-text-shadow: 0 1px 8px rgba(0,0,0,0.25);
  --phase-overlay: rgba(0,0,0,0.18);
}
/* 暗色文字阶段（如 Hero 压在原图上） */
.phase-hero {
  --phase-text: #1A202C;
  --phase-text-soft: #3D4A5C;
  --phase-text-shadow: 0 2px 12px rgba(255,255,255,0.4);
  --phase-overlay: rgba(0,0,0,0);
}
/* 暖色背景阶段 → 暖色叠加层代替纯黑 */
.phase-warm {
  --phase-text-shadow: 0 1px 8px rgba(0,0,0,0.2);
  --phase-overlay: rgba(30,15,0,0.18);
}
```

叠加层用伪元素放在区块背景与内容之间：

```css
.section::before {
  content: ''; position: absolute; inset: 0; pointer-events: none;
  background: linear-gradient(180deg, rgba(0,0,0,0.15), rgba(0,0,0,0.35));
  opacity: var(--phase-overlay); z-index: 0;
}
.section-inner { position: relative; z-index: 1; }
```

| 文字颜色 | 背景情况 | 阴影方案 |
|----------|----------|----------|
| 暗色 `#1A202C` | 亮且复杂（照片/渐变） | 白色阴影 `0 2px 12px rgba(255,255,255,0.4)` |
| 白色 `#fff` | 中亮背景（粉/浅渐变） | 黑色阴影 `0 1px 8px rgba(0,0,0,0.25)` |
| 白色 `#fff` | 暗色背景 | 浅阴影 `0 1px 4px rgba(0,0,0,0.08)` |

决策规则：

```
文字要放在变化的背景上？
├─ 纯色/简单背景 → 固定颜色 + text-shadow 即可
├─ 渐变/照片/多阶段 → 动态可读性系统
│   ├─ 亮色阶段 → 白字 + 深叠加层 (0.15-0.22) + 强 shadow
│   ├─ 暗色阶段 → 白字 + 浅叠加层 (0.05-0.10) + 弱 shadow
│   └─ Hero 直压 → 暗色文字 + 白色双层 shadow
└─ 所有文字用 --phase-text-soft，不硬编码 rgba
```

与 WCAG 的关系：固定颜色在变化背景上必然在某些位置跌破 4.5:1；动态可读性系统用阶段级 overlay + shadow 保证任何阶段正文 ≥4.5:1。验证方法是截取每个阶段的截图，用 WebAIM Contrast Checker 抽查。

## 叙事模式对视觉层次的影响

| 模式 | 对层次的影响 | 评审时检查 |
|------|-------------|-----------|
| 3D 透视卡片 | Z 轴 depth 成为额外层次工具 | hover 时卡片是否仍保持页面层级位置 |
| 磨砂玻璃 | 透明度降低文字对比度 | glass 上的文本是否 ≥4.5:1 |
| 全屏启动门 | 启动门前只有一条信息路径 | 启动门后首个焦点是否清晰 |
| 滚动叙事 | 层次随进度动态变化 | p=0 与 p=1 时主要焦点是否明确 |
| 自定义光标 | 光标本身成为层次载体 | 光环缩放时是否遮挡下方内容 |
| 动态可读性系统 | 背景叠加层改变文字感知深度 | 叠加层是否让背景失去层次感 |

3D/glass 用 depth **增强**层次，不能替代传统的大小/颜色/位置。

## 叙事模式选型矩阵

| 模式 | 适用 | 不适用 | 常见组合 | 设计原则 |
|---|---|---|---|---|
| 滚动叙事引擎 | 产品故事、流程演示、品牌沉浸页 | 纯信息页、长文 | + SVG 图层 / + 打字机 | 动效即信息、性能即美学 |
| 全屏启动门 | 个人空间、游戏、交互作品、品牌首页 | 需要快速获取信息的用户 | + 自定义光标 | 反馈、简洁 |
| 水平滚动画廊 | 作品集、项目列表、卡片展示 | 逐项比较、窄屏移动端 | + 3D 卡片 | 简洁、内容网格 |
| 跑马灯 | 技术栈、品牌信息、公告 | 用户需要停留阅读的重要内容 | — | 动效即信息 |
| SVG 分层绘图 | 机械/建筑/产品"构造过程" | 纯 UI 界面、照片展示 | + 滚动叙事 | 动效即信息、视觉层次 |
| 高级光标 HUD | 沉浸体验、设计工具、品牌站 | 普通内容站、触摸设备 | + 滚动叙事 / + 启动门 | 反馈 |
| 打字机 + 故障效果 | 技术标题、赛博风、叙事开场 | 全文、正式内容 | + 滚动叙事 | 动效即信息 |
| 3D 透视卡片 | 作品展示、产品卡、交互面板 | 列表/表格内容 | + 水平画廊 | 视觉层次、反馈 |
| 暖暗美学 | 品牌与素材明确支持暖暗氛围 | 明亮品牌、长时间高照度阅读 | + 可选叙事模式 | 环境优先、一致性 |
| 动态可读性系统 | 多阶段玻璃质感页、滚动叙事 + 背景变化 | 单色背景纯内容页 | + 滚动叙事 / + 玻璃卡片 | 对比、反馈 |
