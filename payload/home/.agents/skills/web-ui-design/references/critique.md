# 逐屏视觉评审

把"感觉不对"翻译成具体、可执行的修复项，而不是泛泛点评。用于界面已存在（实现或截图）、需要对某一屏做设计质量评审：视觉层次、排版、色彩、构图、可供性、信息密度、品牌一致性。新建或重设计的视觉闭环见 SKILL.md 第 3 段；纯 WCAG 合规审计走 `accessibility.md`；浏览器行为证据走 `validation.md`。

## 评审前

- **有可视产物才评审**。只有文字描述时先索取截图或可运行的实现，不要凭空评。
- **对标必须先渲染参照物**。涉及"和某参照页比较"时，参照页要在浏览器里真实渲染并截图后逐屏比较；禁止用 `web_fetch` 抓到的文本或模型自述代替对参照物的视觉判断。同时确认评审对象与用户目标一致，别把精力全花在自己的产物上。
- **通道分工**：界面语义、层次、拥挤与遮挡用截图做图像分析；实时 DOM、响应式断点、控制台错误用 playwright MCP。两者结论分开报告。
- **品牌维度需要依据**：只在项目提供 `mood.md` / `voice.md` / `tokens.md`（或等价的设计系统来源）时评审品牌一致性；缺失就跳过该维度并说明，不要虚构品牌规则。
- **与行为验收分开**：本评审只负责视觉与设计判断（层次、构图、语气、密度、品牌）；视口、溢出、状态、控制台、性能与无障碍证据属于 `validation.md`。两份报告不要合并成重复清单，也不要用"功能通过"替代"视觉通过"。

## 选择切面

不必每次跑全部七项。按被评界面的主要风险挑选，一次读一到三个切面，不要一次性加载全部。

| 切面 | 何时重点查 |
|---|---|
| 视觉层次 | 用户不知道先看哪、CTA 被埋、层级扁平 |
| 排版 | 字阶混乱、可读性差、token 漂移、气质错配 |
| 色彩 | 对比度、语义色、色觉障碍、token 外的一次性取值 |
| 构图 | 平衡、留白、节奏、Gestalt 分组 |
| 可供性 | 什么可点不清、状态缺失、主操作不明显 |
| 信息密度 | 认知负荷过高、优先级混乱、缺少渐进披露 |
| 品牌一致性 | 与设计系统、tokens 或品牌语气偏离 |

## 视觉层次

- **入口点**：是否有单一主导元素；大小/对比/位置是否确立入口；入口是否匹配本屏首要目标
- **视线流动**：路径是否遵循 F 型、Z 型或有意的阅读顺序；有无死胡同、循环、跳跃；是否自然导向首要 CTA
- **视觉权重**：层级间大小差是否至少 1.5×；粗字重是否克制；背景填充、描边、图标是增强还是对抗层次
- **强调**：每屏是否恰好一个主强调区；颜色/对比/动效是否互相抵消；最高强调是否匹配真实优先级

失败模式：多个竞争的主元素；层级扁平（大小、权重、颜色太接近）；装饰压过功能；CTA 比周围内容更安静。

## 排版

- **字形气质（Character Fit）**：真实渲染出来的骨架、笔画对比、重心、曲线、节奏是否服务画面语气，而不只是 CSS 里写了什么 family；中文与西文的黑度、字面大小、时代感、动势是否协调；展示字是否只用于短标题与签名时刻；是否验证过真实字体加载与 glyph fallback——声明 `serif`、`Songti SC` 或某个 Web font 不构成已渲染证据。判据与中西文配对方法见 `visual.md`。
- **字号阶梯**：是否只用定义好的档位（display、h1–h4、body-lg、body-sm、caption）；每档是否用于其预期角色；有无阶梯外的中间值；层级对比是否 ≥1.25×
- **可读性**：正文是否达到桌面 16px / 移动 ≥14px；行高是否按内容类型（标题 1.1–1.3，正文 1.4–1.6）；正文行长是否在 45–75 字符；字距是否恰当；对比是否达标
- **一致性**：语义等价元素（所有卡片标题、所有表单标签）是否同一字体处理；对齐是否一致；字重是否克制——单屏同时活动的字重档位超过两个会稀释对比
- **Token 合规**：font-family/size/weight/line-height/letter-spacing 是否经 token 设定；列出每个硬编码值及其正确 token 名

失败模式：阶梯漂移（微调 1–2px 而不移到下一档）；行高错配（display 字号配正文行高）；无理由的对齐混用；组件里硬编码 font-size；气质错配（流动柔美的画面配方正均匀的默认字）；幽灵字体（CSS 写了理想字族但目标文字缺 glyph 或字体未加载，实际全由 fallback 渲染）。

## 色彩

- **对比度**：正文是否 ≥4.5:1，大字（18px+ regular、14px+ bold）是否 ≥3:1；交互组件与相邻表面是否 ≥3:1；每一对失败组合标出实测比值与最低要求；占位符与禁用态是否因对比不足妨碍使用
- **调色板一致性**：是否限定在 token 内，有无 token 外的一次性 hex；中性/主/强调色是否按角色使用；相邻或叠加元素是否产生视觉噪声或振动；整体色调（暖/冷/中性）是否契合语境
- **语义使用**：颜色是否被当作状态的唯一指示（若是要标记——必须配图标、标签或图案）；状态色是否全屏一致；交互色与非交互色是否清晰区分；有无装饰色被误认为可操作
- **可访问性**：deuteranopia / protanopia 下是否仍可辨；Windows 高对比或强制配色模式下是否成立；装饰色是否干扰可读性

失败模式：移除下划线后链接色在白底不足 4.5:1；错误态只有红色；占位符 40% 不透明在浅色面上对比不足；贡献者引入 token 外的 hex；交互与非交互共用同一种颜色处理。

## 构图

- **平衡**：对称或非对称是否有意为之；重元素是否被轻元素抵消；布局是否稳定（头重、脚重、左偏）；是否有清晰视觉重心
- **留白**：区块之间的宏观留白是否足够；微观留白（标签、图标与相邻元素）是否一致；留白是引导注意力还是把布局碎成互不相关的区域；有无区域被过度压缩
- **节奏**：间距是否一致并源自间距刻度；重复元素（卡片、列表项、表单行）尺寸与间隙是否统一；是否有变化而不混乱；分节与分隔是否形成可读的页面韵律
- **Gestalt**：接近（相关元素靠近、不相关清晰分开）、相似（功能相同则视觉处理相同）、图/底（前景与背景清晰区分）、连续（对齐与流动线引导视线）、闭合（不完整分组仍被正确感知）

失败模式：等权双列无主次；内边距不一致（16/20/24px 混用无系统）；孤立元素漂浮，缺少接近关系；拥挤区块紧邻空旷区块造成视觉断崖；竞争性横线与分隔线越加越多却不增加结构。

## 可供性

- **可点击信号**：交互元素是否通过颜色、形状、下划线或高度与静态内容区分；有无虚假可供性（像可点但不可点）与缺失可供性（可点但像静态）；移动端触摸目标是否 ≥44×44px
- **状态可见性**：default / hover / active / focus / disabled / selected 是否视觉区分；焦点态是否可见且高对比；异步内容处是否有 loading 与 skeleton；禁用态是否不只依赖颜色
- **CTA 清晰度**：每个视图是否只有单一主导 CTA；主 CTA 是否用填充样式、次操作用 ghost 或文字变体；标签是否具体且动作导向（"保存修改"而非"确定"）；位置是否符合预期（表单右下、内容块后内联）
- **操作可发现性**：操作是否藏在触摸端无法访问的 hover 态或 tooltip 后；上下文操作（编辑、删除、分享）是否可见或有提示；空状态是否告诉用户下一步；破坏性操作是否与建设性操作视觉区分

失败模式：低对比语境下 ghost 按钮边框不可见；用 `outline: none` 抑制焦点环且无替代；一屏多个填充 CTA；编辑/删除藏在 hover 后（触摸端不可达）；空状态不解释也不提供前进路径。

## 信息密度

- **认知负荷**：完成主任务需要同时处理多少信息片段；是否有不相关元素竞争注意力；页面是否想同时服务多个目标；有无不服务当前任务的装饰、次级数据、元数据噪音
- **内容优先级**：用户据以行动的主要信息是否在首屏；支持信息是否视觉上从属；有无权重相等但重要性不等的内容；关键信息是否被埋在 tooltip、折叠区或低对比次级文字里
- **扫描模式**：结构是否匹配真实阅读方式（F 型用于左对齐列表/表格，Z 型用于 hero + CTA）；标签是否左对齐一致以便纵向扫描；数字、日期、状态值是否对齐且格式一致；内容是否拆成可扫描的块
- **渐进披露**：是否一次全显示而非把细节延后；展开区、tab、modal 是否隐藏真正次要的内容而非主操作；高级选项是否与主流程分离；是否呈现清晰起点

失败模式：仪表盘显示所有可用指标而非最可操作的；详情页内联所有关联对象而非链接；表格 10+ 列而其中 3 列完成 90% 的工作；表单一次显示所有字段而多步流程本可降低感知复杂度；引导在用户做任何事之前就前置大量解释。

## 品牌一致性

参考文件：`mood.md`（个性、美学关键词、视觉参考、do/don't）、`voice.md`（语气、语言风格、文案规范、词汇）、`tokens.md`（权威的颜色、间距、圆角、阴影、排版值）。缺失则记录并跳过，不要虚构。

- **Mood 对齐**：视觉语言（图像风格、插画、图标、色彩感觉）是否匹配品牌个性关键词；有无元素语气偏离（活泼品牌却用冷峻企业化样式）；整体情绪基调是否匹配
- **Voice 对齐**：语气是否匹配（直接 vs 对话、正式 vs 友好）；是否违反词汇规则；CTA、标签、错误消息、微文案是否与 voice 一致
- **Token 合规**：是否有硬编码 hex；间距、圆角、阴影是否偏离 token；排版是否用原始 font-size/weight；列出每个不合规值及其 token 等价物

失败模式：硬编码值随时间从 token 漂移；文案未查 voice 规范而默认通用 UI 语言；图像或插画取自品牌参考之外；同屏组件间圆角或阴影不一致。

## 输出格式

对选中的每个切面的每个子维度给出：

1. **观察** — 中立、事实性地描述所见
2. **问题** — 哪里坏了、为什么重要（可读性、可达性、任务效率、可信度）
3. **修复** — 具体可执行的改动（附对比度数值、token 名、间距值等）

每个子维度评级 `pass` / `minor issue` / `major issue`；最后按 `major` 优先给出修复顺序。

评审立场：报行为错误、回归、可访问性缺口与任务阻塞，不把风格偏好当缺陷；每条修复必须落到可观察的结构或数值，不写"可以更精致"这类空话；修复项之间冲突时（如密度 vs 留白）说明取舍，而不是同时要求。
