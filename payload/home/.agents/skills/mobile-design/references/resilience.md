# Mobile Resilience：失败、中断与权限

理想网络、理想设备上的界面不算做完。移动端的失败是常态：地铁里断网、切网瞬断、来电打断、后台被回收、权限被拒、低端机掉帧、折叠态突变。

**触发时机**：涉及网络请求、权限、长列表与图片、异步提交、前后台恢复、深链进入时读本篇。它只补**设计侧的失败与恢复要求**；性能实现细节在 `performance.md`，取证矩阵在 `validation.md`。

## 网络

### 状态与反应

| 情形 | 判定信号 | 界面反应 |
|---|---|---|
| 弱网（高延迟 / 丢包） | 请求未在预期内返回 | 保留骨架或进度，不叠 spinner；超时后转错误态 |
| 断网（飞行模式 / 无信号） | 系统报告无可用网络 | 直接给离线态 + 重试，**不要发请求**（空转耗电） |
| 切网（WiFi ↔ 蜂窝） | 网络路径变化，连接瞬断 | 给 1–2s 宽限期合并抖动，不在切换瞬间判失败 |
| 超时 | 连接 / 读超时 | 具体错误 + 重试；保留用户已填内容 |
| 5xx | 服务端错误 | 通用错误 + 重试 + 反馈入口；不暴露堆栈 |
| 429 | 限流 | 说明等待时间，禁用重复提交 |
| 计费网络（蜂窝 / 热点） | `isExpensive` / 非 `NET_CAPABILITY_NOT_METERED` | 暂停大文件下载与自动播放，告知用户并给「继续」 |

超时值按网络类型和操作代价选，不要全局一个数：普通读请求 10–15s，提交类 20–30s，上传单独处理。重试用指数退避 + 抖动，上限 2–3 次；**离线时进入队列而不是重试**。系统 API：iOS `NWPathMonitor`（`path.isExpensive` / `isConstrained`），Android `ConnectivityManager.registerDefaultNetworkCallback()` 配合 `NetworkCapabilities`（`NET_CAPABILITY_VALIDATED` 才算真通）。切到计费网络时不要静默继续大流量动作。

### 离线可用范围

先给功能划档，再写代码：

| 档位 | 含义 | 要求 |
|---|---|---|
| 完全不可用 | 必须联网且无缓存 | 明确说明并给重试，不要假装能操作 |
| 只读缓存 | 上次拉到的数据 | 展示但标注「离线数据 / 更新于 X」；写操作禁用并说明 |
| 可写队列 | 本地先写，恢复后同步 | 必须幂等 + 明确同步状态（待同步 / 同步中 / 失败 / 冲突） |

### 切回前台与对账

请求在后台被系统冻结，回到前台时状态是**过期**的，不要直接信任冻住的界面。按数据敏感度设刷新阈值：实时类（余额、库存、未读数）< 10s，列表类 30–60s，目录类小时级（缓存实现见 `performance.md`）。回前台的动作顺序：恢复 UI → 取消或续期挂起请求（超时的按失败处理）→ 刷新超阈值数据 → 重放离线队列 → 对账角标与未读数。

离线队列必须解决冲突与重复：同一资源的多次写要合并或串行化；同步失败不能静默丢弃，要给可见的失败项与重试入口。

## 权限

### 请求时机

| 权限 | 何时请求 | 不要 |
|---|---|---|
| 相机 | 用户点「拍照 / 扫码」的同一交互内 | 首屏、注册改头像时立即弹 |
| 相册（读） | 用户点「选择照片」时 | 先要权限再打开选择器 |
| 通知 | 用户完成一次「值得订阅」的操作之后 | 首次启动；权限引导见 `onboarding.md` |
| 定位 | 用户第一次需要附近 / 地图内容时 | 首屏；能只要大致位置就不要精确 |
| 麦克风 | 用户点「录音 / 语音输入」时 | 与相机打包一起弹 |
| 通讯录 | 用户发起邀请 / 找朋友时 | 不问用途就批量上传 |

**能用系统选择器就不要权限**：iOS `PHPickerViewController`（iOS 14+，无需相册权限）、`UIDocumentPickerViewController`、`UTType`；Android Photo Picker `ACTION_PICK_IMAGES`（API 33+，经 Play 服务回溯到 API 30+）无需 `READ_MEDIA_*`。相机也可用 `ACTION_IMAGE_CAPTURE` 委托系统相机（注意：一旦在清单声明 `CAMERA` 权限，就必须申请到才可用）。

### 授权状态机

| 状态 | 含义 | 界面要求 |
|---|---|---|
| notDetermined / 未问过 | 系统弹窗还可用 | 应用内说明页铺垫 → 再触发系统弹窗 |
| granted | 已授权（可能是部分） | 正常流程，不要重复询问 |
| limited | iOS 相册有限访问 / Android 14 部分照片 | 按已授权集合工作 + 提供「选择更多照片」入口 |
| provisional | iOS 通知静默投递 | 保持静默，不要在首启就请求升级 |
| denied（可再弹） | 拒绝但系统仍允许再问 | 说明价值后再请求**一次**，不要再三纠缠 |
| permanentlyDenied | 系统不再弹窗 | 功能降级 + 明确指引到系统设置 |
| restricted | 家长控制 / MDM 策略 | 说明限制方，不给无效入口 |

各平台判定方式不同，必须自己持久化「是否问过」：

- **iOS**：相机 / 相册 / 麦克风 / 定位这类隐私权限的系统弹窗通常**只出现一次**，被拒后只能引导到设置（`UIApplication.openSettingsURLString`）。ATT（`ATTrackingManager`）同样只弹一次。
- **Android 11+**：连续拒绝后系统不再弹窗，且 `shouldShowRequestPermissionRationale()` 在「从未问过」和「永久拒绝」两种情况下都返回 `false`——只看这个返回值会判断错，必须记录自己是否请求过。
- **Android 后台定位**是独立一步：不能与应用内其他权限一起弹窗，必须在设置里选「始终允许」，界面要给分步引导。
- **Android 13+** 通知需要 `POST_NOTIFICATIONS` 运行时权限；targetSdk 低于 33 时由系统在首个通知渠道创建时弹窗。

### 被拒后的降级路径

权限被拒不等于功能消失，每个权限都要写出替代路径：

| 权限 | 降级路径 |
|---|---|
| 相机 | 「从相册选择」或手动输入 |
| 相册 | 系统选择器（无需权限）/ 文件导入 |
| 通知 | 应用内收件箱与角标兜底，不反复推销 |
| 定位 | 手动输入地点 / 邮编，或沿用上次位置并标注 |
| 麦克风 | 文字输入 |

硬要求：拒绝后**不崩溃、不死循环**、不阻塞主路径；引导去设置要有明确时机（用户主动点击需要该权限的功能时），不是每次启动都提示。权限说明文案的写法见 `copy.md`。

## 资源与性能（失败维度）

| 维度 | 失败表现 | 要求 |
|---|---|---|
| 长列表 | 滚动白屏、抖动、内存增长 | 虚拟化 + 分页 / 无限滚动，尾部必须有「加载中 / 到底 / 失败重试」三态（见 `gestures.md`）；失败重试要能续在断点 |
| 图片 | 加载失败留空、滚动串图、内存爆 | 占位 + 可重试的失败占位；离开屏幕取消请求；列表复用必须绑定 item key，禁止使用被回收 holder 的旧状态 |
| 缓存 | 断网或首屏看到空白 | 内存 + 磁盘两级；先给旧数据再刷新（stale-while-revalidate）并标注数据时间 |
| 内存压力 | 后台被杀、图片变白 | 响应 `didReceiveMemoryWarning` / `onTrimMemory`，释放非可见图片与缓存；不要在压力下重建大对象 |
| 低端设备 | 掉帧、启动慢 | 骨架替代复杂动效，首屏只加载可见区域，不在首屏做重计算（见 `performance.md`） |
| 省电 / 散热 | 后台同步不执行、帧率下降 | 读 `isLowPowerModeEnabled`、`PowerManager.isPowerSaveMode`、`thermalState` / `getCurrentThermalStatus()` 后降级：关自动播放、推迟同步、降图片质量。**不要提示用户「请关闭省电模式」** |
| 后台任务 | 上传下载中断或被推迟 | iOS `beginBackgroundTask` 只有约 30s 窗口，长任务用 `BGTaskScheduler` 或 URLSession 后台传输；Android 用 `WorkManager`（周期任务最小间隔 15min）或前台服务。Doze / 后台刷新被关时任务会被推迟到不确定时间，界面不能假设「后台一定能完成」 |

## 系统中断

| 中断 | 信号 | 要求 |
|---|---|---|
| 来电 / 通知横幅 / 控制中心 | iOS `willResignActive`（可能不进入 background）、Android `onPause` | 不要在此刻提交支付或写关键数据；不要弹应用内弹窗（会被覆盖或排队），回来后按需再弹 |
| 锁屏 / 解锁 | 同上 | 应用切换器快照里遮罩敏感内容（iOS 遮罩视图、Android `FLAG_SECURE`） |
| 旋转 | 配置变化 | 滚动位置、选中态、展开态、已填表单必须保持（见 `gestures.md`）；不要用 `android:configChanges` 掩盖重建问题 |
| 分屏 / 多窗口 / 折叠 | 尺寸类变化 | 按窗口尺寸类重组而非拉伸：Android `WindowSizeClass` + `FoldingFeature`（`isSeparating` 决定内容是否避开折痕），iOS `UIScene` 生命周期；展开 / 折叠后 sheet 高度与键盘避让要重算 |
| 输入法切换 | 键盘高度变化 | 用键盘高度通知动态避让，不写死高度；第三方输入法高度差异可达 100pt/dp |
| 系统语言 / RTL 切换 | 进程内语言变化 | 不缓存已格式化的字符串；RTL 方向切换需要重启进程（RN `I18nManager.forceRTL`） |
| 时间 / 时区变化 | — | 不用设备时间做唯一排序依据，列表以服务端时间为准 |

## 输入与提交

- **重复点击**：pressed 反馈 ≤ 100ms（见 `gestures.md`）；提交后立即禁用并显示进行中；支付 / 下单 / 发帖这类动作带幂等键。
- **误触**：主操作与危险操作不相邻；破坏性滑动加撤销窗口或确认。
- **草稿保留**：字段变更后防抖 1–2s 本地持久化，恢复时明确提示「已恢复上次未完成的内容」（实现见 `forms.md`）。
- **乐观更新**：失败必须回滚，且回滚可见（见 `gestures.md`）。
- **乱序响应**：请求带单调递增序号或时间戳，丢弃过期响应；同一资源的并发写要串行化或带版本号。
- **被中断的提交**：超时 / 来电 / 进程被杀后的重试必须幂等；恢复时先向服务端对账再决定是否重发，不要盲目重试产生重复订单。

## 应用生命周期与深链

| 场景 | 内存状态 | 要求 |
|---|---|---|
| 热启动（切后台又回来） | 保留，但网络可能被冻结 | 按上文的刷新阈值对账，不要直接信冻住的界面 |
| 冷启动（进程被系统回收） | 丢失 | 从持久化状态恢复上次屏幕与草稿，重新拉数据并显示加载态，不要显示空屏或首页 |
| 用户手动划掉（iOS 上滑 / 最近任务清除） | 丢失，且 iOS 不做状态恢复 | 必须有冷启动兜底；关键流程状态不能只放内存 |
| 设备重启 | 丢失 | 同上；重启后不要自动弹引导 |

Android 进程可能在任何时候被回收，状态要写进 `SavedStateHandle` / `onSaveInstanceState` 或磁盘，且**不要在持久化状态里存密钥类敏感数据**。

深链、推送点击、分享进入都要覆盖这些边界：

| 情况 | 要求 |
|---|---|
| 未登录 | 保存原始意图，登录完成后直达目标页；不静默落到首页 |
| 对象不存在 / 已删除 | 说明不存在 + 返回 / 搜索入口，不留空白页 |
| 无权限 | 说明原因与申请路径，保留上下文 |
| 需要前置步骤（未加入组织、需更新版本） | 走最短前置流程，完成后回到目标 |
| 冷启动进入 | 合成父级返回栈，保证系统返回有落点，不要一按返回就退出应用 |
| 应用未安装（Universal Link / App Link） | 落到商店页或落地页，安装后带回原始意图 |
| 旧版本推送指向已下线页面 | 迁移到最接近的页面，或明确说明 |

## 自检

- 断网、弱网、超时、切网瞬断、5xx、429 分别显示什么？有没有一处是无限 spinner？
- 离线时哪些功能仍可用？可写数据是否入队、恢复后是否可能重复或静默丢失？
- 每个权限在什么时机请求、被拒走哪条降级路径、永久拒绝如何引导？有没有一次性索要全部权限？
- 前后台往返、来电打断、进程被杀、设备重启后，列表位置 / 草稿 / 选中态 / 未完成任务能否恢复？
- 深链在未登录、对象不存在、无权限三种情况下落在哪一屏？系统返回是否有落点？
- 旋转 / 分屏 / 折叠 / 语言切换后是重组还是拉伸？
- 低端设备、省电模式、内存压力下主路径是否仍能完成？
