# Mobile Screen Critique

对一个已存在的移动界面（截图或真机实现）做结构化评审，把"感觉不对"翻译成具体、可执行的修复项，而不是泛泛点评。本文件是 SKILL.md 第三段截图闭环里的第 3 步。

## 评审前提

- **有可视产物才评**：截图、录屏或真机 / 模拟器。只有文字描述时先要画面，不要凭空评。禁止用文件读取或 OCR 片段代替对画面的观察，也禁止声称"看到了"未经查看的画面。
- **参照物要真实渲染**：涉及"对标某个 App / 页面"时，参照物必须真机或模拟器渲染后截图再逐屏比较；用文字转述、产品介绍或竞品描述代替视觉评判无效。
- **对齐用户目标**：确认被评对象与目标一致，不要把精力全花在自己的产物上而漏评用户真正关心的界面。
- **一次一平台**：iOS 与 Android 按各自惯例分别评审；跨平台界面必须两端各看一次，用一端的惯例去评另一端的实现是无效 finding。
- **品牌维度需要依据**：项目根存在品牌定义文件（情绪 / 语气 / 令牌三类文档，或等价的设计系统令牌来源）时才评品牌一致性；缺失就跳过该切面并说明，不要虚构品牌规则。
- 评审立场：报行为错误、回归、可访问性缺口与任务阻塞；不把风格偏好当缺陷。每条修复必须落到可观察的结构或数值，不写"可以更精致"。

## 选切面（不必每次全跑）

按被评界面的主要风险挑 2-4 个切面，不要把所有清单都套一遍：

| 切面 | 何时重点查 |
|---|---|
| 视觉层次 | 用户不知道先看哪、主操作被埋、与次操作同权重 |
| 排版 | 字阶混乱、可读性差、字号缩放后溢出、token 漂移 |
| 色彩 | 对比度、语义色、深色模式、Dynamic Color |
| 构图 | 平衡、留白、节奏、分组关系被误读 |
| 可供性 | 什么可点不清、状态缺失、操作不可发现（触摸端尤其） |
| 信息密度 | 认知负荷过高、优先级混乱、一屏塞多个用户目标 |
| 品牌一致性 | 与设计系统 / 品牌语气偏离、硬编码值 |

## 切面 checklist

每个子维度给 `pass` / `minor issue` / `major issue`，并写观察—问题—修复。

### 视觉层次

- **入口点**：第一个抓住视线的元素是否就是本屏最重要的东西？是否存在多个同等竞争的主元素？
- **视线流动**：路径是否刻意且高效，是否自然导向主 CTA？有无死胡同或困惑跳跃？
- **视觉权重**：层级之间大小差是否 ≥ 1.5×？粗字重与填充是否克制？背景填充、描边、图标是增强还是对抗层次？
- **强调唯一性**：每屏是否恰好一个主强调区？最高强调元素是否匹配任务优先级？
- 移动端补充：主操作是否在拇指可达区且权重最高；大标题（iOS Large Title）是否被滥用挤掉内容；一屏滚动后首屏仍有明确锚点。
- 失败模式：多个填充按钮互相竞争；层次扁平化；装饰元素压过功能元素；CTA 比周围内容还安静。

### 排版

- **字形气质**：真实渲染出的字形是否服务产品语气（中文黑度与西文是否协调）？是否验证了字体真实加载与 fallback，而不是只在代码里写了字族？
- **字号阶梯**：是否只用定义好的档位（平台文本样式 / 设计系统 token），有无落在阶梯外的中间值？相邻档位对比是否够（建议 ≥ 1.25×）？
- **可读性**：正文字号达阈值（iOS ≥ 16pt、Android ≥ 16sp，标签 ≥ 11pt / 12sp）；行高标题 1.1-1.3、正文 1.4-1.6；行宽约 40-60 字符；对比度正文 4.5:1、大字 3:1。
- **一致性**：语义等价元素（所有列表标题、所有字段标签）用同一样式；对齐有意图；字重不随机变化。
- **令牌合规**：字号 / 字重 / 行高是否走 token 或平台文本样式，有无硬编码固定值使字体缩放失效。
- 移动端补充：**最大 Dynamic Type / 200% 缩放**下是否截断、重叠、把主操作挤出屏幕；长标题与多语言（CJK、德语长词、RTL）是否溢出或断行失败。
- 失败模式：阶梯漂移（微调 1-2px 而不换档）；固定字号导致缩放后溢出；硬编码 font-size 因为"找不到 token"；单屏三个以上字重活跃；只写占位符当标签。

### 色彩

- **对比度**：正文 4.5:1、大字与 UI 组件 3:1；交互组件与相邻表面对比 ≥ 3:1；占位符与禁用态是否因对比不足而不可用；标出实测比值与最低要求。
- **调色板一致性**：是否限定在令牌内，有无一次性 hex？中性 / 主色 / 强调色是否各按其角色？相邻元素是否产生振动或噪声？
- **语义使用**：颜色是否被当作状态的唯一指示？状态色是否全屏一致？装饰色是否被误认为可操作？
- **可访问性**：色觉障碍（红绿盲）下是否成立？增大对比度 / 高对比模式下是否成立？浅色与深色模式是否都检查过？
- 移动端补充：**深色模式与 Android Dynamic Color（壁纸取色）** 下语义色是否仍然可辨；OLED 近黑背景上是否正确处理 elevation（用表面色阶而非阴影表达层级）；系统强调色改变后是否仍满足对比度。
- 失败模式：浅色下链接色不达 4.5:1；错误态只用红色；占位符 40% 不透明度对比不足；深色模式只做了颜色反转没做层级；个别页面引入令牌外颜色。

### 构图

- **平衡**：视觉重量分布是否稳定？重元素是否被抵消？是否有清晰视觉重心？
- **留白**：宏观留白是否足够、微观留白是否一致、是否源自间距刻度？有无过度压缩或碎裂的区域？
- **节奏**：重复元素尺寸与间隙是否统一？分节与分隔是否形成可读韵律，而不是越加越多的线？
- **分组关系**：相关元素是否靠近、不相关是否分开？功能相同的元素是否共享视觉处理？前景与背景是否清晰区分？对齐线是否让视线顺畅穿过？
- 移动端补充：**组内间距 < 组间间距**是否成立（分组误读的首查项）；分组用了最轻的手段（留白 > 分隔线 > 描边容器），嵌套容器是否超过两层；安全区是否参与构图（内容不贴状态栏 / 手势条，底部主操作不被 Home Indicator 遮挡）；小屏上是否把桌面双列硬压成单列而失去比较关系。
- 失败模式：等权双列没有主次；内边距无系统（16 / 20 / 24 混用）；孤立元素漂浮在所属分组之外；拥挤区块紧邻空旷区块形成视觉断崖；分隔线越加越多却不增加结构。

### 可供性

- **可点击信号**：交互元素是否通过颜色、形状、图标或层级与静态内容区分？有无看起来可点却不可点（虚假可供性）或可点却看起来静态（缺失可供性）的元素？触摸目标是否 ≥ 44×44pt / 48×48dp，相邻目标是否留足间距？
- **状态可见性**：default / pressed / focused / disabled / selected 是否视觉区分？**pressed 反馈是否即时（≤ 100ms）**？异步区域是否有 loading 与骨架态？禁用态是否不只靠颜色传达？
- **CTA 清晰度**：每屏是否只有单一主导 CTA？主 CTA 是否用填充、次操作用 ghost / 文字？标签是否具体、动作导向（"保存修改"而非"确定"）？是否位于拇指可达区？
- **操作可发现性**：操作是否藏在 hover 或 tooltip 后？**触摸端是否有可见替代入口**（长按 / 滑动必须另有菜单或按钮）？上下文操作（编辑、删除、分享）是否可见或有提示？空状态是否给出下一步？破坏性操作是否与建设性操作视觉区分并需确认？
- 失败模式：低对比语境下 ghost 按钮边框不可见；一屏多个填充 CTA；编辑与删除只藏在左滑或 hover 后；空状态不解释也不给前进路径；用无反馈的自定义控件替代平台原生控件。

### 信息密度

- **认知负荷**：完成主任务要同时处理几个决策或信息片段？是否有元素不服务当前任务（装饰、次级数据、元数据噪音）？是否一屏想服务多个用户目标？
- **内容优先级**：需要据以行动的信息是否在首屏（且不被键盘 / 折叠区挡住）？支持信息是否视觉从属？关键信息是否被埋进折叠区、sheet 或低对比次级文字？
- **扫描模式**：结构是否匹配用户真实阅读方式？标签是否左对齐可纵向扫描？数字、日期、状态值在列表中是否对齐、格式一致？内容是否拆成可扫描的块而非密集散文？
- **渐进披露**：细节是否延后到详情视图？可展开区 / Tab / sheet 是否隐藏的是真正次要的内容？高级选项是否与主流程分离？屏幕是否有清晰起点？
- 移动端补充：小屏是"每一屏只回答一个问题"，检查是否存在把桌面信息一次全塞进来的做法；长列表是否用分组与索引代替无限堆叠；详情页是否内联所有关联对象而不是链接过去。
- 失败模式：所有可用指标都上首屏而不选最可操作的；详情内联全部关联对象；表单一次显示全部字段（本可分步）；内容繁重的引导在用户做事之前就前置大量解释。

### 品牌一致性

需要项目根的品牌定义文件（情绪 / 语气 / 令牌）或等价设计系统来源；缺失则跳过并说明。

- **Mood 对齐**：图像风格、插画、图标、色彩感觉是否匹配品牌个性关键词？语气是否偏离（活泼品牌用了冷峻企业样式）？
- **Voice 对齐**：所有可见文案（CTA、标签、错误消息、空状态）是否遵循语气与词汇规则？
- **Token 合规**：颜色、间距、圆角、阴影、排版是否都用令牌 / 平台语义资源，有无硬编码值？逐项列出不合规值与正确令牌。
- 移动端补充：图标是否统一用平台图标集（SF Symbols / Material Symbols）；启动图、App 图标、权限说明文案是否与品牌语气一致；原生控件自定义后是否仍符合平台惯例。
- 失败模式：硬编码值随时间从令牌漂移；文案未查阅规范；图标集混用；同屏圆角或阴影不一致。

## 输出格式

对选中的每个切面的每个子维度：

1. **观察** — 中立、事实性地描述所见（不含判断词）。
2. **问题** — 哪里坏了、为什么重要（可读性、可达性、任务效率、可信度）。
3. **修复** — 具体可执行的改动（附对比度数值、令牌名、间距值、平台 API）。

最后按 `major` 优先给出修复顺序。修复项相互冲突时（密度 vs 留白、克制 vs 表现力）说明取舍，不要同时要求。

## 与验收的关系

- 本评审只负责**视觉与设计判断**（层次、排版、色彩、构图、可供性、密度、品牌）；设备矩阵、手势冲突、键盘遮挡、弱网与读屏实测属于 SKILL.md 第三段的平台验收，用 `validation.md`，不要把两个报告合并成重复清单，也不要用"功能通过"替代"视觉通过"。
- 对比度、标签、字体缩放类结论可用自动化扫描支撑，但视觉判断必须基于真实截图。
- 评审发现 `major` 未修正时，验收不得判 PASS；修复后要重新截图比对，确认没有引入新问题。
