# Mobile Gestures & Interaction Patterns

触摸屏没有指针：没有 hover，没有右键，只有一个不精确、会遮挡、随时可能被中断的手指。选择交互模式时以此为前提，再按平台惯例落形态。

## 模式选择决策树

先问"用户要完成什么"，再选模式；模式决定状态需求，组件形态最后定。

```text
用户要做什么？
├─ 浏览内容
│   ├─ 发现式、feed、社交流 → 无限滚动（滑到底自动续，加"回到顶部"）
│   ├─ 有明确目标的查找 → 搜索 + 分页 / "加载更多"按钮
│   ├─ 比较多个对象 → 分组列表 + 排序筛选（移动端不做宽表格，改卡片摘要 + 详情对比）
│   └─ 有序作品、封面主导 → 水平画廊（必须有位置反馈与按钮替代手势）
├─ 输入数据
│   ├─ < 5 个字段 → 单页表单
│   ├─ 5-10 个字段 → 分组或分步
│   └─ > 10 个字段 → 向导 + 进度指示 + 每步保存（详见 `forms.md`）
├─ 操作对象
│   ├─ 创建 / 编辑 → 表单或内联编辑
│   ├─ 删除 / 不可逆 → 确认对话框或底部 Action Sheet
│   ├─ 排序 / 移动 → 长按拖拽 + 键盘 / 按钮替代
│   └─ 高频轻量操（点赞、收藏）→ 乐观更新 + haptic + toast，失败回滚
└─ 系统反馈
    ├─ 操作结果 → Toast / Snackbar（Android 底部，iOS 需自建，注意不遮主操作）
    ├─ 字段错误 → 内联错误消息（不要 toast，也不要 alert）
    ├─ 长任务进度 → 确定式进度条；< 1s 的操作不加 spinner
    └─ 无数据 → 空状态：插图 + 一句解释 + 一个下一步动作
```

## 触摸交互模式表

| 模式 | 移动端适用场景 | 何时不要用 | 平台差异与实现要点 |
|---|---|---|---|
| 骨架屏 | 首屏与列表加载、结构可预测 | 内容 < 100ms 就绪（闪一下更差） | 结构要贴合真实布局，不要一个通用的灰块 |
| 乐观更新 | 点赞、收藏、已读、发送 | 支付、删除、不可逆操作 | 配轻 haptic 与失败回滚提示；回滚要能看见 |
| 无限滚动 | feed、图片流、发现式浏览 | 需要精确位置、需要跳页、结果集小 | 触底加载要有尾部状态（加载 / 到底 / 失败重试）；长按回到顶部 |
| 分页 / 加载更多 | 搜索结果、管理型列表 | 内容发现式浏览 | 移动端用按钮比无限滚动更可控；给总数与当前位置 |
| 下拉刷新 | 内容列表、收件箱 | 实时推送的数据 | 原生手势，不要自造；下拉要有进度与失败提示 |
| 长按 | 多选、上下文菜单、拖拽重排 | 承载主操作 | iOS 长按 → context menu（约 500ms，带 haptic 与预览）；Android 长按 → 多选或菜单 |
| 滑动列表项 | 删除、归档、标记已读 | 隐藏核心功能、无可见替代入口 | iOS 左滑标准；Android 支持但不普遍。**必须**同时提供长按菜单或详情页入口 |
| 横向滑动 | 分页视图、画廊、onboarding | 藏核心内容、与系统返回冲突 | 提供圆点 / 数字位置指示；不与屏幕左右缘手势抢占 |
| 拖拽 | 排序、移动、跨容器搬运 | 目标太小、无障碍场景 | 长按后抬起拖动，落点高亮；提供"上移 / 下移"按钮作为替代 |
| 双指缩放 | 图片、地图、图表 | 正文阅读（改用系统字号） | 缩放手势与系统辅助功能缩放会冲突，要允许双击缩放的替代 |
| 底部 Sheet | 临时选择、筛选、轻量表单、确认 | 复杂表单（> 5 项）、长内容阅读 | 支持下滑关闭 + 把手 + 拖拽吸附；全屏化要保留返回路径 |
| 分段控件 / Tabs | 同级视图切换（≤ 5 项） | 深层导航 | 用平台原生控件，不要自造；切换状态要能被读屏播报 |
| 模态 / Dialog | 关键确认、极短任务 | 大段阅读、长表单 | iOS 居中卡片或 sheet，Android 居中对话框；关闭后焦点回触发元素 |
| 内联编辑 | 标题、短文本、备注 | 长文本、富文本 | 点击进入编辑，明确保存 / 取消；离开时自动保存要有提示 |
| 步进向导 | 注册、结账、复杂配置 | 2-3 步的简单任务 | 进度指示：iOS 可用页点，Android 用顶部步骤条；每步可返回且不丢数据 |
| 空状态 | 列表 / 搜索无结果、首次进入 | 用户还没开始操作（先给引导，不是空状态） | 文案说明为什么空 + 一个明确的下一步动作 |
| Toast / Snackbar | 非关键成功 / 失败反馈 | 关键错误需要用户确认 | Android 底部 Snackbar 可带动作；iOS 无原生 toast，注意不要遮挡底部 Tab 与主按钮 |
| 键盘快捷键 / 外接设备 | iPad 与外接键盘、无障碍切换控制 | 手机纯触摸场景 | 不能作为唯一路径；命令发现性靠 `UIKeyCommand` / 菜单 |

## 六态齐备

每个交互组件都要定义 **default / pressed / focused / loading / disabled / error**（列表与容器再加 **empty / offline / permission-denied**）。缺一种就是设计缺口，不是"以后补"。

- **pressed 必须有即时反馈**：iOS 高亮 / 变暗，Android 涟漪；反馈延迟 ≤ 100ms，否则用户会重复点击。
- **focused** 对外接键盘与无障碍切换控制是必需状态；触摸设备也不要用 `outline: none` 抹掉它。
- **loading** 要区分"按钮内活动指示"（局部，防重复提交）与"整屏骨架"（结构加载）。
- **disabled** 必须仍可辨认且不依赖颜色；优先让按钮可点并在提交时路由到第一个错误，而不是长期禁用。
- **error** 不能只用颜色（见 `forms.md` 的错误体系）。

## 触摸反馈与 haptic

- 触摸反馈是移动端的 hover 替代物：每个可点元素都要有 pressed 视觉变化，不能只有"点了才知道"。
- haptic 只用于强化已经可见的反馈，不制造反馈：成功提交、开关切换、长按触发、拖拽吸附、错误震动。
- 用平台 API（`UIImpactFeedbackGenerator` / `HapticFeedbackConstants`）并尊重系统设置；用户关闭触感反馈后功能必须完整。
- 不要每次点击都震：震动会迅速失去信号价值，并显著耗电。

## 手势冲突与系统保留手势

- **系统保留区不得抢占**：iOS 左缘返回、Home Indicator 上滑；Android 左右缘返回手势、预测性返回、下拉通知栏、上滑多任务。
- 自定义横滑（如左右切换 Tab）要与屏幕边缘保持安全距离（通常 ≥ 20pt/dp），或用次级手势（在内容区内滑动）。
- 与滚动方向冲突时，纵向滚动优先；横向手势要能通过方向判定锁定，避免斜滑误触。
- **手势不能是唯一入口**：任何滑动 / 长按 / 拖拽功能都必须有可见的按钮或菜单替代路径，否则不可发现、且无障碍不可达。
- 手势操作要可撤销或可确认：滑动删除给一次撤销窗口，不可逆操作给确认。
- 列表滚动位置、选中态、展开态在旋转、折叠展开、切后台返回、字体变化后必须保持。

## 无障碍硬性要求

- 所有交互元素可被 VoiceOver / TalkBack 聚焦，有可读的名称、角色与状态（选中、展开、禁用）。
- 滑动操作必须提供长按菜单或详情页入口；拖拽必须提供"上移 / 下移"这类按钮式替代，并播报抓取、位置与放置结果。
- 模态与 sheet 打开后焦点锁在其内部，VoiceOver 焦点移入；关闭后回到触发元素，不落到屏幕顶部。
- Toast 与 Snackbar 在消失前要确保已被播报；短暂出现的内容还要能在通知历史或界面上再次找到。
- 异步结果与状态变化主动播报（`UIAccessibility.post` / `announceForAccessibility` 或 live region）。
- 无限滚动与懒加载要有总数 / 位置语义，让读屏用户知道自己在列表何处、还有多少。

## 命名失败模式

- 主操作藏进左滑或长按菜单，且没有可见替代入口。
- 手指抬起才响应（无 pressed 反馈），或反馈延迟造成重复提交。
- 用 toast 报字段错误，或用 `alert` 弹窗报错。
- 手势与系统边缘返回冲突，导致滑动列表项时误触返回。
- 乐观更新失败后静默回滚，界面与用户认知不一致。
- 无限滚动没有尾部状态，失败后无限 spinner。
- 用横向滚动藏核心内容，或把 Tab 塞满 6 个以上图标。
- 空状态只说"暂无数据"，不给下一步动作。
