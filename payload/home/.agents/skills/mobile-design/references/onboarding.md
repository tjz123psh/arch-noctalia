# Mobile Onboarding：激活与渐进披露

用户第一次打开 App 看到什么，决定他会不会有第二次。移动端的激活窗口比 Web 更短：没有地址栏可以回退，安装来自商店截图，卸载只要长按一下。

**触发时机**：新建 App、设计首次运行、引导页、空状态、权限请求时机、功能发现时读本篇。空状态与权限的失败处理在 `resilience.md`，通知权限文案见 `copy.md`。

## 先定三件事

1. **Aha moment 是什么**：用户做完哪个动作会觉得「这东西有用」——看到附近可用的人、拍出第一张成片、记下第一笔账。整个首启围绕它设计。
2. **用户是谁**：新手 / 老手 / 混合。老手要给跳过；新手要给模板和示例数据。
3. **怎么衡量**：首次价值时间（TTV）、首启完成率、权限授予率、第 1 天与第 7 天留存、流失步。没有指标无法判断做得对不对。

**核心约束**：教 20% 拿到 80% 价值，其余等用户真的用到时再教。移动端还有一条硬约束：**首次价值必须在一次会话内到达**，因为很多用户不会给你第二次。

## 首启流程

| 阶段 | 要求 | 反面 |
|---|---|---|
| 启动画面 | 静态品牌图，不做进度假象 | 用启动画面拖时间、放动画和交互 |
| 价值页（0–3 屏） | 每屏一句收益 + 一个画面；可跳过，跳过入口常显 | 8 屏轮播讲功能清单 |
| 必要信息 | 只收当下必需的；账号可后置或游客模式先行 | 首启就要求注册 + 手机号 + 邀请码 |
| 权限铺垫 | 用应用内说明页解释「为什么需要」，再触发系统弹窗 | 进来就连弹相机 + 通知 + 定位 |
| 首次成功 | 用模板或示例数据完成一件真实的事，明确下一步 | 教程与真实产品分离，示例数据缺失 |
| 达成 Aha | 完成后给明确的正反馈与下一个动作 | 完成后停在空白首页 |

节奏参考：注册类 App 首启可容忍约 1–2 分钟；工具类应在 30–60s 内到达首次价值；**超过 3 屏且不可跳过的引导，完成率会明显下滑**。别把「讲清楚」和「先让我用」对立，能删的步骤都删。

## 权限时机

权限弹窗是首启最容易翻车的地方：系统弹窗只出现一次（iOS 尤其），被拒后只能去设置里改，所以**每一次请求都要有理由**。

| 权限 | 时机 | 铺垫 |
|---|---|---|
| 通知 | 用户完成一次值得订阅的动作后（下单、发布、加好友、开启提醒） | 应用内说明页 → 用户点「开启提醒」→ 系统弹窗 |
| 相机 / 麦克风 | 用户点「拍照 / 录音」时，同一交互内 | 不需要专门铺垫，但要说明降级路径 |
| 相册 | 优先用系统选择器（无需权限） | 需要批量管理时才请求 |
| 定位 | 用户第一次需要附近内容时 | 说明「用于显示附近 X」，能要大致位置就不要精确 |
| 通讯录 | 用户主动发起邀请时 | 说明用途 + 哪些数据会被上传 |

规则：**一次只问一个**；拒绝后走降级路径（见 `resilience.md` 的降级表）；不要用「不授权就不能用」拦截与核心任务无关的权限；不要用奖励或欺骗诱导授权（商店审核与信任双重代价）。

## Aha 与首次价值

- 把最容易成功的一步放在最前：有内容可看就用真实内容（热门、示例、模板），不要留空等用户先创造。
- 要用户输入才有输出时，给**预填示例**让他一键跑通一次。
- 首次价值给完立刻指出下一步（「再记一笔」「把这份报表发给同事」），不要用空首页结束。
- 长流程（建档、开户、配设备）要分步 + 自动保存 + 续做入口，中断后能接着走（见 `resilience.md`）。
- **首次内容要能删**：示例数据必须可清理，否则用户第二天面对一堆不属于自己的东西。

## 空状态策略

空状态是激活的主要时机，不是留白。五类要分别设计，文案与动作都不同：

| 类型 | 用户处境 | 界面 |
|---|---|---|
| 首次使用 | 还没开始 | 一句价值 + 主操作 + 可选的模板 / 示例入口 |
| 用户清空 | 自己删完 | 轻提示 + 最简重建路径，不要大惊小怪 |
| 无结果 | 搜索 / 筛选无匹配 | 说明是筛选导致 + 清除筛选 / 换关键词入口 |
| 无权限 | 看不到但确实有数据 | 说明原因 + 申请或切换账号路径（见 `resilience.md`） |
| 出错 | 加载失败 | 说明失败 + 重试（`gestures.md` 的尾部状态） |

禁止：只说「暂无数据」、把空状态当广告位、把错误伪装成空状态。

## 渐进披露与功能发现

| 手段 | 何时 | 要求 |
|---|---|---|
| 空状态引导 | 功能所在处为空时 | 就地给下一步，不跳模板教程 |
| 点用提示 | 用户第一次遇到该功能 | 指向具体元素、一句收益、可关闭且记住选择 |
| 渐进披露 | 选项多、专业功能 | 先给常用项，高级项按需展开 |
| 强制引导（coach mark / tour） | 复杂界面或重大改版 | 3–7 步、可跳过、可重播、期间不锁全屏 |
| 功能公告 | 新功能上线 | 说明是什么 + 有什么用，允许立刻试 |
| 系统级提示 | 只在必须跨应用提醒时 | 通知 / 角标是承诺，不是引导工具；频繁推送会直接导致卸载或关权限 |
| 应用商店「新功能」 | 更新说明 | 属于商店描述，不算界面文案，也不要在界面里引用 |

**系统级 vs 应用内**：教育用户优先留在应用内。用通知做引导 = 消耗用户对你的推送信任；用系统弹窗做教程 = 用户只会点掉。

## 反面清单

- 强制走完长引导才能使用产品；跳过入口藏起来。
- 首启一次性索要全部权限，或在没有上下文时索要通知权限。
- 用假进度、假加载拖时间，或把引导做成不可跳过的视频。
- 同一个提示反复出现，忽略「不再显示」。
- 引导期间锁死全部界面，不让探索。
- 示例数据无处可删，或被当成真实数据。
- 老用户被当新人处理，每次更新都重新引导。
- 到达 Aha 后被丢在空首页，不知道下一步做什么。
- 引导里的操作在真实产品中无效（示例失效、无网络时整屏空）。

## 自检

- 首次价值时间（TTV）是多少？还能砍掉或后移哪一步？
- 首次打开时用户看到的第一个可操作的东西是什么？要等多久？
- 每个权限在什么时机请求？拒绝后功能是否仍可用？
- 五类空状态是否都给了下一步动作，而不只是空白？
- 引导能否跳过、重播、不再显示？老用户会不会被重复打扰？
- 示例 / 模板数据能一键清理吗？清空后的空状态是否仍然有引导？
- 首启在弱网或离线时是否仍然成立？还是卡在白屏？
