# Mobile Forms

移动端表单的第一约束不是字段数，而是键盘：它占据屏幕近半、会盖住错误、把校验信息推到视野外，用户还常用单手、在被打断的环境里填写。目标是让用户几乎感觉不到在填表——能少填一个字段、少一次键盘切换，都比多加一句提示有用。

## 表单类型与布局

| 类型 | 布局 | 校验策略 | 典型字段数 |
|---|---|---|---|
| 登录 | 单列，2-3 字段 | 提交时校验 | 2-3 |
| 注册 | 单列，分组 | 失焦校验 + 提交 | 5-8 |
| 结账 / 支付 | 多步向导 | 每步失焦校验 + 步提交 | 10-20 |
| 设置 / 配置 | 分组 + 可折叠分节 | 即时（改完即生效） | 8-30 |
| 搜索 / 筛选 | 顶部单行 + 筛选 sheet | 300ms debounce | 2-8 |
| 调查 / 反馈 | 单列，以选择控件为主 | 每页提交 | 5-15 |
| 长表单 | 分组 + 进度指示 | 每段失焦校验 | 15+ |

移动端布局规则：

- **单列永远是默认**。双列字段在窄屏和最大字号下会挤成一团，只有在确实语义并列（如 到期日 月 / 年）时才并排。
- 标签**常驻可见**（浮动标签或字段上方固定标签），不要用占位符当标签——一旦输入，用户就不知道这个框是什么了。
- 输入框高度 ≥ 44pt / 48dp；字段间垂直间距 ≥ 8pt/dp，分组之间更大（用邻近律表达分组，见 SKILL.md 第一段）。
- 主提交按钮放在**拇指可达区**（屏幕下 1/3），可以被键盘顶到键盘上方，或固定在底部并随键盘上移；不要塞在长表单最底部靠滚动才能看见。
- 长表单优先**分步**：按认知负荷切分（谁、什么、怎么付），不按字段数机械切分；每步保存进度并支持返回上一步，返回不丢数据。

## 键盘类型、输入法与自动填充

键盘类型选错，是移动端表单最廉价也最有效的修复点。**用语义化 `type` / `inputmode` 换到正确的键盘布局，同时设好自动填充与大小写策略。**

| 字段 | Web / RN `keyboardType` | 自动填充 | 其他属性 |
|---|---|---|---|
| 邮箱 | `email` / `email-address` | `autoComplete="email"` / `textContentType="emailAddress"` | `autoCapitalize="none"`、`autoCorrect` 关 |
| 电话 | `tel` / `phone-pad` | `autoComplete="tel"` / `telephoneNumber` | 允许含 `+`、空格、连字符 |
| 数字 / 金额 | `inputmode="numeric"` / `number-pad` | — | 金额用 `decimal-pad`；避免用 `type="number"` 造成滚动误改 |
| 搜索 | `search` | — | `enterKeyHint="search"`，回车即搜索 |
| 密码 | `password` | `autoComplete="current-password"` | 隐藏密码要提供"显示密码"切换 |
| 新密码 | `password` | `autoComplete="new-password"` | 强提示配即时强度反馈，别用九条规则列表 |
| 验证码 | `inputmode="numeric"` | `autoComplete="one-time-code"` | 支持从短信 / 邮件自动填充，不用手输 6 位 |
| 信用卡号 | `inputmode="numeric"` | `autoComplete="cc-number"` | 允许分组空格；扫描卡片是更好的入口 |
| 地址 | `text` | `autoComplete="street-address"` / `postal-code` | 优先用系统地址选择器，不手打 |
| 姓名 | `text` | `autoComplete="name"` | `autoCapitalize="words"` |

- **自动填充与密码管理器必须能工作**：设好 `autoComplete` / `textContentType`，用单页表单而不是把 用户名 / 密码 拆到两步，提供可机器识别的字段名，否则用户要手打长密码。
- **`enterKeyHint` / `returnKeyType` 指向下一步**：中间字段用 `next` 并在按回车时移动焦点，最后一个字段用 `done` / `send` / `go` 并触发提交。
- **不要为格式做输入掩码陷阱**：接受用户粘贴的任意格式（带国家码的电话、带空格的卡号），在提交前规范化，而不是边打边纠正光标位置。
- 键盘高度因输入法而异（第三方输入法、语音输入、手写、emoji 键盘差异很大），**不要硬编码键盘高度**；用键盘事件给的高度或 `KeyboardAvoidingView` / `WindowInsets` 自适应。
- 中文输入法有**组合态（composition）**：`onChange` 时不要把拼音当作已输入内容去校验或计数，组合结束后才取最终值（Web 上用 `compositionstart`/`compositionend`，RN 用 `onChangeText` 的实际提交值）。
- 输入类型与标签都要对读屏友好：字段名由 `<label>` / `accessibilityLabel` 提供，不要只靠 placeholder。

## 键盘遮挡

这是移动端表单最高频的事故来源，按顺序处理：

1. **焦点进入滚动容器视野**：输入框获得焦点时滚动到键盘上方，而不是靠用户自己滑。
2. **错误消息不能被键盘盖住**：错误出现在字段下方，字段在键盘上方时错误才可见；校验失败后滚动到第一个错误字段，而不是让用户猜哪个框错了。
3. **主按钮保持可达**：固定在底部的提交按钮随键盘上移，或让表单内容可滚动并在底部留出键盘高度的内边距。
4. **避免布局跳变**：键盘弹出时不要重排整个页面；用内边距 / inset 变化，保持滚动位置与已填内容不变。
5. **失焦不丢内容**：收起键盘、切后台、来电打断、进程被杀后恢复，已填内容与滚动位置都要保留（长表单还要草稿保存）。

## 校验时机

核心原则：**不要打断用户输入**，只在用户说完一句话之后才评断。

| 时机 | 适用字段 | 原因 |
|---|---|---|
| 失焦（blur） | 邮箱、电话、URL 等格式校验 | 用户已完成输入，不打断思路 |
| 提交（submit） | 必填字段的首次检查 | 用户还没走到这些字段 |
| 输入防抖（debounce） | 密码强度、用户名可用性 | 用户主动寻求反馈 |
| 输入即时 | 密码确认匹配 | 依赖字段，需要实时确认 |
| 粘贴后再判断 | 全部字段 | 粘贴后立即报错最招人烦，延迟到失焦或提交 |

规则集：

1. 首次交互 → 失焦校验，让用户把话说完。
2. 字段**已经**报错 → 切到输入即时校验，用户在修正时要看到即时确认。
3. 提交时 → 校验全部字段，滚动并聚焦到第一个错误。
4. 异步校验 → 300-500ms 防抖 + 取消过期请求（`AbortController` / 请求序号），避免旧响应覆盖新结果。
5. 未触达字段 → 提交时才校验，不要一进页面就飘红。
6. 组合策略：失焦校验负责格式，提交校验负责必填。

## 错误体系

三通道分发，不要混用：

| 错误类型 | 位置 | 说明 |
|---|---|---|
| 字段内联 | 字段下方 | 基础位置；图标 + 文字 + 颜色三重编码 |
| 摘要 | 表单顶部（或分步的首步） | 字段 > 6 个时必须有；每条可点击跳转到对应字段 |
| 全局横幅 | 表单上方 | 仅系统级错误：网络中断、服务端失败、会话过期 |

字段状态令牌（示例；项目已有令牌时用项目值）：

```text
error:   border red-500 /  bg red-50  / text red-700
warning: border amber-500/  bg amber-50/ text amber-700
success: border green-500/  bg green-50/ text green-700
neutral: border gray-300 /  bg surface  / text gray-900
```

- 错误消息要**具体、可执行**："邮箱需要包含 @"、"请使用格式 MM/DD/YYYY"、"密码至少 8 个字符"；不要写 "Invalid input" / "错误" / "必填项"。
- 错误文本与背景对比度 ≥ 4.5:1；颜色不是唯一提示（图标 + 文字 + 颜色）。
- 错误必须能被读屏播报（`role="alert"` 或 `accessibilityLiveRegion`），字段状态标为无效（`aria-invalid` / `accessibilityState.invalid`）。
- **错误时保留所有已填内容**，不要清空表单。

## 提交与反馈

- 提交按钮写具体动作："创建账户"、"下单"、"保存修改"，不要写 "Submit" / "确定"。
- 不要为了"合法"而长期禁用提交按钮——用户不知道错在哪。让按钮可点，提交后滚动到第一个错误。
- 提交中：按钮内联 loading + 禁用重复提交（幂等保护），不要整屏遮罩。
- 成功后要有明确落点：跳转下一页 / 关闭 sheet / 显示成功态；异步校验进行中也要能看见，别让用户以为已通过。

## 无障碍（WCAG 2.2 AA）

- 每个字段有持久的可读标签，并与控件关联；分组分节用 fieldset / 分组语义表达。
- `aria-invalid`（校验失败）与 `aria-describedby`（指向错误或帮助文本）。
- 焦点顺序符合视觉顺序，键盘 / 切换控制可达全部字段与按钮。
- 最大动态字号（AX5 / 200%）下标签、错误文本与按钮都不截断、不重叠。
- 正确的键盘类型与自动填充本身就是无障碍特性，不是可选项。

## 常用反模式

1. 禁用提交按钮直到表单合法 → 用户不知道错在哪。
2. 每次按键都校验 → 像在背后看人打字。
3. 用 tooltip 或 toast 报错 → 触摸端不可达、稍纵即逝；错误放在字段下方。
4. 只有红框没有文字 → 色盲用户无法感知。
5. 错误时清空表单 → 最打击人的行为之一。
6. 只给摘要不给内联 → 用户要自己找字段；两者同时存在。
7. 只给内联不给摘要（长表单）→ 修完一个才知道还有三个。
8. 用 `alert()` 报错。
9. 异步校验没有 loading 状态 → 用户以为通过了。
10. 输入掩码边打边改光标位置 → 无法粘贴、无法用语音输入。
11. 用 placeholder 当唯一标签 → 输入后标签消失，也无法被读屏稳定读取。
12. 提交按钮写 "Submit"。
