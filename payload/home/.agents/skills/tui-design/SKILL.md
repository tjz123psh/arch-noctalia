# TUI Design

终端是独立媒介，不是缩水的 GUI。利用字符网格、精确对齐、键盘、低延迟、SSH 与 shell 可组合性，同时尊重终端能力差异。

本 skill 端到端覆盖设计 → 实现 → 验收。按下方顺序推进，不要跳步。

## 工作流

1. **判断**（第 1 段）：运行环境（是否 TTY、能力探测）、已知/推断/未知、一句话问题、内容模型、分组与密度、交互模式、动效动机、终端约束、布局选择、宽度模式——逐项给结论
2. **形态确认**：结构定下后、实现前确定信息形态（列表 / 表格 / 树 / 主从 / 覆盖层）与它在三种宽度下如何变换；窄屏的降级形态要先定，不要等发现放不下再改
3. **分流**（第 2 段）：按判定信号读一到两篇 reference，不追求全读
4. **实现**：跟随项目现有架构与框架约定；帧更新只重算必要区域；只为明确的复杂度新增抽象或依赖
5. **视觉闭环**：真实终端运行 → 截图或录屏 → 按 `references/critique.md` 自评 → 修正 → 再截图（视觉变化时必须走完）
6. **验收**（第 3 段）：选小改 / 常规 / 发布，逐维度留测试、buffer 断言或录屏证据，写出残余风险

范围窄的评审（单个视图、一处对齐问题、一次配色修复）可从第 2 段直接开始，但仍要给出第 1 段中与本次改动相关的判断结论，并按第 3 段留证据。

## 一、判断（在此段直接决定，不读文件）

**先定问题，再画界面。**

- **已知**：需求、现有代码、真实数据、现有终端环境。**推断**：为推进作的最小假设，说明依据、保持可逆。**未知**：会改变架构的问题；能从项目发现就先发现，只有高影响且不可恢复时才问用户。
- 一句话固定：为 `[谁]` 在 `[什么终端环境]` 完成 `[首要任务]`，需要突出 `[内容/操作]`，成功表现为 `[可观察结果]`。
- 六个变量：使用频率、熟练度、紧迫性、错误代价、内容密度、设备与输入方式。高频专业工具与低频消费界面不能用同一套简化逻辑。
- 首次运行还是第 N 次运行：新用户需要一条到首个真实结果的最短路径，老用户不该再看到引导（见 `references/onboarding.md`）。

**内容模型**：列出真实对象、属性、动作、关系、状态，再决定布局。区分主对象与辅助信息、高频与低频动作、必须同时比较与可以渐进披露的内容、以及正常/加载/空/错误/离线/无权限/极端内容。

**分组与密度（终端适配）**：终端里对齐、缩进、空行比边框便宜且更强。分组手段按此顺序升级：

1. **邻近律（默认）**：组内间距 < 组间间距。标签贴紧它的值；区块标题离下方内容比离上一节更近。这个比例关系而非固定列数创造层次。
2. **共同区域**：只有边界本身有意义时（区域独立滚动、可调整大小、需要显式焦点、或与底层分离）才加边框。用能完成任务的最弱手段：缩进 > 空行 > 分隔线 > 边框。嵌套不超过两层。
3. **隔离效应**：只让少数元素与周围形成差异（一行 ghost 项里唯一反显的当前项）。多个元素同时高亮会互相抵消，且不能只靠颜色。

用户误读结构时先查邻近关系，通常是根因。密度由「需要同时比较的量」决定，不由可用空间决定。

**交互模式（终端适配）**：模式本身的适用性跨终端，但终端只有键盘：

| 需要 | 终端做法 | 不要照搬 |
|---|---|---|
| 加载反馈 | 阶段文本 + 计数（`3/8`），或瞬时 spinner | 骨架屏（无像素布局可言） |
| 吞吐过长列表 | 虚拟滚动 + 过滤/搜索 | 无限滚动（无法回滚位置） |
| 分页 | 明确页控件，或「加载更多」键 | 触底自动加载 |
| 确认危险操作 | 覆盖层确认 + 写出对象名与动词 | toast 式静默执行 |
| 临时选择 | 命令面板 / picker 覆盖层 | 底部 sheet |
| 操作结果 | 状态行或通知队列（可累积、可回看） | 自动消失的 toast |
| 上下文操作 | 命令面板列出全部可用动作 | 隐藏的右键菜单 |
| 空状态 | 直接提示下一步按键 | 插图 + 文案 |

每个交互态必须定义六种状态：**默认 / 加载 / 空 / 错误 / 禁用 / 成功**。缺失一种就是设计缺口。状态的**文字内容**（错误消息、空状态、进度描述、键位提示的写法）按 `references/copy.md` 的宽度预算与结构写，不要临场措辞。

**动效（终端适配）**：终端动效的问题不是"够不够炫"，而是**闪烁与重绘**。

- 准入三问同样适用：解释了什么状态变化、去掉是否失去理解、是否复用已有空间逻辑。答不上来的删掉。
- 有意义的动效限于：进度推进、阶段切换、异步状态序列（`idle → requested → running → succeeded/failed/cancelled`）、以及光标/焦点移动的即时反馈。
- 时长以「一次渲染帧」为单位而非毫秒：瞬时反馈同帧完成；需要时间感的过程用计数或阶段文本表达，不用补间动画。
- **禁止**：整屏重绘、逐字符打字机效果（远程会话下必然闪烁）、靠动画营造设计感、把内容可见性绑在定时器上。
- 帧更新只重算必要区域；高频更新要节流合并，避免 resize 风暴或日志洪流下的无限重绘。
- 尊重 `NO_COLOR` 与非交互（非 TTY）场景：无动效时内容必须完全可用。

**终端约束**

| 属性 | 设计含义 |
|---|---|
| 字符网格 | 用行列、显示宽度、稳定对齐；不要像素思维 |
| 基本等宽 | 表格与 diff 高效，但 CJK/emoji 仍需正确宽度处理 |
| 主题由用户控制 | 不假设深色背景；不覆盖全部默认颜色 |
| 能力分层 | TrueColor → 256 → 16 → 无色，每层都必须可用 |
| 键盘优先 | 所有关键动作有键盘路径；鼠标是增强 |
| 远程/复用器 | SSH、tmux、延迟、能力降级都要考虑 |
| Shell 环境 | 退出必须恢复终端；日志不得污染交互屏 |

**运行环境判断（先于设计，不通过就换形态）**：终端程序可能根本没有"屏幕前的人"。

| 判定 | 结论 |
|---|---|
| stdin/stdout 任一非 TTY、`CI` 存在、`TERM` 为空或 `dumb` | 不设计全屏交互；只给行式/`--json` 输出，绝不阻塞等按键 |
| 尺寸/色彩/字符集探测失败或返回 0 | 按 80×24、16 色、ASCII 回退设计，而不是崩或空白 |
| 复用器（`$TMUX`/`$STY`）或高延迟 SSH | 一帧一次缓冲写、不做逐字符动效、鼠标动作必须有键盘等价路径 |
| 可能被 `kill -9`、断连或磁盘写失败 | 清理链幂等且必须挂到所有退出路径，并给用户可执行的恢复指引 |

细节见 `references/resilience.md`；这一判断必须在画界面之前做完。

**布局选择**（按关系选，不按美感选容器）

| 数据/任务 | 首选形态 | 不要默认成 |
|---|---|---|
| 同类记录比较 | 对齐表格或紧凑列表 | 每条一个盒子 |
| 层级/资源树 | 树、Miller 列、下钻栈 | 平铺卡片网格 |
| 主对象 + 详情 | 主从分栏或可切换详情 | 三个等分面板 |
| 连续事件 | 时间线或日志流 | 指标卡片 |
| 一次性查询/执行 | 覆盖层、命令面板、过滤 | 常驻侧栏 |
| 少数关键状态 | 状态行、摘要条、内联标记 | 仪表盘组件墙 |
| 长文档/diff | 全宽阅读区带行号与导航标记 | 窄卡片里的正文 |

**宽度模式**：紧凑 `<80` 单主任务，辅助内容切换或覆盖；标准 `80–119` 主视图 + 有限上下文；宽 `≥120` 仅在确有价值时加并行信息。阈值是起点，按最小内容宽度与真实终端调整；低于最小可用尺寸时给出明确提示或进一步降级。

**启动前停止条件**（出现任一条先重构，别进实现）：所有内容塞进同尺寸盒子；面板数量来自模板而非内容关系；边框比内容更醒目；窄屏只是把面板纵向堆叠；日志/表格/正文没有明确滚动归属；关键状态只能靠颜色或图标辨别。

## 三、验收（本 skill 内闭环，不调外部测试 skill）

用真实终端条件与可复现证据验收，**不接受单张宽屏截图**。证据优先级：纯状态转移测试 > buffer/snapshot/golden 测试 > 伪终端自动输入测试 > 真实终端截图或录屏 > SSH/tmux/不同模拟器的代表性冒烟。**不得**用只比较 ANSI 字符串的测试替代真实宽度与终端恢复检查。

按风险选组合：

| 风险 | 必做证据 |
|---|---|
| 小改 | 目标宽度（80）功能路径 + 退出后终端卫生 |
| 常规 | + 60/120 宽度、16/256/TrueColor、空/错误/加载状态、命令与 footer 一致性 |
| 发布 | + NO_COLOR、明暗背景、ASCII 与 Unicode/宽字符、resize 期间状态保持、SSH/tmux 冒烟、非 TTY/管道形态、性能与闪烁检查 |

主任务最小路径：启动 → 主任务 → 错误恢复 → 返回 → 退出。逐项检查见 `references/validation.md`。

**终端卫生**（正常退出、错误退出、取消、panic 四种路径都要查）：raw mode 关闭、alternate screen 退出、光标可见、echo 正常、鼠标捕获释放、后台日志不再污染 shell。清理的顺序要求与非 TTY/断连路径的验证方式见 `references/resilience.md`。

**交付物**：报告必须列出测试矩阵、失败证据、已做修正、未覆盖环境、残余风险。不要只写"看起来没问题"。

## 四、跨端边界

- Do NOT 用于网页或 Web 应用 → 用 `web-ui-design`；Do NOT 用于原生移动端 → 用 `mobile-design`。**本 skill 自带判断、分流与验收三段，不要在其后再串联任何设计或测试 skill。**
- 视觉方向、质感打磨、设计 token、逐屏评审：终端场景下的做法已在本 skill 内（`references/critique.md` 与 `references/visual-system.md`），不依赖其它 skill。
- 纯 CLI 输出美化（非全屏 TUI）按 `references/frameworks.md` 的生态工具条目处理，不走完整 TUI 流程。
- 若任务需要新增框架级依赖，先确认语言栈与部署约束，再按 `references/frameworks.md` 选型；本环境当前**没有**框架专用 skill，实现遵循项目自身框架约定，不要引用不存在的 skill。
