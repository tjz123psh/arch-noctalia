# TUI 首次运行、帮助发现与空状态

何时读本篇：设计终端产品的首次运行体验、帮助与快捷键的发现路径、空状态、配置初始化时读。视觉呈现（符号、颜色、层级）在 `visual-system.md`，交互状态机与键位分层在 `interaction.md`，本篇只管"用户第一次怎么学会用、之后怎么想起来"。

终端里的引导有一条硬约束：**用户往往就坐在 shell 里，且很可能已经用过同类工具**。过度引导的成本比网页更高——它占屏幕、拦输入、还挡脚本化。

## 一、第一次与第 N 次必须分开

| 条件 | 判定 | 行为 |
|---|---|---|
| 首次运行 | 无配置文件且无状态记录 | 可给一次简短引导（≤1 屏，任何键继续） |
| 老用户 | 已有配置/状态 | **不出任何引导**，直接进主界面 |
| 非交互 | 非 TTY、`CI`、已给 `--json` | 绝不输出引导；见 `resilience.md` |
| 版本升级 | 版本号变化 | 只用一行提示说明破坏性变更，不重放引导 |

"首次"的标志写在自己的状态目录（如 `~/.config/<app>/.first-run-done`），不要靠"配置为空"推断——用户可能只是没改过默认配置。尊重 `--quiet`、`--no-banner` 与"不再提示"的选择并持久化。

比引导更好的做法：主界面默认就摆着一条**真实可执行的示例**（预填路径、示例查询、当前目录的列表），用户按第一个键就产出了真实结果——终端里的 Aha moment 通常是"它把我这堆真实数据变好看"，不是"我看完了一段说明"。

## 二、帮助发现的分工

四条路径各司其职，不要互相复制：

| 入口 | 面向 | 内容 | 何时可见 |
|---|---|---|---|
| footer 提示 | 正在操作的人 | 当前上下文最重要的 3–5 个动作 | 常驻（窄屏可缩减） |
| `?` | 想学的人 | 按上下文分组的完整键位表，含不可用原因 | 覆盖层，`Esc`/`?` 关闭 |
| 命令面板（`Ctrl-P`/`:`） | 记得名字、忘了键的人 | 可搜索的动作列表 + 主键 + 禁用原因 | 覆盖层 |
| `--help` | 脚本与人 | 用法、参数、退出码、非交互示例 | 终端命令行 |

要点：

- `--help` 与交互帮助**不共用同一份文案**：前者要能被 `grep`，后者要按当前视图分组。
- `?` 里必须包含 `?` 本身与退出方式，否则用户进去出不来；footer 随模式变化，编辑态下不显示会与输入冲突的按键。
- 帮助内容与实现的键位必须同源（从一个键位注册表生成），否则必然漂移；长帮助分页或分段，不要一次刷满屏把上下文顶掉。

## 三、空状态是终端最便宜的引导位

终端没有插图，所以空状态只能靠**一句话 + 一个可执行动作**。四类分别处理，文案写法见 `copy.md`：

| 类型 | 触发 | 必须给出 |
|---|---|---|
| 无数据（用户清空/新库） | 集合为空但操作合法 | 具体创建命令或按键（`n 新建`、`app import <文件>`） |
| 无结果（筛选所致） | 有数据但过滤器命中 0 | 当前过滤条件 + `Esc 清除筛选` |
| 未配置 | 缺必填配置/凭据 | 配置路径与 `app config set` 的确切命令 |
| 无权限 | 认证成功但无权读 | 说明原因 + 申请路径或需要的角色 |

再叠加两类终端常见情况：**加载中**（区分首次加载与刷新）与**部分成功**（3/5 项成功，失败项可再试）。空状态不能只是空白加一句 `No items`。

## 四、渐进披露

- 默认视图只放完成主任务必需的列/字段；其余通过 `?`、详情视图、`--verbose` 或配置文件获得。
- 不要在启动时弹"选择你的偏好设置"向导。默认值应当对多数人成立，配置是**用户主动去找**的东西。
- 引导只讲 1–3 个概念（怎么移动、怎么执行、怎么退出），其余留到用户真正用到时再解释；引导里演示的操作必须在真实数据上有效，示例数据缺失会让引导变成谎言（必须用时明确标注并给一键清除）。
- 可跳过、可重放（`app help --tour` 或 `?` 里的一节）、不在返回用户身上重复。

## 五、配置初始化与默认值

| 问题 | 建议做法 |
|---|---|
| 首次运行是否写配置文件 | **默认不写**。只在用户显式执行 `config init`/首次改变某项设置时写入 |
| 写到哪里 | 遵循 XDG：`$XDG_CONFIG_HOME/<app>/config.toml`，回退 `~/.config/<app>/`；状态与缓存分开放 `$XDG_STATE_HOME`/`$XDG_CACHE_HOME` |
| 已有配置怎么办 | 绝不覆盖。合并时保留未知字段与注释（若格式允许）；迁移前备份到 `config.toml.bak` |
| 权限 / 写失败 | 目录 `0700`，可能含凭据的文件 `0600`（见 `resilience.md`）；写失败明确告警一次并降级为内存默认值 |
| 优先级 | 显式参数 > 环境变量 > 项目级配置（`.apprc`）> 用户配置 > 内置默认 |
| 破坏性变更 | 只迁移可无损转换的项；无法自动迁移时保留旧文件并在启动横幅里指明要改哪个键 |

首次运行的引导如果给出了目录/账号选择，选择结果应写进配置**而不是只存在"首次"记忆里**。

## 六、反面清单

- 首次启动强制走多步向导，不给跳过；或把"跳过"藏在最后一页、做得很暗。
- 每次启动都打大型 ASCII 横幅，老用户每次要等它刷完，`-q` 又关不掉。
- 引导拦在键盘上，用户按键被引导吃掉，无法直接操作。
- 帮助里列了实现里已不存在的键，或漏了新键；空状态只有 `No data`，不给下一步。
- 首次运行就覆盖用户已有配置，或把默认值当作用户选择写进文件。
- 在非 TTY/CI 里输出彩色的欢迎语，污染 stdout；用示例数据演示，用户误以为那是自己的真实数据。

## 七、激活自检

- 老用户第二次启动时，屏幕上有没有任何一处多余的引导文本？
- 新用户从启动到完成第一件真实的事，中间隔了几步？哪一步能砍？
- 每个空状态是否都带一个具体按键或命令？
- `?` 与实现键位是否同源，`?` 里能否退出？
- 首次运行的配置写入是否可预测、可回退、不覆盖现有文件？
- 非交互环境下引导是否完全不出现，stdout 是否仍然干净？
- 引导是否可跳过、可重读、不会重复出现？
