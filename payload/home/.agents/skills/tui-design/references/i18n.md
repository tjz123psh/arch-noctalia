# TUI 国际化与字符宽度

终端里的本地化不是"翻译字符串"，而是**列对齐能在任何字符集下成立**。CJK 占两列、Emoji 宽度不统一、RTL 需要隔离符——这些会让表格错位、边框断裂、光标偏移，是最常见的终端本地化故障。

**触发时机**：界面要支持多语言、要处理 CJK 或 Emoji 输入、要排查表格错位与边框断裂、或要在 60/80 列下验证翻译文本时读本篇。宽度预算的**具体数值**在 `copy.md`，locale 环境变量的**失败回退**在 `resilience.md`，本篇讲模型与算法。

## 字符宽度模型

终端坐标是"列"，不是字符。一个码点可能占 0、1、2 列：

| 类别 | 列宽 | 例子 |
|---|---|---|
| 零宽 | 0 | 组合附加符（U+0301）、零宽连接符（U+200D）、变体选择符 |
| ASCII / 半角 | 1 | `a`、`1`、半角标点 |
| 东亚宽 / 全角 | 2 | 汉字、日文假名、谚文、全角标点（，。！） |
| Emoji | 1 或 2 | 取决于终端与 `wcwidth` 实现，同一字符可能不一致 |

**规则**：所有列对齐计算必须走显示宽度（`wcwidth`/`wcswidth` 等价实现），**不要用 `len()`、`.length`、字节数或码点数**。库通常提供：Rust `unicode-width`、Python `unicodedata.east_asian_width`、Go `go-runewidth`、JS `string-width`。

**对齐失败的症状**：中文表格逐行右移；边框在混排行后错位；光标停在错误列；进度条长度抖动。看到这些先查宽度计算，不要先调 CSS 式的"补偿空格"。

## 字素簇截断

按码点截断会切出半个字符或替换符（`�`）。正确做法是按**字素簇**（grapheme cluster）切：

```text
错误：name[:6]              → 可能切在组合符中间
正确：按字素簇取前 6 个，再检查显示宽度是否超列宽
```

组合序列尤其危险：`é` 可能是 `e` + U+0301 两个码点；家庭 Emoji 由多个码点加零宽连接符组成。**宽度加起来是 2，码点数可能是 7。**

截断后必须保留可获取完整值的路径（`title`、详情视图、`--json` 输出），并且截断标记本身要占位（`…` 通常 1 列，中文场景可用 `…` 或 `...` 显式选择）。

## 折行与无空格语言

CJK 没有空格，按空格断词的折行算法会失败。要点：

- 断行点可以是任意字素簇边界（CJK 允许行内断开），但**不能**把行首标点留到行尾（避免「。」开头），也不能把组合字符拆开。
- 混排时按"词内不断（拉丁） + 字间可断（CJK）"处理。
- 数值与单位、数字与百分号、`Ctrl+K` 这类键位组合视为不可断的整体。
- 硬折行要保证不丢失字素簇，宁可某行短一点。

## RTL 与双向文本

终端对 bidi 的支持差异很大，**不要依赖终端自动镜像**：

| 场景 | 做法 |
|---|---|
| 纯 RTL 内容 | 用 Unicode 隔离符包裹（U+2067 RLI … U+2069 PDI），或 U+202B RLE … U+202C PDF；先在一行内验证再铺开 |
| RTL 与拉丁混排 | 显式隔离，否则显示顺序取决于终端实现，无法预测 |
| 方向性符号（箭头、返回） | 改用镜像符号或文字（`←` 在 RTL 语境可能被重排） |
| 进度条、对齐的数值列 | 保持 LTR 内嵌，不要随段落方向翻转 |
| 终端不支持 bidi | 降级为"每行单独隔离 + 不做整体重排"，并在文档里写明限制 |

**验证方式**：用伪本地化（`~/.agents/skills/_shared/scripts/pseudoloc.py --mode rtl`）把界面字符串转成"加长 + 强制 RTL"，立刻暴露未镜像的布局与硬编码的左右位置。

## 本地化格式

数值与日期**不要手写拼接**：

```text
日期：Intl.DateTimeFormat / strftime，按 locale 取格式
数字：Intl.NumberFormat（千分位、小数分隔符）
货币：Intl.NumberFormat({style:'currency'})，注意符号位置
时区：显式显示或用 ISO 8601，不要用本地"昨天/3 小时前"作为唯一信息
```

**终端特有的取舍**：可被脚本解析的输出优先 **ISO 8601 与固定小数分隔符**（`.`），与界面显示分开——同一程序可以 `--json` 给机器、默认给人类（见 `resilience.md` 第九节）。

日历与数字系统：非公历、非阿拉伯数字（如天城文数字）在终端宽度上是 1 列，但排序与显示顺序需按 locale；不确定时给 ISO 回退。

## 翻译与文本膨胀

德语通常比英语长 30%，日文可能更长，中文更短——**按最宽语种定列宽预算**，不要按英文估。

- 固定列宽（表格列、状态行分段）必须按最长语言的真实翻译验证，不是按英文长度加个余量。
- 术语与快捷键提示也要本地化：`Save` / `保存`，但 `Ctrl+S` 保持不变。
- 不在翻译字符串里拼接句子片段（语序不同），用完整句模板加占位符。
- 标点宽度变化：英文逗号 1 列、中文逗号 2 列，混排时预算按 2 列算。

伪本地化是投产前的低成本验证：`pseudoloc.py` 支持 accent（加长 + 标记边界，暴露截断与硬编码）、rtl（强制 RTL，暴露未镜像）两种模式，接受任意文本、文件或 JSON，零依赖。

## 验收

在同一份界面文本上跑矩阵：

| 维度 | 取值 |
|---|---|
| 列宽 | 60、80、120 |
| 字符集 | ASCII、CJK、Emoji、组合字符 |
| 方向 | LTR、RTL、混排（用 pseudoloc 生成） |
| 语言长度 | 最短（中文）、最长（日文/德文）、真实翻译 |
| locale | 正常 UTF-8、`LC_ALL=C`、缺 `LANG` |

必查项：

- 表格边框在 CJK 混排行后不位移。
- 中文标题与长翻译在 60 列下不撑破、不重叠、不截出半个字。
- 进度条、对齐数值在 RTL 下位置正确。
- `LC_ALL=C` 时不崩溃、有 ASCII 回退、关键状态仍可辨。
- `--json` 输出的数字与日期是 ISO 形式，与界面显示解耦。

## 自检

- 所有列计算是否都走显示宽度，没有一处用 `len()` 或字节数？
- 截断是否按字素簇，且提供完整值路径？
- RTL 是否显式隔离，而不是假设终端会自动处理？
- 日期与数字是否走 locale API，且脚本输出有 ISO 回退？
- 列宽预算是否按最宽语种验证过，而不是按英文估？
- `LC_ALL=C` 与缺 `LANG` 时是否仍可用？
- 是否用伪本地化验证过截断、硬编码与未镜像的布局？
