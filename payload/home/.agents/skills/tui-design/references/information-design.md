# TUI 信息设计参考

把终端画布当作字符网格与操作工作台，不是缩小版网页。先决定用户要读什么、比较什么、定位什么、改什么，再选布局。

## 选择问题（按顺序问）

1. 用户在比较同类记录？→ 表格或对齐列表。
2. 用户在导航祖先层级？→ 树、Miller 列或下钻。
3. 两个上下文必须在操作时同时可见？→ 主/详情分栏。
4. 任务是一次性的？→ 覆盖层或命令面板。
5. 内容是连续的？→ 文档、diff、时间线或日志视口。
6. 信号相互独立且同等重要？→ 只有此时才用仪表盘网格。

## 工作流

1. 写出单一首要任务、最常用动作、错误代价。
2. 标注数据形态：集合、层级、序列、日志流、文档、指标、主从关系。
3. 按关系选表示法，不按对容器的审美偏好选。
4. 为紧凑、标准、宽三种终端宽度画 ASCII 线框图。
5. 为加载、空、无权限、断连、错误、部分成功设计固定位置。
6. 删除所有无助于扫视、比较、定位、行动的分隔线、标题与装饰。

## 空间分配

- 首要任务占最大连续区域；辅助信息按使用频率分配。
- 保持稳定的空间记忆：列表、详情、状态、帮助在常规更新中不应跳动。
- 只有区域需要独立滚动、调整大小或显式焦点时才用边框。
- 优先用对齐、缩进、空行、颜色、文本属性做分组。
- 宽屏增加有用的并行上下文，不是拉伸文本或重复统计。
- 窄屏保住任务链；把次要面板转成视图、抽屉或覆盖层。

## 信息层级

每个视图最多四级视觉优先级：

1. 当前对象与主要状态。
2. 当前可用动作。
3. 比较或决策所需内容。
4. 说明、元数据、快捷键提示。

不要让品牌 ASCII 图、边框标题或装饰符号的层级高于当前任务。

## 设计交付物

至少包含：内容模型与首要任务；选定的布局语法与被舍弃形态的理由；60–79、80–119、120+ 列宽的线框图；主视图之外的空/错误/加载/帮助状态；每个区域的滚动、焦点与截断策略。

## 宽度变换

| 宽 | 标准 | 紧凑 |
|---|---|---|
| 主 + 详情 + 上下文 | 主 + 有限详情 | 主；详情转为视图 |
| Miller 列 | 双列 | 下钻栈 |
| 全表格 | 隐藏低价值列 | 标签/值行或横向分页 |
| 常驻帮助 | footer 提示 | `?` 帮助覆盖层 |

变换过程中不得静默移除主要动作或状态。
