# TUI 表单与输入参考

终端表单的核心约束：**没有鼠标、没有 tooltip、没有自动填充**。所有反馈必须落在字符网格内的固定位置，且纯键盘可达。

## 字段布局

| 表单规模 | 布局 | 校验时机 |
|---|---|---|
| 1–3 字段（登录式） | 单列，标签左对齐或上置 | 提交时 |
| 4–8 字段（配置式） | 单列分组，组间空行 | onBlur（离开字段） |
| 9–15 字段 | 分组 + 可折叠小节 | 每段 onBlur + 提交 |
| 15+ 字段 | 多步向导 + 进度指示 | 每步提交 |

标签与输入框用邻近律绑定：标签紧贴其值，与下一个字段的间距明显更大。终端里用对齐的标签列（`Status   degraded`）比现代 UI 的浮动标签更易扫视。

## 校验时机

1. **首次交互（onBlur）**：用户离开字段后校验格式（路径、URL、数字范围）。不要在每个按键上校验——终端重绘成本高，且会打断输入。
2. **字段已有错误后**：切到逐键校验，用户修正时立即看到错误消失。
3. **提交时**：校验全部字段，焦点移到第一个错误，状态行显示 `3 errors` 之类的计数。
4. **异步校验**（如路径是否存在）：显示 `checking…` 状态，防抖合并，用户继续输入时取消旧检查。
5. **未触达字段**：提交前不报错，不要闪。

## 错误呈现

终端没有 tooltip，错误必须内联或落在固定位置：

| 错误类型 | 位置 |
|---|---|
| 字段级 | 字段下方一行，前缀标记（`✗` 或 `ERROR`），缩进对齐该字段 |
| 摘要 | 表单上方或状态行，每项对应字段序号，可用按键跳转 |
| 系统级 | 状态行或覆盖层（网络失败、权限不足） |

错误消息写作：写具体条件与后果，不写"输入无效"。

```
✗ retry-limit 必须是 1–10 之间的整数，当前值 99
```

不要只靠颜色标错：用符号前缀 + 文字，并确保 `NO_COLOR` 下仍可辨识。

## 输入控件

| 需求 | 终端做法 | 避免 |
|---|---|---|
| 单行文本 | 内联编辑，`Enter` 确认 `Esc` 取消 | 每次都开新对话框 |
| 多行文本 | 明确的行编辑模式，显示行号与 `-- INSERT --` 式模式提示 | 复用单行控件 |
| 布尔开关 | `[x]` / `[ ]` 或 `on`/`off` 文本 | 只靠颜色区分 |
| 枚举选择 | 循环切换（`←/→`）或 picker 覆盖层 | 让用户手输合法值 |
| 数值 | 支持 `+/-` 步进与直接输入，显示范围 | 只接受裸输入 |
| 路径 | 提供补全（`Tab`）+ 存在性校验 | 要求盲打完整路径 |
| 敏感输入 | 掩码显示，明确提示不回显 | 明文回显 |
| 多选 | `[x]` 清单 + 范围选 + 全选/反选 | 只能逐项切换 |

## 编辑模式约定

- **模式可见**：在固定位置（通常底部状态行）显示当前模式，`-- INSERT --` / `-- NORMAL --` 之类。
- **退出确定**：`Esc` 永远退出编辑；`Esc`/`Left` 返回上层视图；应用退出用显式命令。
- **文本输入不劫持快捷键**：插入态下 `j/k/q` 是普通字符。
- **焦点与选中分离**：焦点指"按键去哪"，选中指"哪个对象被作用"，视觉上必须可区分。
- **危险操作**：单字符删除不可逆前必须确认，并在确认里写出具体对象名与动词。

## 多步与长任务

- 进度用 `步骤 2/5` 或计数而非百分比估算。
- 每步可返回上一步；已填内容保留。
- 取消要区分"已请求取消"与"已停止"。
- 异步提交期间显示阶段（`uploading`、`verifying`），不要只转 spinner。

## 无障碍与降级

- 纯键盘完成全部输入路径；鼠标只是增强。
- 错误、必填、当前焦点在 `NO_COLOR`、16 色、无 Unicode 下都要可辨识。
- 非 TTY 场景（管道、脚本）提供非交互输出或明确报错，不要挂起等输入。
- 屏幕阅读器场景下，状态变化要有文本表达而非仅视觉变化。

## 表单自检

- 每个字段的错误位置固定、可达、带文字而非仅颜色？
- 提交失败后焦点是否落在第一个错误？
- 是否保留了用户已填内容？
- 提交按钮措辞是否具体（`创建账户` 而非 `提交`）？
- 插入态下快捷键是否失效、`Esc` 是否总能退出？
- 长表单是否有进度与返回路径？
