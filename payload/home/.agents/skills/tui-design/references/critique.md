# TUI 逐屏评审参考

对一个已实现的终端界面做结构化评审。目标是把"感觉不对"翻译成具体、可执行的修复项。

## 评审前

- 拿到真实截图或录屏，不是描述。终端场景要覆盖多个宽度与颜色能力（见 `validation.md` 的矩阵）。
- 明确本次评审的切面（见下），不要一次评所有维度。
- 区分"事实"（可观察）与"主张"（需要判断）。视觉判断与行为证据分开写。

## 评审切面

按需选择一个或几个切面，每个切面独立给结论。

| 切面 | 看什么 |
|---|---|
| **层次** | 首要任务是否第一视觉优先级；有无四级以上优先级 |
| **密度** | 信息密度是否匹配任务；过疏（仪表盘常见默认错误）或过密 |
| **构图** | 空间分配是否反映内容关系；有无无用边框、重复标题、卡片墙 |
| **对齐与节奏** | 列是否稳定对齐；区块间距是否成刻度；数字/时间戳宽度是否稳定 |
| **可供性** | 可操作项是否看起来可操作；焦点与选中是否可区分 |
| **状态完整** | 默认/加载/空/错误/禁用/成功是否都有表达 |
| **降级** | 无颜色、16 色、无 Unicode、窄宽度下是否仍可用 |
| **文案** | 是否写具体对象与动作；错误消息是否说清条件与后果 |
| **首次体验** | 老用户是否被重复引导；空状态是否给出下一步；帮助是否可发现 |
| **环境韧性** | 非 TTY、断连、能力探测失败、被 kill 后的行为是否可接受 |

### 每个切面的判定问题

单列一栏"看什么"不够，评审时逐条问：

| 切面 | 判定问题（答不上来即为缺陷） |
|---|---|
| 层次 | 遮住颜色后，能否只靠位置与符号指出首要任务？一屏里有几个元素在争第一？ |
| 密度 | 一屏能同时比较多少条记录？为完成主任务需要滚动几次？ |
| 构图 | 每条分隔线/边框是否对应一个真实的区域边界？删掉它结构是否仍然清楚？ |
| 对齐与节奏 | 数字与时间戳是否右对齐且宽度固定？区块间距是否只有两三种取值？ |
| 可供性 | 当前焦点在哪、按 Enter 会发生什么，是否不试就能说出？ |
| 状态完整 | 空/错误/加载/禁用四种状态是否都能在真实数据下看到，而不只是代码里有？ |
| 降级 | `NO_COLOR=1` 与 16 色下，错误、选中、进度是否仍可辨识？ |
| 文案 | 错误消息里是否有能立刻按下的键？同一动作是否全文同名？ |
| 首次体验 | 第二次启动时是否还有多余引导？每个空状态是否带一个具体按键？ |
| 环境韧性 | 管道、断连、`Ctrl-Z`、`kill -9` 之后是否留下坏终端或挂起？ |

## 输出格式

每个问题写成三行，不要只给形容词：

```text
[切面] 观察：<在哪个界面/宽度/颜色档下看到了什么>
       问题：<它让用户无法完成什么，或误读了什么>
       修复：<具体到可执行的改动>
```

示例：

```text
[构图] 观察：80 列下，日志面板与状态面板都用了边框，边框比内容更醒目
       问题：用户扫视时先看到框线，日志正文反而退到第二层
       修复：去掉状态面板边框，改用一行空行 + 反显标题分组
```

## 评审立场

- **不把风格偏好当缺陷**。评审聚焦"是否妨碍理解/完成/辨错"，不是"我更喜欢另一种"。
- **每条问题必须能指向一个真实用户的损失**：读错、找不到、重复操作、无法恢复。
- **区分严重度**：阻断主任务 > 造成误操作 > 增加认知负担 > 纯美观。前者必修，后者可选。
- **不要一次列二十条**。挑当前风险档下最关键的几条，其余列入观察项。
- **承认未覆盖**：没测的宽度、颜色档、输入方式要明确写出来，不要用沉默当通过。

## 与验收的分工

- **本文件只做视觉与设计判断**：层次、构图、密度、语气、可供性、首次体验。
- **行为证据归 `validation.md`**：功能路径、状态转移、终端卫生、性能。
- **设计侧的加固要求归 `resilience.md`**：非 TTY、断连、能力探测失败、清理顺序；评审时只判断"是否可接受"，取证仍在 `validation.md`。
- 不要把两者混成一张重复清单，也不要用功能通过替代视觉通过——功能全对但层次崩塌，仍然是不合格。

## 常见终端专属缺陷

- 边框套边框，两级以上嵌套。
- 每条记录一个盒子，导致一屏看不完几条。
- 窄屏只是把面板纵向堆叠，没有重构信息优先级。
- 表格列按顺序丢弃最后一列，而不是按价值降级。
- 关键状态只靠颜色（红色 = 错），无符号或文字。
- 长内容截断后无法访问完整值。
- 内容刷新导致布局跳动，破坏空间记忆。
- 状态行提示与实际可用按键不一致。
- 空状态是空白或 `No items`，没有下一步动作。
- 每次启动都打横幅/引导，老用户要按一次键才能开始工作。
- 错误消息只报错误码或内部术语，不给可按的键或命令。
- 进度用无依据的百分比，或三个异步阶段长得一模一样。
- 宽度改变时字段位置重排，光标/选中跟着丢。
- 在非 TTY 或被管道连接时仍试图进全屏、等按键。

## 评审记录表

每条问题按此表填，便于跨轮比较与销项：

```text
ID      切面      位置（视图/宽度/颜色档）   严重度   观察 → 问题 → 修复     状态（待修/已修/观察项）
C-01    构图      日志视图 / 80 列 / 16 色  major    双层面板边框压过正文 → 扫视时先看框线 → 去掉状态面板边框  待修
```

- 严重度只取四档：`blocker`（阻断主任务）/ `major`（造成误操作）/ `minor`（增加认知负担）/ `polish`（美观）。
- 修完一轮后**重跑同一批证据**（相同宽度与颜色档），在表里更新状态，不要只写"已修复"。
- 观察项（未纳入本轮的问题）保留在表里并注明未纳入原因，下一轮再排优先级。
