# TUI 视觉系统参考

用一小组可降级的语义 token 建立层级。终端的美感来自节奏、对齐与状态清晰度，不是更多颜色和边框。

## 建立 token

至少定义：

```text
text.primary       text.muted        text.emphasis
surface.base       surface.raised    surface.selected
accent.primary     focus.ring
status.success     status.warning    status.error    status.info
border.subtle      border.strong
```

组件只引用语义 token，绝不散落原始 RGB/ANSI 数字。

## 降级顺序

1. **TrueColor**：品牌色与细粒度层级。
2. **256 色**：保留语义差异。
3. **16 色**：状态与对比仍然成立。
4. **单色/`NO_COLOR`**：用文本、符号、粗体、反显、位置表达。

颜色绝不能是错误、选中、进度或可操作性的唯一线索。

## 层级工具优先级

1. 空间与对齐。
2. 文案与符号。
3. 粗体、暗色、下划线、反显。
4. 前景色。
5. 背景色。
6. 边框与装饰。

如果必须依赖第 5–6 项才能看懂结构，先重做信息架构。

## 边框规则

使用边框的有效理由：

- 区域独立滚动或可调整大小。
- 覆盖层需要与底层分离。
- 高密度画布中焦点区域必须显式。
- 两个相邻区域内容同质，仅靠留白不足以分隔。

不要给每个标题、统计、按钮、列表项都加框。嵌套边框尽量不超过两层。

## 文本与符号

- 默认支持 ASCII；Unicode 图标必须有等宽与缺字回退。
- 关键状态同时用词语，例如 `FAILED`、`PAUSED`、`3/8`。
- 避免用 emoji 当稳定图标；不同终端可能渲染成双宽或彩色。
- 截断要保留可识别部分，并提供访问完整值的方式。
- 数字按小数点或单位对齐；时间戳与 ID 用稳定宽度。

## 节奏

- 主要区块之间用一行空行，不要每行都空。
- 密集控件内部用单字符间距，同级组之间用双字符间距。
- 同一视图内标签对齐；不要跨无关区域强制全局对齐。
- footer 提示视觉上比内容更安静，但仍需可读。

## Focus、选中与状态

至少区分：normal、hover/鼠标、focus、selected、disabled、busy、error。

| 状态 | 必需的非颜色线索 | 可选颜色线索 |
|---|---|---|
| Focused | `>` 标记、下划线或强边框 | accent |
| Selected | 复选框、圆点或反显文本 | selected 背景 |
| Disabled | 明确原因或禁用标签 | 暗前景 |
| Loading | 阶段文本与进度/计数 | info accent |
| Success | `OK` 或勾选字形 | 绿色系 |
| Warning | `WARN` 或警告字形 | 黄色系 |
| Error | `ERROR` 与恢复文本 | 红色系 |

- 焦点优先用前缀、反显或明确边框。
- 多选使用勾选/标记，而不只是背景色变化。
- 禁用项保持可读，并解释为何不可用。
- 警告与错误不得共用同一档红色。

## 对比审查

在两种用户可控的终端背景上测试文本。不要假设"默认"就是深色。基础层优先用终端默认前景/背景，显式颜色只留给语义强调。

## 视觉验收

在这些环境下验证截图或录屏：

- 16 色、256 色、TrueColor。
- 深色与浅色终端背景。
- `NO_COLOR=1`。
- ASCII-only 与 Unicode。
- 窗口聚焦与失焦。
- 60、80、120、160 列。

如果无颜色时层级完全消失，说明视觉系统不合格。
