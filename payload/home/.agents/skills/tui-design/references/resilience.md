# TUI 韧性：非交互环境、断连与故障降级

何时读本篇：构建或改造 TUI，需要它在非 TTY、SSH/tmux、能力受限、进程被杀、输出洪流、磁盘与配置异常下仍可用时读。本篇是设计侧行为要求；终端卫生的四路径检查清单与取证矩阵在 `references/validation.md`，不在此重复。

终端程序不是"总有人坐在面前的整屏应用"。同一个二进制会跑在管道、cron、CI、掉线的 SSH、被 `kill -9` 的窗口里。这些是常态输入，不是异常。

## 一、先判定运行环境

进入 alternate screen 之前探测一次，结果缓存整个生命周期，不要每帧重查。

| 探测 | 方法 | 失败/缺失时的行为 |
|---|---|---|
| 交互输入 | `isatty(0)`（shell：`[ -t 0 ]`） | 不进入交互模式，不读 stdin |
| 屏幕输出 | `isatty(1)` | 禁用 alt screen、光标控制与动画 |
| 尺寸 | `ioctl(TIOCGWINSZ)` | 回退 80×24，并 clamp 到 20–500 列 / 10–200 行 |
| 颜色档 | terminfo `colors`、`RGB`、`COLORTERM` | 按 16 色处理（最保守的可用档） |
| 字符集 | `LC_ALL`/`LC_CTYPE`/`LANG` 含 `UTF-8` | 回退 ASCII 符号集 |

`NO_COLOR` 只要非空就禁用颜色，`FORCE_COLOR`/`CLICOLOR_FORCE` 可反向覆盖；冲突时以显式参数（`--color=always|never`）为准。探测结果要允许配置与参数覆盖，不要只信环境。

## 二、非 TTY、管道与重定向

| 场景 | 判定 | 要求 |
|---|---|---|
| `app > file` | stdout 非 TTY，stdin 是 | 不进入 alt screen；不输出光标/清屏序列；按行输出结果 |
| `app < /dev/null`、cron、CI | stdin 非 TTY | 绝不阻塞等按键；缺参数就报错并打印用法，退出码 ≠ 0 |
| `app \| head`、管道 | 两端之一非 TTY | 处理 `SIGPIPE`/`EPIPE`（被 `head` 关闭管道时安静退出，不退化成 core dump） |
| 完全非交互 | 两者都非 TTY | 走 `--json`/`--quiet`/`--yes` 等非交互开关，输出机器可解析 |

- **进度与动画只写 stderr**。stdout 留给数据，`app list | jq` 不能被进度条污染。
- 交互模式要求输入时，非 TTY 下给出可执行替代：`非交互环境，请用 --yes 或 --force`，并**提示具体命令**，而不是挂起。
- 退出码语义固定：`0` 成功、`1` 运行错误、`2` 用法错误、`130/143` 被信号终止；错误信息进 stderr。
- `TERM` 为空或 `dumb` 时按纯文本处理：不输出任何 ANSI 序列，退化成分行报告仍然成立。

## 三、断连、复用器与迟滞网络

| 情境 | 表现 | 设计要求 |
|---|---|---|
| SSH 断连 | 收到 `SIGHUP`，写端变 `EIO`/`EPIPE` | 捕获 `SIGHUP` 走清理路径；`$TMUX`/`$STY`/`$TERM_PROGRAM` 存在时按复用器限制处理鼠标、剪贴板与真彩 |
| tmux/screen 分离 | 应用继续跑，输出进被复用器的缓冲 | 不在分离期间无限刷屏；重连后按当前状态整体重绘一次 |
| 高延迟（RTT 100ms+） | 逐格刷新肉眼可见 | 一帧一次缓冲写；不做逐字符打字机效果；帧率 10–30fps 足够 |
| 写阻塞 | socket 写满，缓冲不排空 | 非阻塞写 + 有界队列；积压时**丢旧帧保最新帧**，绝不让 UI 停转 |
| 迟滞网络 | 探测/请求慢 | 用单调时钟做超时；超时后给状态文本与取消键，不要无限 spinner |
| 复用器限制 | `screen`/`tmux` 可能不透传真彩与 OSC | 依赖 terminfo 档位而非 `$TERM` 字面猜测；剪贴板用 OSC 52 时必须有回退（打印值让用户复制） |

复用器下的鼠标与滚轮可能被复用器截获；应用启用鼠标捕获后要告知用户可用 `Shift` 绕过选择，且**所有鼠标动作都要有键盘等价路径**（见 `interaction.md`）。

## 四、能力探测失败与降级

- **尺寸未知**：先 `TIOCGWINSZ`，其次 `$LINES`/`$COLUMNS`（用户可能在 shell 里设成错值，只作兜底），最后 80×24。某些 pty 初始返回 0×0，等第一次 `SIGWINCH` 后再重排。
- **色彩未知**：按 16 色布局；语义差异用文本与符号承担（见 `visual-system.md` 的层级工具优先级）。真彩支持无法可靠探测时，宁可少用色。
- **Unicode 不可用**：ASCII 回退符号集必须**等宽且确定**：`[x]`/`[ ]`、`>`、`-`、`+`、`!`。不要用 emoji 或装饰性方块作为唯一状态线索。
- **宽字符/组合字符与截断**：按显示宽度而非字节或字符数计算，按字素簇截断（否则会切出半个字符或替换符）；缺字形时终端常渲染成空白或问号，关键标记不要依赖单个罕见字形。
- 降级必须**一次到位**：运行中不再改档，避免同一会话里符号集闪烁。

## 五、信号与清理顺序

清理只在事件循环里做：信号处理器只置标志（async-signal-safe），不要在里面分配、打印、`exit()`。

| 信号 | 触发 | 处理 |
|---|---|---|
| `SIGINT` | `Ctrl-C` | 中断当前操作或退出；先取消子进程/请求 |
| `SIGTERM` | 外部停止（容器、systemd） | 与 `SIGINT` 同路径，退出码 143 |
| `SIGHUP` | 终端/SSH 断开 | 同路径；不再依赖后续输出可见 |
| `SIGQUIT` | `Ctrl-\` | 允许核心转储前也尽量恢复终端 |
| `SIGTSTP`/`SIGCONT` | `Ctrl-Z`/`fg` | 挂起前恢复终端，恢复后重新进入（见下） |
| `SIGWINCH` | 尺寸变化 | 防抖 16–50ms 合并，重排一次而不是每事件一次 |
| `SIGPIPE` | 下游关闭管道 | 忽略并改为处理写错误 `EPIPE` |

退出清理**顺序**（顺序错了会留下坏终端）：

1. 停止读取输入与渲染定时器，取消未完成的后台任务。
2. **先恢复 termios**（`ICANON`/`ECHO`/`ISIG`/`IEXTEN`/`IXON`/`ICRNL`/**`OPOST`**）。raw mode 关掉了 `OPOST`，此时打印换行会阶梯状错行——所以恢复必须早于写退出摘要，或显式写 `\r\n`。
3. 退出 alternate screen（`rmcup`，xterm 系为 `\e[?1049l`）。
4. 释放鼠标捕获（`\e[?1000l\e[?1002l\e[?1003l\e[?1006l`）。
5. 恢复光标可见与形状（`cnorm`，`\e[?25h`；若改过 `DECSCUSR` 也要还原）。
6. 恢复键盘模式（`rmkx`）与应用键区；清掉 bracketed paste（`\e[?2004l`）。
7. 写完退出摘要与退出码（被信号终止按 128+signum 报告）。

`Ctrl-Z` 挂起走同一条链：挂起前做 2–6 步，`SIGCONT` 后重新探测尺寸与能力并整体重绘。

宁可清理函数幂等（重复调用无副作用），也不要依赖"只会在退出时跑一次"。异常路径（panic/未捕获错误）必须挂同一个清理钩子，见 `references/frameworks.md` 的框架级错误恢复工具。

## 六、被 `SIGKILL` 之后的残留

`kill -9` 不给清理机会，终端会停在 raw mode + 无回显 + 隐藏光标的状态。程序无法自救，只能给用户恢复路径：

- 退出后 shell 输入不回显 / 无换行 → 运行 `reset`（`tput reset` 亦可）。
- 只剩光标不可见或残留鼠标捕获 → `printf '\e[?25h\e[?1000l\e[?1002l\e[?1003l\e[?1006l'`。
- 屏幕内容错乱但输入正常 → `clear`（若仍在 alt screen 需先 `tput rmcup`）；在 tmux 内可用 `tmux send-keys -R` 重置该 pane 状态，无需 kill 会话。
- 把这段恢复指引写进 README 排错节与崩溃日志尾部，用户才能在坏掉的状态下**读到**它（崩溃日志落文件，不要只打到已被弄坏的屏幕）。

设计上减少残留面：只开启必需的能力（不无谓地开鼠标捕获、不开 bracketed paste、不改光标形状）；能不用 alt screen 就不用。

## 七、输出洪流与背压

- 输入永远优先：任何渲染策略都不能让按键延迟；高频更新按 100ms 窗口合并。
- 日志洪流用**环形缓冲**保留最近 N 条（如 10k），并显式显示丢弃量（`dropped 1234`），绝不静默截断。
- 明确丢弃策略：保最新、保每类首条、按级别取样（错误全留，调试丢弃），并让用户可切换"暂停滚动/跟随"。
- 超大单条（几 MB 的一行 JSON／日志）要分块或折叠渲染，不要试图一帧画进网格。
- 落盘写入用追加 + 定期 flush；写盘失败不得让 UI 崩，降级为仅内存并提示。
- 背压传导：下游（管道、日志文件、远端 socket）不排空时主动丢帧并降低刷新频率，而不是自旋重试。

## 八、存储、权限与配置损坏

| 故障 | 行为 |
|---|---|
| `ENOSPC`（磁盘满） | 明确告知且**保住已有数据**；不静默截断，必要时转只读模式 |
| `EACCES`/`EROFS`（无权限、只读） | 降级为内存态继续主任务，警告一次（不刷屏），给出可写路径建议 |
| 配置文件解析失败 | 不改写原文件；报告行号与期望格式；用默认值继续并提供 `--config` 指向修复版 |
| 配置已有未知字段 | 保留不删，只在显式 `schema upgrade` 时迁移 |
| 目录不存在 | 只创建本应用自己的目录（权限 `0700`）；不递归创建可疑路径 |
| 已存在实例/锁文件 | 报出 PID 与命令，提示如何接管，不静默覆盖 |
| 敏感文件（token、凭据） | 权限 `0600`；不落日志、不进崩溃报告 |

写入一律**原子**：写临时文件 → `fsync` → `rename`，崩溃不会留下半截配置。

## 九、时钟、locale 与环境变量

- **超时、节流、耗时统计用单调时钟**；墙上时钟只用于显示，DST 回拨不能让"耗时"变负数。时间以 UTC 存储、按本地时区渲染，并显示时区（`14:03:12+08:00` 或 `Z`）；不假设 `$TZ` 正确或存在。
- locale 缺失（`LANG` 为空/`C`）时不要依赖本地化格式：数字与日期回退 ISO 8601，便于脚本解析；输出编码固定 UTF-8，不按 locale 转码。

| 变量 | 风险 | 处理 |
|---|---|---|
| `LINES`/`COLUMNS` | 陈旧或手设错值 | 只作兜底，且 clamp |
| `TERM=dumb`、`NO_COLOR` | 能力或偏好声明 | 按其降级，不覆盖 |
| `CI`、`SSH_TTY`、`TMUX`、`STY` | 环境提示 | 用于决定是否打扰用户（见 `onboarding.md`） |
| `PAGER`/`EDITOR`/`VISUAL` | 可能被指向任何程序 | 只在交互且经校验后调用，失败给回退 |
| `LC_*` / 无前缀的自定义变量 | 宽度与排序依赖 locale；命名冲突 | 宽度按码点/字素计算，不依赖 locale；本程序变量统一加应用前缀 |

## 十、韧性自检

- 非 TTY、管道、`/dev/null`、CI 四种形态下是否都能非交互完成或明确报错，而不是挂起？
- 断连、`Ctrl-Z`、`kill -9` 之后用户是否有可执行的恢复路径，且指引写在能读到的地方？
- `SIGINT`/`SIGTERM`/`SIGHUP`/panic 四条退出路径是否都经过同一个幂等清理链，且顺序正确？
- 尺寸/颜色/字符集探测失败时是否仍有可用界面，而不是崩或空白？
- 每秒上万条日志时输入是否仍然跟手，丢弃量是否可见？
- 磁盘满、配置损坏、无写权限时是否降级而非崩溃，且不损坏用户已有数据？
- 非 TTY 时 stdout 是否仍可被 `jq`/`grep` 直接消费？
