# TUI 文案与措辞

何时读本篇：写终端界面里的任何文字——标签、状态行、错误消息、确认提示、空状态、进度描述、键位提示——时读。呈现方式（符号、颜色、层级、对齐）归 `visual-system.md`，键位分配与状态机归 `interaction.md`；本篇只管文字内容本身。

终端文案与网页的差别：没有 hover、没有 tooltip，宽度按字符计且常只有 80 列，用户在键盘流里扫一眼就要做决定——所以每句都必须当场可读、可执行。

## 一、宽度预算：按显示宽度算

CJK 与全角标点占 2 列，ASCII 占 1 列；80 列 ≈ **40 个汉字**或 **80 个 ASCII**，混排折半累加（8 汉字 + 64 ASCII）。

| 位置 | 预算（80 列终端） | 约束 |
|---|---|---|
| 状态行整行 | ≤78 列 | 两侧各留 1 列，防自动换行 |
| 单条状态消息 | ≤40 列 | 其余位置留给计数器、模式、时间 |
| 键位提示项 / footer 总宽 | ≤16 列 / ≤76 列 | 「键 + 动词」两词式；超出砍项，不砍字 |
| 表格单元格 / 错误消息 | 按列宽定死 / ≤100 列 | 按字素簇截断并给完整值路径；错误可到第二行 |

- 预算按**最宽语种**（常是日文）定，别按英文估（中文通常比英文短 30–50%）；用最长真实值（超长路径、长主机名、CJK 项目名）验证不换行、不撑破边框。截断保留可识别部分（`…/long/path/config.toml` 优于 `…/long/pat`）。

## 二、诊断表：终端版

| 病灶 | 终端表现 | 改法 |
|---|---|---|
| 术语 | `Webhook 配置实体写入失败` | 用用户的语言：`通知设置保存失败` |
| 泛泛的错误 | `出错了`、`Invalid input` | 说清**对象 + 原因 + 下一步按键/命令** |
| 被动语态 | `文件已被删除` | `已删除 deploy-api.yaml`（主动 + 具体对象） |
| 报告实现细节 | `EPIPE while writing buffer` | `连接已中断，按 r 重连`；细节留给 `--verbose` |
| 归咎用户 | `你输入了非法值` | `端口需在 1–65535 之间，当前 70000` |
| 自造缩写 / 时间含糊 | `cfg inv.`、`刚刚`、`稍后` | 换短同义词；用 `14:03`、`重试中（第 2/3 次）` |
| 状态无动词 | 单独一个 `pending` | `等待部署`、`正在校验`——说清在等什么 |
| 大小写、标点混乱 | 同屏 `Save`/`save`；`保存成功,共 3 项` | 全大写只作短状态标记；中文文案用中文标点 |

## 三、错误消息：发生什么 → 为什么 → 现在能做什么

- 一次说全三件事，第一行写完，第二行才补细节：`✗ config.toml 第 12 行：timeout 需为正整数，当前 "30s"` / `已用默认值 10s 继续；修复后按 r 重新加载`。
- 消息里必须带能立刻按下的键，因为用户会边读边操作：`✗ 无法连接 api.internal:443（超时 5s）— r 重试 · o 查看日志 · Esc 返回`。
- 能给出确切命令就给：`运行 app login --host api.internal`，不写"请重新登录"；错误码放括号里便于搜日志（`E_TIMEOUT`），但不以码代替人话。
- 不道歉、不抒情、不用感叹号；不复述用户已知的操作。多个错误给汇总与定位（`3 个错误 · Enter 跳到第一个`）。
- 可恢复失败留在状态行不打断键盘流；阻塞失败（无法鉴权、无法启动）走覆盖层或固定位。

## 四、破坏性操作确认

写清**动词 + 具体对象 + 影响范围 + 可逆性**，默认焦点在"取消"侧。

| 写法 | 评价 |
|---|---|
| `确定吗？[y/n]` | 不合格：无对象、无范围、无后果 |
| `删除项目「报表」及其 12 个部署记录？` | 合格：动词 + 对象 + 范围 |
| `删除 3 个分支（不可恢复）。输入前 3 个字符确认：` | 高风险批量：要求打字确认 |
| `已删除 deploy-api.yaml（可在 ~/.trash 恢复）` | 结果消息说明可逆性 |

不可逆用完整动词（`永久删除`），可逆的用轻动词并给撤销路径（`u 撤销`）；批量写出数量与实际项（超 5 项列前 3 项 + `等 N 项`）；要求打字确认时写清输入什么，且 `Esc` 取消不产生副作用。

## 五、状态行与进度

| 内容 | 推荐写法 | 避免 |
|---|---|---|
| 阶段进度 | `部署中 3/8 · 等待 api-3` | `37%`：终端里无法验算，也不稳定 |
| 未知总量 | `已扫描 1,204 个文件…` | 假百分比、来回晃的进度条 |
| 异步状态 | `提交中` → `已请求取消` → `已停止` | 三阶段写成同一个 `Loading…` |
| 后台任务 / 连接 | `后台 2 个任务 · F8 查看`、`重连中（第 2/5 次）` | 静默执行；用颜色圆点表示连接 |
| 模式 / 结果 | `-- FILTER: error_ --`、`已保存 · u 撤销` | 模式只靠光标形状；只显示 `OK` 不说是哪个对象 |

计数用**单调递增总量 + 单位**（`3/8`、`1,204 个文件`、`耗时 12.4s`），不用修辞。状态行字段位置固定，值变化时整行不重排；长任务完成把结果留在原位一行，不弹窗打断。

## 六、键位提示的统一写法

统一语法 `键 动词`，键在前、动词在后、不带句号：`↑↓ 移动  Enter 打开  / 过滤  ? 帮助  q 退出`。

| 规则 | 说明 |
|---|---|
| 一键一含义 | 同一上下文一键只表示一件事；`Esc` 只用于返回/取消 |
| 键名统一 | 固定 `Enter`、`Esc`（不混 `Return`/`Escape`）；方向键写 `↑↓`，ASCII 回退写 `Up/Down`；`Ctrl-R` 与 `^R` 择一 |
| 动作同名 | footer 写 `删除`，确认是 `删除`，结果是 `已删除`；别处不叫 `移除`/`清理` |
| 取舍 | footer 只放当前上下文最重要的 3–5 项；不可用的键不显示，要解释时进 `?`；单字符危险动作用大写并标注（`D 删除`）且执行前确认 |

`?` 里的键位表与 footer 必须同源（由同一个键位注册表生成），否则必然与实现漂移。

## 七、空状态与引导文案

- `还没有项目。按 n 新建，或运行 app import <路径> 导入`——一句现状 + 一个真实动作。
- `没有匹配 "error_" 的条目（0/1,204）。Esc 清除筛选`
- `未配置 API 地址。运行 app config set api.url <URL>` / `当前 token 无 projects:read 权限。授权后按 r 重试`
- 引导只写「怎么动、怎么执行、怎么退」，≤ 1 屏并写明任何键继续；空状态的触发条件与首次运行判定见 `onboarding.md`。

## 八、自检

- 同屏文本在 80 与 40 列下是否都不换行、不裁切，最长真实值也一样？
- 每条错误消息是否都含一个可执行命令或可按的键；破坏性确认是否写出动词、对象名与影响范围？
- 进度是否用计数/阶段而非不可验证的百分比；同一动作在 footer、`?`、确认、结果里是否叫同一个词；中英标点、大小写与键名写法是否全应用一致？
