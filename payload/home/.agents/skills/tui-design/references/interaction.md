# TUI 交互设计参考

让首次使用者能完成任务，让熟练用户能建立肌肉记忆，同时避免隐藏模式与键位冲突。

## 先定义状态机

列出视图状态、焦点区域、选中状态、临时模式。至少区分：

- **Browse**：移动、过滤、打开。
- **Edit**：输入文本或修改字段。
- **Select**：单选、多选、范围选。
- **Transient overlay**：帮助、命令、确认、搜索。
- **Busy**：可取消、不可取消、后台。

不要只实现按键处理；要定义哪些键在哪些状态下有效、如何退出、焦点回到哪里。

## 键位分层

| 层 | 目标 | 示例 |
|---|---|---|
| 通用基线 | 无需记忆即可用 | 方向键、Tab、Enter、Esc |
| 终端惯例 | 提升熟练度 | `j/k`、`g/G`、`/`、`?`、`q` |
| 领域命令 | 贴近任务语言 | `s` stage、`r` retry、`d` delete |
| 高级组合 | 批量与自动化 | 命令面板、范围、宏、配置 |

- 每个动作只分配一个主快捷键；不要用别名填满 footer。
- 单字符危险动作绝不能立即执行不可逆行为。
- 文本输入状态不得劫持普通字符快捷键。
- 支持标准退出路径：Esc 关覆盖层、Esc/Left 返回上层、显式命令退出应用。

## 命令记录

每条命令必须写明：

| 字段 | 含义 |
|---|---|
| Name | 面向用户的动词与对象 |
| Scope | 全局、视图、焦点控件或选区 |
| Keys | 主键与可选惯例别名 |
| Enabled | 精确前置条件 |
| Feedback | 立即可见的结果 |
| Undo | 如何逆转 |
| Conflict | 与文本输入、终端、shell 或 OS 的冲突 |

## Focus 与选中

- Focus 指"键盘输入会去哪"，selection 指"哪个对象被作用"——视觉上必须可区分。
- Tab 在区域间移动，方向键在区域内移动；除非应用有更强惯例。
- 打开覆盖层时捕获焦点；关闭时回到触发控件或原条目。
- 列表刷新时按稳定 ID 保持选中，不按行号。
- 删除当前项后，选中最近的合理对象并告知结果。

## 模式纪律

- 在稳定位置显示当前模式。
- Esc 行为必须确定。
- 绝不把焦点与多选复用同一视觉处理。
- 助记键多到一屏放不下时，用可搜索命令面板承接。
- 拒绝无效命令要给出原因，不要静默忽略。

## 可发现性

- 首屏 footer 只显示当前最重要的 3–5 个动作。
- `?` 打开按上下文分组的完整帮助。
- 命令面板显示动作名、快捷键与不可用原因。
- 空状态直接提示下一步，不依赖帮助页。
- 鼠标悬停或右键动作必须有等价键盘路径。

## 危险操作与长任务

- 优先可逆删除（"执行 + Undo"）；不可逆操作要求写出具体对象名与具体动词。
- 批量操作执行前显示作用范围。
- 长任务显示当前阶段、完成量、可取消性。
- 后台任务不得锁住浏览；结果报到稳定状态区或通知队列。
- 按下取消后，区分"已请求取消"与"已停止"。

## 异步状态序列

```text
idle → requested → running → succeeded
                   ├→ failed → retrying
                   └→ cancel-requested → cancelled
```

这些状态要渲染成彼此可区分的样子。单独的 spinner 不是完整状态模型。

## 交互验收

键盘-only 完成主任务，并确认：

- 每个模式都有明确退出路径。
- 焦点绝不落在不可见或禁用区域。
- 快捷键不与文本输入、终端保留键、平台惯例冲突。
- 帮助内容随当前上下文变化。
- 快速连续输入、按键重复、窗口 resize 不会破坏状态。
- 焦点、选中、错误在无颜色或读屏环境下仍可辨识。
