# Deep Diagnosis｜深层诊断与反证追问

版本：1.0.0

一个面向细微、复杂、跨环节问题的通用分析技能。它不预设操作系统、开发语言、行业或工作类型，也不是只针对视觉异常、软件 bug 的排查清单。

核心做法：核实真实状态 → 分离事实与决策 → 找作用边界与不同语义 → 建立竞争假设 → 分轮追问关键取舍 → 最小区分检查 → 最小干预 → 真实验收。

## 它特别适合什么

- 细微、短暂、偶发、只在某些条件下出现的问题。
- “别人正常，只有我这里不正常”。
- “看起来每一步都对，组合起来却出问题”。
- “已经改过／做完了，为什么使用者仍看到旧结果”。
- 数据、文档、流程或研究中互相矛盾的证据。
- 需要 grill-me 式追问，找出计划或决策里的隐藏假设。

对简单事实查询、明确单步任务，不应启动整套调查和长访谈。高风险领域必须遵从该领域规则和专业判断；“通用”不代表可以无授权干预任何对象。

## 与 grill-me 的融合方式

吸收的思想：

- 追问直到形成真正共享的理解，而不只接受表面说法。
- 把选择画成决策依赖树，按轮次讨论现在可回答的问题。
- 可查事实由助手调查；价值判断、重要取舍与授权属于用户。
- 每个建议应说明依据、代价和可推翻条件。

为实际工作增加的约束：

- 默认只追问影响本轮行动的关键项，不无限展开所有分支。
- 证据线与决策线分开，不让用户替助手查资料或投票选根因。
- 不强制调用子代理、创建团队，也不依赖某个工具 API。
- 不是“问完就结束”：用户要求执行且已授权时，继续推进到约定的生效与验收阶段。
- 不能把模型实验、编译、预览或建议写出，误报成真实问题已解决。

本包以本次实际案例的方法反思及现有 grilling 技能的分轮追问思想重新编写，不是逐字复制某个外部 grill-me 项目。不需要同时安装原 grilling 技能，也不依赖该文件在你的环境里存在。

## 使用示例

### 普通难题

~~~text
使用 deep-diagnosis 分析这个偶发问题。
先核对真正生效的对象，区分已确认和猜测。
最多先做一项低风险、最有区分力的检查；需要修改时先说明范围。
~~~

### 修过但仍有问题

~~~text
使用 deep-diagnosis 继续处理。
先确认之前的改动到底制作、交付、生效到哪一步，
不要把没有生效当作方案失败，也不要从头重复所有排查。
~~~

### 审查计划／grill-me 模式

~~~text
用 deep-diagnosis 的全面追问模式审查这个计划。
按依赖树分轮提问；能查的事实先自己查。
重点挑战失败场景、利益冲突和隐藏取舍，先不要替我执行。
~~~

### 非技术工作

~~~text
用 deep-diagnosis 查这个报表／交付文档／跨部门流程的问题。
追踪真实输入、交接状态与接收方实际使用的产物，
不要只检查我当前打开的这份副本。
~~~

### 限制投入

~~~text
使用 deep-diagnosis，但先给我最小结论和下一项检查。
不要安装工具、重启服务、做全量测试或改变真实业务数据。
未知项写清楚，不要用更多分析代替行动建议。
~~~

这些是使用提示，不是新的权限。助手仍须遵守当前环境的文件访问、确认、隐私和安全要求。

## 如何放进目标工具

这是标准 Markdown 技能目录，以带 YAML 元数据的 SKILL.md 为入口。

1. 解压并保留整个 deep-diagnosis 目录结构。
2. 按目标助手／客户端的技能文档注册或放入其支持的技能目录。
3. 如果客户端只接受单文件提示，可先使用核心指令；附件为可选补充，不是运行依赖。
4. 如果自动发现机制或格式不同，应按该客户端要求适配；本包不声称已在每一种客户端实际加载验证。

本次只创建了下载目录内的技能包，没有安装到当前助手、修改现有技能或启用任何后台行为。把文件放在下载目录不等于客户端已经加载它。

## 阅读和运行成本

平时只加载核心指令；需要深入追问、记录复杂证据或迁移领域时，才读取对应附件。模板不要求全部填写，示例不应该变成预设答案。

包内不包含自动安装、系统修改或联网脚本。使用者自行决定何时注册、怎样授权以及什么才算完成。
