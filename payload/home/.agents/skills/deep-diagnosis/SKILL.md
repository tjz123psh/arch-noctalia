# Deep Diagnosis｜深层诊断与反证追问

目标：找到真正生效的规则、状态或交互边界，用最少但足够的证据决定下一步；需要修改时，让结果进入真实使用路径，而不是止于解释或候选产物。

本技能可独立使用，不依赖另一个 grilling / grill-me 技能。它吸收“决策树、分轮追问、事实自己查、选择由用户决定”，但默认有范围和停止条件，不执行无限访谈。

## 0. 边界与投入

- 遵守当前宿主的权限、安全、文件和工具规则。本技能不授予读取、修改、联网、安装、重启、发信、发布或委派的权限；领域专用规程优先。
- 用户已有明确限制、格式或预算时照办。明确的低风险任务直接做，不强行画大图、建台账或提问。
- 默认先列至多 3 个主要假设，安排 1 个信息量高、风险低的检查，再决定是否扩大。高风险或不可逆任务提高证据要求，不把“最小实验”当作随意试错的理由。
- 不必同时读完附件。追问困难时读[分轮追问](<references/grill-rounds.md>)；需要记录时读[工作模板](<references/worksheets.md>)；迁移到陌生领域时读[跨领域示例](<references/cross-domain-examples.md>)。相对路径以本技能目录为基准。

## 1. 先确认“问题是什么、现在是什么状态”

用一句可检验的话描述：在什么条件下，谁对哪个实际对象做了什么，期望什么，实际偏差是什么。

至少区分：

- 规范上的期望与现实中的行为；用户报告与自己的观察。
- 开始／结束／切换／重试等过渡阶段与稳定阶段。
- 偶发还是必现；影响范围、频率、损失和不能牺牲的部分。
- 现在要求的是理解、决策、制作产物，还是实际修复并生效。

核对任务真正使用的对象：运行实例、生效配置、数据版本、适用制度、交付文件、接收方、环境或执行流程。不要把同名文件、旧版本、开发副本、预览、别人好评或上一轮结论当作当前事实。

遇到“还是不行”：先确认上次到底做到了哪一步、对象是否相同、修改是否被加载／采用。没有生效不能算修复失败，也不能怪用户没看懂。

## 2. 分开维护事实、假设与用户决策

使用两条线，避免问错人、把猜测当授权：

1. 证据线：已观察到什么、机制是什么、有哪些替代解释、下一条证据如何取得。
2. 决策线：目标、优先级、可接受风险、范围、取舍和授权；用依赖树表示哪些选择必须先决定。

事实能从现有工具、文件、数据、规则或可靠资料查到，就自己查。确实无法访问时，才请用户提供最小必要材料，说明缺少什么、为什么重要；不要索取不必要的隐私或凭据。

决策属于用户。已经授权且未超范围的步骤不要反复确认；需要扩大范围、破坏性操作、发布或新的风险时再确认。不能查明的事实标为未知，不用“推荐答案”替它填空。

## 3. 画出真实作用链，找状态和边界

只展开会影响当前偏差的部分，不做无关全景重构。通用骨架：

~~~text
触发 → 输入／前提 → 规则与状态变化 → 产物生成
     → 提交／交接／传播 → 实际使用者消费 → 可观察结果
     → 结束／撤销／回退／资源清理
~~~

对可疑边界问：谁拥有状态？谁最后解释它？何时变更？何时可见？谁还能覆盖它？过渡中哪一层仍然有效？

重点比较，而非假定等价：

- 没有值、空值、零值、默认值；继承、明确拒绝、撤销覆盖。
- 不可见、不存在、未生效、已删除；逻辑结束与外部停止作用。
- 已生成、已提交、已接收、已应用、已验证。
- 局部规则与全局规则；当前状态与缓存、重试、定时任务、同步副本。

短暂问题要记录前／中／后时间线。不要因结果像“不同步”就断言并发或时序错误：也可能每次都同步地执行了错误语义。反过来，内部状态一致也不保证使用者同一时刻看到它。

## 4. 建立可反驳的竞争假设

每个主要假设写清：机制、支持证据、反对证据、如果成立应观察到什么，以及什么结果会推翻它。保留至少一个强替代解释，主动审问自己最喜欢的解释。

证据分级：

- 已确认：说明确认的是观察、规则、机制还是本次因果。代码／条文证明“会这样做”，不自动证明这次真的走了该路径。
- 高概率：现象与证据吻合，但仍有具体缺口或替代解释。
- 尚未确认：需要什么材料或实验才能推进。

不使用没有校准依据的精确百分比制造确定感。相似案例、社区评价、既有模型结论只能提供线索。“底层问题”“环境问题”“用户问题”“无解”必须有排除替代解释的证据，不能是停止思考的标签。

## 5. 用 grill-me 式追问推进决策，而不是拖住工作

按轮次处理“前置问题已经解决、现在就能回答”的关键决策。默认一轮 2—4 个彼此独立的问题；没有价值的凑数问题不问，关键阻塞只有一个就只问一个。

每个问题给出：具体选择、为什么现在需要、建议及代价，并保留不同意见。没有推荐依据时直说，不诱导用户认同。

~~~text
Q1｜需要决定什么？
为什么现在问：它会改变哪一步或哪种风险。
选项／建议：推荐什么、依据是什么、代价是什么。
边界：哪些事实仍未知，建议可能如何被推翻。
~~~

依赖本轮答案的问题放下一轮。收到回答后更新决策树；不要重复已回答项。等待某个事实时，可以继续不依赖它且已获授权的工作，不重复开展同一调查。

共享理解的门槛：目标、验收标准、不可牺牲项、当前行动范围和关键取舍明确。对其作简短确认后执行；不要用讨论无限延迟已授权行动。

用户明确要求全面拷问时，增加反例、失败场景和利益冲突检查，覆盖约定范围内所有关键分支；不是穷尽宇宙中每一种可能。始终挑战假设，不羞辱或揣测用户。

## 6. 优先选择能区分原因的最小检查

检查前写下：比较哪两个解释、保持什么不变、改变什么、各自预测什么、看什么指标、何时停止或回退。

可选方法不局限于代码实验：查原始记录、复算一个样本、冻结输入、检查真实交付物、观察一次交接、构造最小情境、做可逆对照或使用安全的模拟。不能安全干预时，使用观察和资料交叉验证，坦诚因果限制。

- 优先低代价的来源／版本／实际生效状态检查，再考虑大规模构建、环境替换或流程重写。
- 尽量一次改变一个关键变量；记录环境、输入、观察方法和阶段。
- 不同环境或前后背景变化不是严格单变量对照。可使用各自基线辅助识别，但必须披露混杂因素，不能把它宣称为排他性因果证明。
- “移除某机制仍复现”说明它不是必要条件，不等于该组件毫无责任。
- 最小模型通过不等于实际对象通过；没复现也不等于排除了低概率问题。
- 观测工具也可能改变结果或遗漏阶段；区分真实行为与记录、采样、导出、缓存造成的假象。

只运行会改变判断或行动的检查。证据足够且验收达到，就停；用户已经要求少验证时，不用一套固定清单做形式化表演。

## 7. 最小干预，并把结果推进到真实使用路径

选择风险最低、作用边界清晰、可回退的干预。优先撤销多余覆盖、修正状态语义、对齐交接和生效条件；不是一律重写内部，也不是一律归咎外部。

区分：根因修复、配置／流程规避、临时缓解。保留正常能力；不要用禁用所有效果、跳过审批、丢弃异常数据等方式冒充无代价修复。

修改前确认授权、对象、备份和恢复方法。执行后检查差异，避免顺手修无关隐患。委派只有在环境允许且有价值时使用，划清范围，不强制创建团队或并行写同一对象。

维护准确状态，不跳级：

~~~text
已提出 → 已制作／修改 → 已交付 → 已采用／生效 → 真实使用路径已验收
~~~

软件对应编译／部署／运行；文档对应导出／送达／接收方打开；流程对应获批／发布／实际执行。只适用其中一部分时标明，不强求所有任务都“部署”。

做一次足以覆盖原始偏差的真实验收：相同关键条件、触发点和观察指标；确认保留功能与副作用。权限不足以生效或测试时明确停在哪一级，不声称问题已解决。不要为了追求闭环越过授权。

## 8. 收敛与输出

默认结果包含以下内容；用户指定结构时服从用户，不必重复长报告：

1. 结论与当前实际状态：解决了什么，哪些只是建议／候选。
2. 最短真实作用链与关键分岔。
3. 已确认／高概率／尚未确认，附可核查来源和反证。
4. 最小改动或决策建议、影响范围、保留能力和回退办法。
5. 实际做过的验证、结果及局限；未做的测试明确写出。
6. 剩余问题与下一项最有区分力的动作。

默认停止于：关键解释有证据、用户决策足够、授权范围内产物已达到约定验收。无权限或证据不足时说明确切缺口及最小下一步；不要编造确定结论、把困难叫作无解，或用更多分析掩盖尚未生效。
