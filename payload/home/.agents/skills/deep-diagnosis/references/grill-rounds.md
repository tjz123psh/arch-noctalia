# 分轮追问：把 grill-me 变成能推进工作的访谈

按需阅读；不是要求每次执行全部题库。目标是揭示关键盲点、形成共享理解，而不是让用户证明自己值得被帮助。

## 一、先分类，再决定要不要问

| 节点类型 | 例子 | 处理 |
|---|---|---|
| 可查事实 | 哪份配置／哪版数据真正生效 | 在授权范围内自己查 |
| 用户独有观察 | 他实际收到的文件、现场感受、无法远程观察的操作 | 请求最小样本或具体描述，说明用途 |
| 用户决策 | 可接受的损失、优先级、是否修改生产对象 | 给选择和依据，等用户决定 |
| 暂时假设 | 认为某个步骤已经完成 | 标记并找证据，不伪装成事实或选择 |

“事实自己查”不意味着你拥有访问权限。无法访问不等于没有事实；准确说明访问缺口，不能反复要求用户提供已经给过的材料。

## 二、使用依赖树

~~~text
成功是什么？[决策]
├─ 哪些能力不能牺牲？[决策]
├─ 谁是实际使用者／接收方？[事实或决策]
└─ 哪个观测足以证明达成？[共同确认]

实际生效的对象是什么？[事实]
└─ 当前最强的两个解释是什么？[证据]
   └─ 哪项检查最能区分？[分析]
      ├─ 是否需要接触真实对象？[事实]
      └─ 用户是否接受该风险和范围？[决策]
         └─ 何时执行、怎样回退？[决策＋事实]
~~~

节点可记录为：编号、内容、类型、依赖、状态、答案／证据、影响。状态至少区分“已确认、待回答、待查证、本轮无关”。后者必须说明为何暂不处理，不能静默假定它已解决。

当前可问的问题，是前置条件已满足的关键决策。检查办法尚未选定时，不要提前问某个高风险操作的执行时间；调查尚未完成时，也不要让用户选择你臆测的根因。

## 三、一轮的实际形式

默认每轮 2—4 个独立关键问题。只有一个阻塞就问一个；用户已给出答案则不再问。

~~~text
❓ Q1｜这次成功必须保留哪些能力？
为什么现在问：不同验收标准会决定能否使用简化或临时规避。
➡️ 建议：先保留你明确在意的能力；如果要牺牲其中一项，单独说明代价。
还需要你决定：只在确实存在未决取舍时提问，否则记录已有约束即可。

❓ Q2｜本轮允许干预到哪里？
为什么现在问：下一项检查需要改变一个正在被使用的对象。
➡️ 建议：只对确定的局部做可回退修改，不扩大到其他对象。
代价／替代：若不允许，改用只读证据或隔离模型，并注明不能直接验收真实结果。
~~~

以上是形式示例，不是每次照问的固定问卷。如果用户只要分析报告，就不要询问是否可以部署；如果他已经允许同范围操作，就不要每个小步骤重新索要许可。

每轮后：

1. 简短复述新确定的目标、边界或取舍。
2. 标出哪些下游问题因此被解锁、哪些假设被推翻。
3. 继续不依赖未知项的已授权工作。
4. 只有新的关键决策才发起下一轮。

不要把偏好当成事实验证，也不要用“推荐答案”掩盖资料不足。建议是可反对的：应说明最强反方理由，以及什么新证据会改变建议。

## 四、反证追问题库

优先问自己；只有需要用户独有信息或价值选择时才问用户。

### 目标与替代

- 我们是在消除原因，还是只让某个指标更好看？
- 用户真正不接受的是什么？这个建议会不会牺牲了它？
- 什么情况下，一个更简单的方案已经足够？
- 如果不能执行首选方案，最小有用替代是什么？

### 因果与证据

- 当前证据证明了“可能这样”，还是“这次就是这样”？
- 我最支持的解释，遇到什么结果必须放弃？
- 哪个替代解释也能产生同样外观？现有检查能区分吗？
- 去掉被指责的机制，现象是否仍可能发生？
- 对照中的输入、时间、群体、工具或背景是否同时变化？

### 边界与状态

- 这个“完成”是对谁而言？下一个参与者真的收到并使用了吗？
- 取消局部设置后，是停止作用，还是恢复了另一条默认规则？
- 空白、零、未设置、拒绝、继承在此处究竟各是什么意思？
- 哪个参与者拥有最后解释权？哪个参与者只改变内部状态？

### 失败与反事实

- 哪类输入、用户或时间点会让方案失效？
- 稳态正常，但开始、结束、切换或重试时会怎样？
- 如果先前结论完全错误，我们现在应重新核对哪一个事实？
- 看不到异常，是被修好了，还是观测方式看不到它？

### 授权与落地

- 谁承担副作用、谁可以同意这个取舍？
- 修改的是实际使用对象，还是一个无人使用的副本？
- 怎样恢复原状，恢复时会不会覆盖后来的有效改动？
- 谁来验收，看到什么才算成功？

## 五、何时停止追问

默认停止于：当前行动所需的目标、验收标准、关键前置事实、风险与授权足够明确。把非关键未知留在记录里，不让它们拖住行动。

用户明确要求全面 grill-me 时，深入检查约定范围内的每个关键分支，包括反例、利益冲突和代价。每轮仍只问已经具备前提的问题；不得以“全面”为理由羞辱用户、无限扩大范围或要求其重复可查事实。

若新证据推翻先前前提，重开受影响分支，并说明为什么需要重新决定。不要保卫自己的旧结论，也不要悄悄改变用户已确认的目标。
