# Sidebar 2.2.0（2026-10-08）

## 变更

- **移除媒体卡（用户要求）**：顶栏已有媒体显示，侧栏不再重复。删除媒体轮询 / 封面下载 / 定位（seek）/ 播放控制与相关依赖声明（`playerctl`、`curl`、`file` 不再需要）；其余六张卡（搜索 / 随手记 / 窗口 / 计时器 / 系统 / 最近文件）不变。此前媒体进度冻结的根因（拖动滑块留下的 `media.seeking` 锁死位置更新）随卡片一并移除。
- **计时器升级（更实用 / 多样 / 自由）**：
  - 自由输入：`90s` / `25m` / `1h30m` / `2时` / `1:30`（分:秒）/ `1:30:00` / 裸数字=分钟 / `90分30秒` 均可，范围 1 秒 – 24 小时；输入即解析并显示实时预览；解析失败显示示例提示；Enter 直接开始。
  - 预设扩为两行 8 个：1 / 3 / 5 / 10 / 15 / 25 / 45 分 + 1 时（当前时长高亮）。
  - 运行中可一键 **+1 分 / +5 分** 延长：安全停止当前轮后以「剩余 + 加时」重开一轮，沿用串行队列与身份核验协议；接管中的后台计时剩余未知，不提供延长。
  - 时长写入布局文件（重开保留）；显示支持小时（如 `1:30:00`）；到点通知文案随时长自适应（`25 分钟到了` / `1 小时 30 分钟到了` / `90 秒到了`）。
  - 新增 IPC 通道（无鼠标回归 / 快捷键）：`noctalia msg plugin pang/sidebar:panel all timer start:25m | stop | reset | extend:300`。
  - 计时器输入框并入既有输入生命周期机制（收起即卸载、折叠动画中仍可重建），与搜索 / 笔记同规格处理。

# Sidebar 2.1.1（2026-10-08）

2.1.0 上线当晚发现"面板能打开、点击全无反应、且应用列表卡在'正在读取应用列表…'"的事故，本版为修复。

## 根因

- 宿主（Noctalia 5.2.1）每次脚本回调限 25 ms CPU；连续 3 次超时（或 60 s 内累计 5 次）会**自动停用整个插件运行时**（仅弹一次通知），此后点击、帧回调、IPC 全部被静默丢弃——表现即"点击无反应、列表永远加载中"，重开面板只显示停用前缓存的旧画面。
- 触发点是应用列表 / 最近文件的解析回调：本机宿主 Lua 环境中 `(.-)` 懒惰匹配代价异常高（90 行桌面文件解析约 13 ms），贴着预算上限；开机等负载场景下越线，连续超时触发停用。

## 修复

- 应用列表解析：`^(.-)\t...` 七段懒惰捕获 → `^([^\t]*)\t...` 字符类捕获（无回溯），90 行解析约 13 ms → 2 ms（实机测量）。
- 最近文件：`xmlUnescape` / `artDecode` 增加无 `&` / 无 `%` 快速路径（跳过 gsub 链）；刷新周期 10 s → 30 s。
- 行为不变：字段语义、XDG 优先级去重、隐藏/覆盖规则、排序与展示与 2.1.0 完全一致。

## 验证（2026-10-08）

- 全量离线测试与宿主 `noctalia plugins lint sidebar`（0 errors / 0 warnings）通过；改动仅上述 4 处。
- 实机：热重载后应用列表 53 项正常，媒体/窗口/最近文件加载正常；6 次快速开关压力测试 0 超时；IPC 派发返回 `ok: dispatched`。
- 若再现"点击无反应"（运行时被停用），执行 `noctalia msg plugins disable pang/sidebar && noctalia msg plugins enable pang/sidebar`（或改动 panel.luau 触发热重载）即可复活。

# Sidebar 2.1.0 修复记录

## 本次调整

- 默认轻量模式：正文一次完成收展布局，只有箭头做 120 ms 的反馈；不再逐帧调整滚动视口高度。柔和模式保留 220 ms 收展，按绝对时间计算进度，每 16 ms 最多提交一次，连续反向以最新目标为准。关闭模式不做卡片动画。
- 宿主原有面板开场动画保持不变，没有重启或修改 Noctalia 本体。
- 修复默认收起卡片首次展开直接跳变的路径；窗口列表及图标错峰预建，其他关闭卡片不预建大正文。
- 重开复用 Lua 描述缓存；首屏不携带关闭的大列表。笔记加载占位预留最终高度，避免从 48 跳到 240 导致首屏跳动/裁短。
- 收起搜索和笔记时移除输入框，防止隐藏的原生输入框继续获得键盘输入；其他重绘不随意更换编辑器身份。
- 搜索选择改为 Alt+↑/↓，Enter 打开。宿主 capture_keys 是无条件全局捕获，原来的普通上下键会吞掉笔记光标移动，无法在插件回调中按焦点放行。
- 工具栏展开数量及时同步，拖到列表末尾会离开置顶组，非法拖放与便签选择值不再改变状态。

## 功能与数据安全

- 读取笔记失败不会作为空内容打开；切换失败保留原缓冲和选择；重开读取失败锁住旧缓存，避免覆盖后来变化的磁盘文件。
- 新建便签使用 shell noclobber 排他创建，避免面板旧文件列表漏掉外部新建的同名文件；连点合并，创建失败保留原笔记。删除仍须确认，并保留至少一份便签。
- 旧 scratchpad 迁移只复制到独占的新文件，不移动或覆盖旧原件。保存失败继续保留内存缓冲，关闭/重开不能用磁盘旧内容覆盖它。
- 应用扫描遵循 XDG 路径优先级、按 desktop ID 覆盖与隐藏，不再误删同名不同应用；递归扫描导出目录。启动交给 GIO 解析 desktop 文件，不再把 Exec 当作任意 shell 文本解析。
- 最近文件正确处理 localhost、百分号编码、字面加号及 XML 实体，拒绝远端 authority 和 NUL；中文截断不破坏 UTF-8 字符。
- 媒体一次读取曲目和封面 URL；每次封面提取独占临时路径，过期任务只能清理自己的文件，不会覆盖新封面。失败 30 秒重试，最多四张本轮缓存；拒绝 HTTP 错误/非图片 MIME。定位串行只保留最新目标，旧轮询不再把进度拉回去。面板打开时回收上一次会话或热重载遗留的无主封面临时文件（含旧版 art_0.jpg / art_1.jpg），临时文件不会越积越多。
- 媒体暂停/收起时降到三秒轮询，隐藏时不查询，收起不开始封面下载。
- 计时器启停命令串行，独立于面板关闭生命周期；关开不再丢接管状态。新计时器通过锁和完整轮次身份协作退出，不发 kill，不会由旧清理任务抹掉新记录。旧 PID 文件严格核验后兼容；无法核验时保留记录并显示错误。

## 已知限制与后续方向

Noctalia 5.2.1 的 [render 绑定](https://github.com/noctalia-dev/noctalia/blob/6ef43e2bf2f3d5b4205ec72a72e34a2ab76ce3b4/src/scripting/plugin_bindings.cpp#L473-L584) 每次转换整个描述树，但 [原生协调器](https://github.com/noctalia-dev/noctalia/blob/6ef43e2bf2f3d5b4205ec72a72e34a2ab76ce3b4/src/ui/ui_tree_reconciler.cpp#L752-L861) 会按 type/key 重用控件；缓存 Lua 表不等于避免宿主布局。面板关闭后重新打开仍会由宿主重建原生树。

[ScrollView](https://github.com/noctalia-dev/noctalia/blob/6ef43e2bf2f3d5b4205ec72a72e34a2ab76ce3b4/src/ui/controls/scroll_view.cpp#L442-L482) 高度变化会测量和排列正文，并可能因滚动条缩窄宽度。现有 API 没有通用的原生展开、clip-only、节点级更新或自然高度测量，柔和模式仍有这个宿主成本。默认轻量模式优先响应速度而不是长画卷效果；若仍敏感可选“关闭卡片动效”。

实际运行日志还显示 Noctalia 的 IconThemePollSource 约每分钟一次耗时 230–300 ms。这是整个宿主的周期性扫描，可能造成额外偶发停顿，不是本插件能够完全消除的。日志位置为 [noctalia.log](</home/pang/.cache/noctalia/noctalia.log>)；没有为了它修改宿主、系统权限或重启桌面。进一步解决需要单独确认宿主范围。

旧格式计时器兼容仍使用严格核验后的单 PID TERM，现有 shell/API 无法数学上消除核验到发信号之间极窄的 PID 复用窗口；新格式不发送信号。图片 MIME 校验不等同于完整图片解码验证。封面清理只针对本插件数据目录里匹配 sidebar-art-* 与旧版 art_N.jpg 的文件，不触碰其他插件或用户文件。
