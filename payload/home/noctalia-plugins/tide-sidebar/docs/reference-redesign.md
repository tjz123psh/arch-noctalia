# 参考式改版验收记录

## 视觉基准

用户确认的[静态样张](<../design/reference-flat-proof.png>)为唯一视觉基准：[可编辑 SVG](<../design/reference-flat-proof.svg>)。

- 平整奶黄、米白、橄榄、绿色；不使用明显反光渐变或白色亮边。
- 波浪是色块边界，不是贴在卡片上的图表装饰线。
- 轻软投影表达厚度；数字按键不分别套盒子。
- 便签全高，计算器与倒计时同页，左侧窄标签。
- 只保留功能文字，不恢复品牌大标题或口号。

## 已确立的实现边界

- GTK4 原生前端负责显示；原 Noctalia 服务仍是便签/倒计时数据唯一写入者。
- 现有 notes/timer 的双存档格式未迁移；私有目录维持 0700。
- 输入法、选择、撤销由真实 Gtk.TextView / Gtk.Entry 处理，不用隐藏输入或截图冒充编辑器。
- 控件只建立一次，变化时更新对应属性；小波浪绘制区域只在明确交互后短时刷新，静止不持续 tick。
- runStream 在本机 API32 只收安全引用后的命令字符串，并有 64 KiB 行限制。大便签走有界分片，完整重组后才交给模型。
- [GTK4 Layer Shell 官方加载说明](https://github.com/wmww/gtk4-layer-shell/blob/main/linking.md)要求库先于 libwayland 载入；仅此 GJS 进程设置 LD_PRELOAD，并在进程内清除该环境变量以免传播到辅助进程。不改全局环境或 Shell 二进制。

## 性能观察口径

旧版一次短采样：打开 6.008 秒，Noctalia 消耗 0.68 CPU 秒，约单核 11.32%；收起 6.009 秒，0.11 CPU 秒，约 1.83%。这包含开场动画及其它 Shell 活动，不是 FPS、输入延迟或严格单变量因果证明。

[可重跑的 UI/CPU 观察](<../tests/native_perf.py>)只改变侧栏可见性，保留原页面/可见状态，不发便签、计时器或网络修改命令。新版预热后 6 秒观测：Noctalia 4.00% + 原生前端 1.67%，合计约单核 5.67%；收起合计 1.17%。前端 RSS 约 217 MiB，是额外常驻进程的内存开销。见[观测记录](<performance-observation.json>)。旧采样包含开场动画，新采样在 1.1 秒预热后开始，不能据此宣称严格降低了 50% 或给出 FPS；离屏构造测试也不替代真实流畅度验收。

## 2026-10-15 追加修复

- 自由倒计时：根因是数字框预填两位又限制 2 字符，未选中旧值时直接打字会被原生输入拒绝；暂停/运行中改时长原本只会继续旧计时。现在点入数字框即选中原值可直接替换，运行或暂停时出现“按新时长开始”二次确认，确认才替换。
- 秒表：新增独立模型与双存档。绝对时间锚点，收起界面不暂停，重启 Shell 可恢复；计次上限 100，写满后明确提示且不丢旧记录。
- 文字与滚动：便签选择器改 14px 中等字重（实测墨迹 21px 完整可见，属可读性改善，未声称修复了未复现的硬裁切）；列表改为原生弹层，不再挤压正文；滚动条完整重置为主题遗留边框清零、透明 6px 槽与 4px 滑块；倒计时进度线降为 2px 并清除负边距。
- 配色：便签纸面由 `#FFE49A` 调淡为 `#FFEAB2`、底波 `#F0DDA1`；热点由大面积棕色改为浅薄荷 `#E1EEDD`＋深绿文字与主按钮。
- 宿主差异：Noctalia 的 JSON 会把空 Lua 表编码为 `{}`，秒表视图只对已知 `laps` 字段做空对象到空数组的规范化，其他形状仍拒绝。
- 真实输入验收：在临时映射窗口内用真实键盘事件键入 45，替换成功并形成 270 分钟启动请求（仅 mock 接收，未动生产计时）。

## 2026-10-15 插件设置

新增 10 项插件级设置（`plugin.toml` 的 `[[setting]]`，服务用 `noctalia.getConfig` 读取，全部声明过）：减少装饰动效、侧栏宽度、记住上次标签页、起始标签页、倒计时默认时长、倒计时预设、关闭窗口前先确认、默认热点名称、默认热点频段、状态刷新间隔。取值在服务端统一钳制与规范化（宽度 380–640、预设过滤无效项且最多 6 个、未知标签页回落），再经新的 `config` 快照通道下发；服务实现 `onConfigChanged`，改设置当场生效而不重启运行时。

实测：`settings-open-plugin` 后设置页显示 10 项，中文标签与说明都来自 `translations/`；把快照里的 `panelWidth` 改成 520，前端把层壳宽度从 450 改成 520（`frontend-geometry` 的 `windowWidth` 450 → 520，改回 450 后同步回落）。热点默认值只在 helper 新加的 `desiredSsidKnown`/`desiredBandKnown` 为假时生效，脚本已记录的名称与频段始终优先。

过程中发现并修掉一个真实缺陷：`config` 通道只加进了 Lua 侧白名单，漏在前端 `channels` 数组里，导致配置根本没有被读取——设置页看着正常，行为却全用默认值。现在 `tests/run_all.py` 会做通道对齐检查：服务发布的每个通道都必须被前端读取（`geometry` 是只写诊断，已显式列为例外），同类漏配以后会在测试里直接暴露。

## 2026-10-15 第二轮复查

- 复制到剪贴板：本机 GIR 里 `gdk_clipboard_set_text` 未导出，GJS 实际走 `gdk_clipboard_set_value(GValue)`。做了一次真实往返验证（写入后读回一致，验证后未留下测试内容），确认 `clipboard.set('文本')` 可用；`main.js` 的 `copy()` 现在会捕获异常并返回真实结果，不再是“永远成功”。
- 倒计时存档：文件存在但读不出时，原先会静默回到默认时长并在下次保存时覆盖它。现在与秒表一致，先报告再继续（倒计时是短时数据，不封锁操作）。
- 权限：启动与退出时各执行一次 `chmod -R go-rwx -- <私有目录>`，目录维持 0700、其中的文件变为 0600；会话中新写入的文件在退出时收紧。
- 便签列表弹层宽度修复（用户截图反馈）：弹层内容原本只有约 135px 宽、每条标题被省略成“新…”。原因是 `Gtk.Popover` 按内容定宽，而 `Gtk.ScrolledWindow` 默认**不传递自然宽度**（列表此前在页面里靠 `hexpand` 撑开，搬进弹层后才暴露）。现在弹层给一个 300px 下限，并在弹出时对齐选择器自身宽度；新增两条回归：离屏测量 ≥280px（`native_notes_spec`），真实弹出宽度 ≥280px 且标题分配 ≥120px（`native_popup_spec --allow-test-window`）。 修复后的[真实弹层截图](<../previews/notes-picker.png>)。
- 滚动条位置修正（用户反馈“和模块融合了”）：overlay 滚动条画在滚动容器自己的右边缘，而容器的右边缘原本就等于卡片右边缘（外壳只留 16px 外边距），所以滑块像贴在卡片上。现在每个滚动容器内部预留 12px 专属沟槽（`.scroll-gutter`），卡片提前 12px 结束、滑块独占那条缝。实测（450×1000 捕获窗口）：滚动容器宽 366、卡片宽 354、滑块槽在窗口坐标 428–434，卡片右缘 422，中间留 6px 背景。受影响的是工具页、热点页与窗口页（含页头、搜索框、错误提示、关闭确认卡，保证与卡片同一条右边线）。便签正文的滚动条在黄色纸面内部，属于文本框内滚动，未改动。
- 窗口跳转不再自动收起侧边栏（按用户反馈）：原先“跳转成功→收起”是原生前端的硬编码行为，现在只在手动收起时关闭，方便连续切换窗口。
- 死代码 `lib/theme.luau`、`lib/view.luau`（旧 Noctalia-UI 版本残留，已无任何引用）移入 `.backups/legacy-lua-ui/`；过期截图移入 `.backups/legacy-previews/`。
